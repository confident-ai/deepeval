The `ConversationResolutionClassifier` labels a whole conversation as `resolved`, `unresolved`, or `handed_over` based on whether it reached the end state the scenario called for, such as an issue fixed, a booking made, or a clean handover to a human. It is built for end-to-end flow testing of scripted multi-turn conversations, where the expected label describes the outcome of the entire exchange rather than the quality of any single turn.

## Labels

- `resolved`: by the end of the conversation the user's goal or scenario is fully achieved.
- `unresolved`: by the end of the conversation the user's goal is not achieved and has not been handed over.
- `handed_over`: the conversation ends with the user handed over to a human or another channel instead of being resolved.

## Usage

Set `scenario` (and optionally `expected_outcome`) on the test case so the judge knows what "resolved" means for this conversation.

```python
from deepeval.classifiers import ConversationResolutionClassifier
from deepeval.test_case import ConversationalTestCase, Turn
from deepeval import evaluate

resolution = ConversationResolutionClassifier()

test_case = ConversationalTestCase(
    scenario="User wants to cancel their subscription.",
    turns=[
        Turn(role="user", content="I want to cancel my plan."),
        Turn(role="assistant", content="I can do that. Can you confirm the email on the account?"),
        Turn(role="user", content="jane@example.com"),
        Turn(role="assistant", content="Done. Your plan is cancelled effective today."),
    ],
    expected_labels={"conversation_resolution": "resolved"},
)

evaluate(test_cases=[test_case], classifiers=[resolution])
```

All built-in classifiers accept the same optional arguments as a [custom `Classifier`](/docs/classifiers-classifier#usage): `model`, `include_reason`, `async_mode`, and `evaluation_template`. You can also override `name` or pass your own `labels`.
