The `Classifier` class lets you build a **custom** LLM-as-a-judge classifier. You give it a name and a closed set of labels, and it assigns exactly one of those labels (or `NONE`) to any [`LLMTestCase`](/docs/evaluation-test-cases) or [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases), along with a reason.

Every built-in classifier in the [single-turn](/docs/classifiers-refusal) and [multi-turn](/docs/classifiers-conversation-resolution) sections is a `Classifier` subclass with a curated label set. Use `Classifier` directly whenever your labels are specific to your application: topic, intent, product area, escalation category, or anything else you can name.

:::tip
If you are new to classifiers, read the [introduction](/docs/classifiers-introduction) first for how labels, expected labels, and verdicts fit together.
:::

## Required Arguments

To create a `Classifier` you must provide:

- `name`: a string that identifies the classifier. It is the key used in a test case's `expected_labels`, so it must be unique within a run.
- `labels`: a list of at least one `Label` or plain string. Names must be unique (case-insensitively), and `NONE` is reserved.

A `Classifier` has no required test case parameters. It reads whatever is populated on the test case it receives (see [What the judge sees](#what-the-judge-sees)).

## Usage

Instantiate a `Classifier` with your labels, then pass it through `classifiers=` to `evaluate()`:

```python
from deepeval.classifiers import Classifier, Label
from deepeval.test_case import LLMTestCase
from deepeval import evaluate

topic = Classifier(
    name="topic",
    labels=[
        Label("billing", "Questions about invoices, charges, or payment methods."),
        Label("refund", "Requests to get money back for a purchase."),
        Label("shipping", "Questions about delivery status, times, or addresses."),
    ],
)

test_case = LLMTestCase(
    input="I was charged twice this month.",
    actual_output="Sorry about that. I can see the duplicate charge and will reverse it.",
    expected_labels={"topic": "billing"},
)

result = evaluate(test_cases=[test_case], classifiers=[topic])
classification = result.test_results[0].classifications[0]
print(classification.label, classification.success, classification.reason)
```

There are **FOUR** optional parameters when creating a `Classifier`:

- [Optional] `model`: a string specifying which of OpenAI's GPT models to use, **OR** [any custom LLM model](/guides/guides-using-custom-llms) of type `DeepEvalBaseLLM`. Defaulted to <DefaultLLMModel />.
- [Optional] `include_reason`: a boolean which when set to `True`, includes a reason for the chosen label. Defaulted to `True`.
- [Optional] `async_mode`: a boolean which when set to `True`, enables [concurrent execution within the `classify()` method](/docs/metrics-introduction#using-metrics-async). Defaulted to `True`.
- [Optional] `evaluation_template`: a subclass of `ClassifierTemplate` used to [override the default prompts](#customize-your-template). Defaulted to `ClassifierTemplate`.

### With an expected label

Set `expected_labels` on the test case, keyed by the classifier's `name`, to turn the classifier into an assertion for that case. The test case passes if the predicted label matches and fails otherwise:

```python
LLMTestCase(
    input="Can I get my money back?",
    actual_output="Yes, refunds are processed within 5 business days.",
    expected_labels={"topic": "refund"},
)
```

### Without an expected label

Leave `expected_labels` unset (or omit this classifier's key) and the classifier still labels the case, but records `success=None` and leaves the test case's verdict untouched. This is the right mode for topic-style classifiers where no label is inherently correct:

```python
LLMTestCase(
    input="Where is my order?",
    actual_output="Your order shipped yesterday and arrives Thursday.",
)
```

The console report still shows the label, and the **Aggregate Classifiers** panel gives you the label distribution across the run.

### Multi-turn

The same `Classifier` accepts a `ConversationalTestCase`. It reads every turn, plus `scenario`, `expected_outcome`, `user_description`, `context`, and `chatbot_role` when they are set:

```python
from deepeval.classifiers import Classifier
from deepeval.test_case import ConversationalTestCase, Turn
from deepeval import evaluate

resolution = Classifier(
    name="resolution",
    labels=["resolved", "unresolved", "handed_over"],
)

convo_test_case = ConversationalTestCase(
    scenario="User asks to cancel a subscription.",
    turns=[
        Turn(role="user", content="I want to cancel my plan."),
        Turn(role="assistant", content="Done. Your plan is cancelled effective today."),
    ],
    expected_labels={"resolution": "resolved"},
)

evaluate(test_cases=[convo_test_case], classifiers=[resolution])
```

### Alongside metrics

Classifiers and metrics run in the same `evaluate()` call. Metrics must still match the test case type (`BaseMetric` for `LLMTestCase`, `BaseConversationalMetric` for `ConversationalTestCase`), while the same classifiers apply to either:

```python
from deepeval.metrics import AnswerRelevancyMetric
from deepeval import evaluate

evaluate(
    test_cases=[test_case],
    metrics=[AnswerRelevancyMetric()],
    classifiers=[topic],
)
```

### In CI/CD

`assert_test()` accepts `classifiers=` too, with or without `metrics=`. A classification that fails its expected label raises an `AssertionError` naming the classifier, the predicted label, and the expected label. A classification with no expected label never raises:

```python title="test_topic.py"
from deepeval.classifiers import Classifier
from deepeval.test_case import LLMTestCase
from deepeval import assert_test

topic = Classifier(name="topic", labels=["billing", "refund", "shipping"])

def test_topic():
    test_case = LLMTestCase(
        input="I was charged twice this month.",
        actual_output="I can see the duplicate charge and will reverse it.",
        expected_labels={"topic": "billing"},
    )
    assert_test(test_case=test_case, classifiers=[topic])
```

```bash
deepeval test run test_topic.py
```

### As a standalone

You can also run a `Classifier` on a single test case as a one-off execution. `classify()` returns the label and stores the result on the instance:

```python
...

label = topic.classify(test_case)
print(label, topic.reason)
```

If the judge answers with something outside your label set, `topic.label` is `None` and `topic.error` explains what was returned.

### What the judge sees

There are no `evaluation_params` to configure. The prompt includes **every populated field** of the test case and omits anything that is `None` or empty:

- `LLMTestCase`: `input`, `actual_output`, `expected_output`, `context`, `retrieval_context`, `tools_called`, `expected_tools`.
- `ConversationalTestCase`: `scenario`, `expected_outcome`, `user_description`, `context`, `chatbot_role`, and every turn's `role`, `content`, `retrieval_context`, and `tools_called`.

A test case with nothing populated (or a conversation with no turns) raises a `ValueError` rather than asking the judge to classify an empty prompt.

## How It Works

A `Classifier` makes a single LLM call. The prompt lists your labels with their descriptions, includes the test case content, and asks the judge for a JSON object with two fields: `label` and `reason`. `deepeval` then matches the returned label case-insensitively against your declared labels or `NONE`. Anything else is recorded as an error rather than silently mapped to a label.

The verdict is computed after classification, not inside the judge call:

- expected label present and equal to the predicted label: `success=True`
- expected label present and different, or the classifier errored: `success=False`
- no expected label: `success=None`

### Caching

Like metrics, classifications on an `LLMTestCase` are cached between runs when caching is enabled. A cached result is reused only when the classifier's `name`, full label set (names and descriptions), `model`, and `include_reason` all match, and the cached run did not error. On a hit, the label and reason are restored and the verdict is recomputed against the current test case's `expected_labels`, so changing what you expect never serves a stale pass/fail. Conversational test cases are not cached.

## Customize Your Template

You can override the default prompts by subclassing `ClassifierTemplate` and passing it as `evaluation_template`. There are two methods, one per test case type:

- `classify_single_turn(labels: str, test_case_content: str)`
- `classify_multi_turn(labels: str, test_case_content: str, turns: list)`

`labels` is the rendered list of label names and descriptions, `test_case_content` is the rendered non-turn fields, and `turns` is a list of dicts with the populated fields of each turn. An override only needs to declare the variables it uses.

```python
from deepeval.classifiers import Classifier, ClassifierTemplate
import textwrap

class StrictClassifierTemplate(ClassifierTemplate):
    @staticmethod
    def classify_single_turn(labels: str, test_case_content: str) -> str:
        return textwrap.dedent(
            f"""
            Pick exactly one label for the test case below. Prefer the most
            specific label. Return "NONE" only if no label could apply.

            Labels:
            {labels}

            Test case:
            {test_case_content}

            Return JSON only: {{"label": "...", "reason": "..."}}
            JSON:
            """
        )

topic = Classifier(
    name="topic",
    labels=["billing", "refund", "shipping"],
    evaluation_template=StrictClassifierTemplate,
)
```

:::tip
The default templates live in the `deepeval` repository under [`deepeval/classifiers/classifier/templates/`](https://github.com/confident-ai/deepeval/tree/main/deepeval/classifiers/classifier/templates). Start from those when writing your own so the JSON contract stays intact.
:::
