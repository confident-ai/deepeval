A `Persona` defines **who the simulated user is, how they behave, and how they sound**.

A persona pairs with a `ConversationalGolden`: the persona is _who_ is calling, while the golden's `scenario` and `expected_outcome` are _what_ they are trying to do.

```python
from deepeval.dataset import ConversationalGolden, Persona

golden = ConversationalGolden(
    scenario="Andy Byron wants to purchase a VIP ticket to a Coldplay concert.",
    expected_outcome="Successful purchase of a ticket.",
    persona=Persona(characteristics="Something."),
)
```

::::note
Keep traits on the persona and the task on the golden. "You are impatient and talk over people" belongs in `characteristics`; "buy a VIP ticket" belongs in `scenario`. Mixing the two makes a persona single-use — the whole point is to run the same caller across many scenarios, and the same scenario across many callers.
::::

## Create A Persona

```python
from deepeval.dataset import Persona

persona = Persona(
    name="Andy Byron",
    characteristics="You are the CEO of Astronomer. You are curt and used to being deferred to. You speak in short sentences and interrupt long explanations.",
    voice="onyx",
)
```

There is **ONE** mandatory and **TWELVE** optional parameters when creating a `Persona`:

- `characteristics`: a string prompt describing the user's demographics, personality, emotional arc, and speaking style.
- [Optional] `name`: a string name for the caller. Defaulted to `None`.
- [Optional] `metadata`: a dictionary of structured facts about the caller (an account number, a resume, an order) that the simulator can draw on. Defaulted to `None`.
- [Optional] `tts_model`: a [TTS model](#tts-model), as an object or a model name, that this caller speaks through instead of the one on your `VoiceConfig`. Defaulted to `None`.
- [Optional] `voice`: a voice ID for the caller's TTS model, or a dictionary of voice IDs [keyed by provider](#voice). Defaulted to `None` (the TTS model's own default voice).
- [Optional] `voice_instructions`: a string of [plain-language direction](#voice-instructions) on how the caller speaks — accent, pace, tone — for TTS models that take it. Defaulted to `None`.
- [Optional] `interruption_behavior`: an [`InterruptionBehavior`](#interruptions) that lets the caller barge in, or `None` for a caller who never cuts in. Defaulted to `None`.
- [Optional] `speaks_first`: a boolean for whether the caller opens the conversation instead of waiting for the agent's greeting. Defaulted to `True`.
- [Optional] `muted`: a boolean which when set to `True` makes the caller stay completely silent for the whole call. Defaulted to `False`.
- [Optional] `background_noise`: a [`BackgroundNoiseSettings`](#background-noise) that loops ambient audio underneath the caller's speech. Defaulted to `None`.
- [Optional] `line_quality`: either `"wideband"` or `"phone"`, where `"phone"` carries the caller to your agent [over a simulated phone line](#line-quality). Defaulted to `"wideband"`.
- [Optional] `multilingual_stt`: a boolean which when set to `True` asks your `stt_model` to detect the agent's language per utterance instead of locking to one. Defaulted to `False`.
- [Optional] `hold_timeout`: a float number of seconds of agent silence or hold music before the caller hangs up. Defaulted to `None`.

Only `name`, `characteristics` and `metadata` apply to text simulations. Everything else is voice-only and is ignored when you simulate with a `model_callback`.

:::caution
`persona` supersedes the deprecated `user_description` on `ConversationalGolden`. Passing `user_description` still works and is promoted to `Persona(characteristics=...)` for you.
:::

## Configuring Characteristics

`characteristics` is a **prompt, not a label**. The simulator model writes the caller's dialogue from it and the TTS model speaks that text verbatim — so emotion, hesitation, and pacing come mostly from the words you give the persona. On TTS models that take them, [`voice_instructions`](#voice-instructions) can direct the delivery as well.

Describe behavior in terms of word choice and conversational patterns:

```python
# Less effective — a label the model has to interpret
Persona(characteristics="You are an angry customer.")

# More effective — observable behavior the model can act out
Persona(
    characteristics="""You are extremely frustrated and losing patience. You use short, clipped sentences.
When you have to repeat information you have already given, you say things like "I already told you this."
Your language gets sharper the longer the agent takes to resolve your issue.""",
)
```

A few things that matter more in voice than in text:

- **Give the caller an emotional arc.** Real callers escalate and de-escalate: "You start calm but grow frustrated if the agent puts you on hold. If your issue is resolved, your tone softens."
- **Punctuation is a speech cue.** `!` reads as emphasis, `,` as a natural pause, `-` as a brief break, and short sentences as stress. Avoid `...`, which some TTS engines read aloud as "dot dot dot".
- **Spell filler words plainly.** `um`, `uh`, `hmm`, `oh`, `well` — not `ummm` or `uhhhh`, which TTS engines often spell out letter by letter.
- **Tag blocks work well.** `characteristics` is free-form multi-line text, so `<speaking_style>…</speaking_style>` or `<end_call>…</end_call>` sections are a good way to separate delivery from call-control instructions.

## Configuring Audio

### TTS Model

By default, every caller speaks through the `tts_model` on your [`VoiceConfig`](/docs/conversation-simulator-voice-mode#tts-and-stt-models). Give a persona its own `tts_model` and that caller speaks through it instead, so a single run can mix models and providers:

```python
from deepeval.dataset import Persona
from deepeval.models import ElevenLabsTTSModel

persona = Persona(
    characteristics="You are a retiree calling about a billing error.",
    tts_model=ElevenLabsTTSModel(model="eleven_flash_v2_5"),
)
```

`tts_model` accepts the same values as `VoiceConfig(tts_model=...)`: a TTS model object, or a model name. A name is read as a model of the provider your [environment selects](/docs/environment-variables), so pass model objects when you want to mix providers.

The persona's [`voice`](#voice) has to be one this model knows, or keyed by provider so each model finds its own. What the persona's model spends is priced at that model's own rates and still adds up in the simulator's `tts_cost`.

### Voice

`voice` is passed straight through to the caller's TTS model, so valid values depend on that model — `"alloy"`, `"onyx"`, `"shimmer"`, etc. for the default `OpenAITTSModel`.

```python
persona = Persona(
    characteristics="You are an older adult who is uncomfortable with technology.",
    voice="onyx",
)
```

Voice IDs don't carry across providers: `"onyx"` means nothing to ElevenLabs. To keep a persona working whichever model speaks for it, key `voice` by provider — `"openai"`, `"elevenlabs"`, `"cartesia"`, or `"deepgram"` — and each TTS model picks its own provider's entry:

```python
persona = Persona(
    characteristics="You are an older adult who is uncomfortable with technology.",
    voice={"openai": "onyx", "elevenlabs": "<your ElevenLabs voice ID>"},
)
```

A model whose provider has no entry falls back to its own default voice.

Speaking rate and pitch are **not** persona fields, because every provider spells them differently. Set them on the TTS model itself (`OpenAITTSModel(generation_kwargs={...})`) so the persona stays portable.

### Voice Instructions

`voice` chooses who speaks; `voice_instructions` directs how they speak. Describe the delivery the way you would brief an actor — accent, pace, tone, mood:

```python
persona = Persona(
    characteristics="You are calling about a delivery that is three days late.",
    voice="coral",
    voice_instructions="Light Scottish accent. Speaks quickly and sounds a little impatient.",
)
```

Today only `OpenAITTSModel` with `gpt-4o-mini-tts`, the default model, takes instructions. Other TTS models skip them, so the same persona still runs anywhere; it just sounds plainer.

:::tip
To support instructions in your own `DeepEvalBaseTTS`, return `True` from `supports_voice_instructions()` and accept an `instructions` keyword in `a_synthesize` (and in `a_synthesize_stream`, if it streams).
:::

### Background Noise

Real calls are not made from a recording booth. `background_noise` loops an ambient audio file underneath the caller's speech, so your agent's speech recognition has to work through it:

```python
from deepeval.dataset import Persona, BackgroundNoiseSettings

persona = Persona(
    characteristics="You are calling from a busy cafe and keep losing your train of thought.",
    background_noise=BackgroundNoiseSettings(audio="cafe.wav", volume=0.3),
)
```

There is **ONE** mandatory and **ONE** optional parameter when creating a `BackgroundNoiseSettings`:

- `audio`: a path or `http(s)` URL to a `.wav` or `.mp3` file, which is looped for the length of the call.
- [Optional] `volume`: a float between `0.0` and `1.0` for how loudly the noise is mixed in. Defaulted to `0.3`.

:::tip
Pick a file that loops cleanly — an abrupt cut or trailing silence repeats for the whole conversation. `.mp3` files need `pydub` and `ffmpeg` installed; `.wav` files need nothing.
:::

### Line Quality

Most voice agents are reached by phone, where callers sound nothing like a TTS model in a quiet room: the line carries only 300–3400 Hz and codes every sample as 8-bit μ-law (G.711). Test only against clean, full-band speech and your agent's speech recognition looks better than it will on real calls. Set `line_quality="phone"` and everything the caller sends — speech, background noise, even silence — crosses that same narrowband channel before your agent hears it:

```python
from deepeval.dataset import Persona, BackgroundNoiseSettings

persona = Persona(
    characteristics="You are calling from your car on a hands-free kit.",
    background_noise=BackgroundNoiseSettings(audio="car.wav"),
    line_quality="phone",
)
```

The default, `"wideband"`, sends the caller's audio at the TTS model's full quality.

:::note
Calls placed over a real phone number or SIP trunk already cross the phone network, so leave `line_quality` at `"wideband"` for those. It's for connectors that would otherwise hand your agent studio-quality audio, such as WebRTC and WebSocket.
:::

## Configuring Behavior

### Who Speaks First

Most voice agents open with a greeting. Set `speaks_first=False` and the simulated caller stays quiet until the agent has spoken, so the greeting becomes the first `Turn` of the conversation:

```python
persona = Persona(
    characteristics="You are a patient caller who waits to be greeted.",
    speaks_first=False,
)
```

On a full-duplex connector the caller waits [`hold_timeout`](#hanging-up-on-hold-music) seconds for the greeting (15 when unset), then speaks first anyway.

### Silent Callers

`muted=True` makes the caller never speak at all — every user turn is empty and only silence goes up the wire. Use it to test how your agent handles dead air: does it re-prompt, escalate, or hang up?

```python
persona = Persona(characteristics="You are unable to speak.", muted=True)
```

### Hanging Up On Hold Music

`hold_timeout` is the number of seconds of agent silence (or hold music) the caller tolerates before ending the call. Without it, the simulation runs until `max_user_simulations` is exhausted:

```python
persona = Persona(
    characteristics="You are in a hurry and will not sit through hold music.",
    hold_timeout=15,
)
```

This is most useful for transfer flows — set it to 10–15 seconds to confirm a hand-off actually happened without waiting out the agent's own timeout.

### Multilingual Recognition

By default the caller "hears" your agent in whatever language your `stt_model` is configured for. Set `multilingual_stt=True` and the STT model detects the language per utterance instead, which is what you want for agents that switch mid-call ("For English press one, para español presione dos").

### Interruptions

`interruption_behavior` gives the caller permission to **barge in**: instead of politely waiting for each reply, they can cut in mid-sentence while the agent is still speaking.

```python
from deepeval.dataset import Persona, InterruptionBehavior

persona = Persona(
    characteristics="You are impatient and finish other people's sentences.",
    interruption_behavior=InterruptionBehavior(frequency="frequent", overlap="insist"),
)
```

`frequency` controls how readily the caller barges in, and `overlap` controls what they do when both sides end up talking at once. Leaving `interruption_behavior` as `None` means the caller never cuts in — on a [full-duplex connector](/docs/conversation-simulator-voice-connectors#full-duplex-custom-connectors) it still hears everything the agent says while it talks.

::::tip
Barge-in is a whole simulation mode of its own — how the judge decides to interrupt, what happens during double-talk, and what gets recorded on each `Turn` are covered in [Interruptions](/docs/conversation-simulator-voice-interruptions).
::::
