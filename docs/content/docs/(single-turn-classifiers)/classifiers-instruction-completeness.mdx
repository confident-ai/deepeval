The `InstructionCompletenessClassifier` labels a single response as `complete`, `partial`, or `ignored` based on whether the assistant addressed every part of a multi-part request, addressed only some, or addressed none of them. It is meant for assistants and copilots that handle compound tasks such as "summarize this, then list the action items, then draft a reply", where test cases with several explicit parts expect `complete`.

## Labels

- `complete`: every part of the user's request is addressed in the response.
- `partial`: some parts of the user's request are addressed and others are not.
- `ignored`: none of the parts of the user's request are addressed.

## Usage

```python
from deepeval.classifiers import InstructionCompletenessClassifier
from deepeval.test_case import LLMTestCase
from deepeval import evaluate

completeness = InstructionCompletenessClassifier()

test_case = LLMTestCase(
    input="Summarize the meeting notes, list the action items, and suggest a date for the follow-up.",
    actual_output="Summary: ... Action items: 1. ... 2. ... Suggested follow-up: next Tuesday.",
    expected_labels={"instruction_completeness": "complete"},
)

evaluate(test_cases=[test_case], classifiers=[completeness])
```

All built-in classifiers accept the same optional arguments as a [custom `Classifier`](/docs/classifiers-classifier#usage): `model`, `include_reason`, `async_mode`, and `evaluation_template`. You can also override `name` or pass your own `labels`.
