The `ToneAdherenceClassifier` labels a single response as `on_tone` or `off_tone` based on whether it matches the voice configured for the assistant, such as formal, friendly, or concise. It is built for branded assistants and for catching drift after a prompt or model change, where a regression suite with `on_tone` as the expected label on every case makes a shift in voice visible before it reaches users.

## Labels

- `on_tone`: the response matches the configured tone in wording, register, and length.
- `off_tone`: the response departs from the configured tone in wording, register, or length.

## Usage

Pass `tone` to describe the voice the assistant is meant to have; it is folded into the label descriptions.

```python
from deepeval.classifiers import ToneAdherenceClassifier
from deepeval.test_case import LLMTestCase
from deepeval import evaluate

tone = ToneAdherenceClassifier(tone="warm, plain-spoken, and under three sentences")

test_case = LLMTestCase(
    input="My package hasn't arrived.",
    actual_output="Sorry about that! I've checked and it's out for delivery today. I'll keep an eye on it for you.",
    expected_labels={"tone_adherence": "on_tone"},
)

evaluate(test_cases=[test_case], classifiers=[tone])
```

There is **ONE** optional argument specific to this classifier:

- [Optional] `tone`: a string describing the configured voice. Defaulted to `None`, in which case the judge relies on the test case alone.

All built-in classifiers also accept `model`, `include_reason`, `async_mode`, `evaluation_template`, `name`, and `labels`, as described for the [custom `Classifier`](/docs/classifiers-classifier#usage).
