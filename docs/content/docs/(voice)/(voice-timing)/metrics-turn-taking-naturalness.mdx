The turn-taking naturalness metric measures the **rhythm of the call** — how long the agent made the caller wait, whether it waited about as long each time, and whether either side talked over the other. It runs four single-issue timing metrics, reading the call from the stereo call recording when there is one or from the audio on every turn, and returns the share of agent replies none of them flagged, between 0 and 1.

:::note
Like the other timing metrics, this judges *when* things happened rather than what was said or how it sounded. Without a call recording, it needs `start_time` on every audio clip, which voice simulations populate from the live call clock.
:::

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import TurnTakingNaturalnessMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks three short follow-up questions about a delivery.",
    expected_outcome="The agent answers each question in turn.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = TurnTakingNaturalnessMetric(threshold=0.6)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **SIX** optional parameters when creating a `TurnTakingNaturalnessMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `use_speech_detection`: a boolean which, when set to `True`, only counts the caller as talking when the sound on their channel is speech, so background noise is not mistaken for the caller. Without a stereo `call_recording_path`, it finds where each speaker's speech starts and stops inside every turn's own audio instead. It is passed to all four timing checks. Defaulted to `True`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

Every voice metric records what it measured on `score_breakdown`. Read it after a standalone `measure()` call, or turn on `verbose_mode` to have it printed during an `evaluate()` run:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

For `TurnTakingNaturalnessMetric` the breakdown counts the replies, lists every issue found, gives each part's own result, and says where the timing came from:

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [
        {"type": "slow_response", "turn": 5, "duration_seconds": 4.8, "start_time": 26.7, "response_delay_seconds": 4.8, "metric": "Response Latency"},
        {"type": "delay_shift", "turn": 5, "duration_seconds": 4.8, "start_time": 26.7, "response_delay_seconds": 4.8, "shift_seconds": 3.9, "metric": "Response Delay Consistency"},
    ],
    "skipped": [],
    "metrics": {
        "Response Latency": {"score": 0.75, "eligible_turns": 4, "turns_with_events": 1},
        "Agent Interruption": {"score": 1.0, "eligible_turns": 4, "turns_with_events": 0},
        "User Interruption": {"score": 1.0, "eligible_turns": 4, "turns_with_events": 0},
        "Response Delay Consistency": {"score": 0.75, "eligible_turns": 4, "turns_with_events": 1},
    },
    "timing_source": "turn_timestamps",
}
```

`eligible_turns` is how many agent replies were judged and `turns_with_events` how many had at least one issue. `events` holds each part's events unchanged, tagged with the `metric` that raised them; the part's own page explains its fields. With a call recording, events carry `reply_start` or `caller_start`, seconds on the call's clock, instead of `turn`. `skipped` collects what a part could not time. `metrics` gives each part's own `score`, `eligible_turns` and `turns_with_events`, counted the part's own way, or `{"score": None, "reason": ...}` when that part could not judge the call. `timing_source` is `"call_recording"` or `"turn_timestamps"`.

The reason for the call above reads "1 of 4 agent replies had an issue: Response Latency (1), Response Delay Consistency (1). Judged from each turn's own audio and timestamps, as no stereo call recording was available." The last sentence is added only when the turn timestamps were used.

## How Is It Calculated?

`TurnTakingNaturalnessMetric` runs these single-issue timing metrics on the call, each with its default limits:

| Part                                                                   | Flags an agent reply that                                          |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------ |
| [Response Latency](/docs/metrics-response-latency)                     | kept the caller waiting too long after they finished.              |
| [Agent Interruption](/docs/metrics-agent-interruption)                 | started into the caller, as a false start or by talking over them. |
| [User Interruption](/docs/metrics-user-interruption)                   | the caller cut into, with a false start or by talking over it.     |
| [Response Delay Consistency](/docs/metrics-response-delay-consistency) | came after a wait clearly longer or shorter than the agent's usual. |

The score is the share of judged agent replies that none of the parts flagged:

<Equation formula="\text{Turn-Taking Naturalness} = 1 - \frac{\text{Agent replies flagged by at least one part}}{\text{Agent replies judged}}" />

A reply flagged by two parts counts once. Agent speech with pauses under a second counts as one reply, so an agent's two-part reply is judged once. A User Interruption counts against the agent reply the caller cut into: the one playing when the caller started, or else the latest one that started before. A part that cannot judge the call, such as Response Delay Consistency with fewer than three timed replies, is left out of the score.

### With a call recording

When the test case has a stereo `call_recording_path` (caller on the left channel, agent on the right), every part reads who spoke when from the recording instead of the turns, and `timing_source` is `"call_recording"`. Each part's page explains how it reads the recording.

<include cwd>snippets/voice/speech-detection.mdx</include>

Without a recording, who spoke when comes from the speech found inside each turn's audio, placed on the call timeline by its `start_time`. Every audio turn needs a `start_time`; when one is missing there is no honest way to tell when anyone spoke, so the metric is skipped with the reason "Every audio turn needs a start_time to time the call, so none was inferred."

:::caution
Timings depend on the connector and its end-of-turn detection, so they only compare within a `VoiceProtocol`: keep the connector fixed when tracking this score over time.
:::
