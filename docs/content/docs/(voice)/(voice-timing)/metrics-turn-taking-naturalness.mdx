The turn-taking naturalness metric measures the **rhythm of the call**: how long the agent made the caller wait, whether it waited about as long each time, and whether either side talked over the other. It runs four single-issue timing metrics and returns the share of agent replies none of them flagged, between 0 and 1.

## Required Arguments

To use the `TurnTakingNaturalnessMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with audio on at least one of:

- `audio` on the test case, a stereo recording of the whole call
- `audio` on the caller's and agent's turns, each with a `start_time`

Agent turns can also carry `latency_ms`, used with turn audio as in [Response Latency](/docs/metrics-response-latency).

Read the [How Is It Calculated](#how-is-it-calculated) section below to learn how each is used.

## Usage

The `TurnTakingNaturalnessMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import TurnTakingNaturalnessMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = TurnTakingNaturalnessMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **THREE** optional parameters specific to the `TurnTakingNaturalnessMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `use_speech_detection`: a boolean which when set to `True`, only counts someone as talking when [speech is detected](/docs/metrics-voice-introduction#speech-detection). Passed to all four parts. Defaulted to `True`.
- [Optional] `eval_mode`: `"deterministic"` or `"hybrid"`. Passed to the two interruption parts, which in `"hybrid"` [double-check each interruption](/docs/metrics-agent-interruption#second-check) with an audio decision model before it counts. Defaulted to the configured voice eval mode (`"deterministic"` unless set).
- [Optional] `audio_decision_model`: the model that does the second check in `"hybrid"` mode, passed to the two interruption parts. Defaulted to `HumeDecisionModel()`.

### As a standalone

You can also run the `TurnTakingNaturalnessMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

| `metrics` | Each part's own score and counts, counted the part's own way |
| `skipped` | Everything any part couldn't time, without repeats |

A part that couldn't judge the call shows `{"score": None, "reason": ...}` under `metrics`. Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events).

`eligible_turns` is how many agent replies were judged and `turns_with_events` how many had at least one issue. The score is the share that had none.

## How Is It Calculated?

The `TurnTakingNaturalnessMetric` score is calculated according to the following equation:

<Equation formula="\text{Turn-Taking Naturalness} = \frac{\text{Number of Agent Replies No Part Flagged}}{\text{Total Number of Agent Replies Judged}}" />

### The four parts

The metric runs these metrics on the call, each with its default limits, reading [call audio or turn audio](/docs/metrics-voice-introduction#call-audio-vs-turn-audio) the same way they do on their own:

| Part | Flags an agent reply when |
| --- | --- |
| [Response Latency](/docs/metrics-response-latency) | The caller waited more than 4 seconds for it |
| [Agent Interruption](/docs/metrics-agent-interruption) | It started into the caller, as a false start or a talk-over |
| [User Interruption](/docs/metrics-user-interruption) | The caller cut into it, with a false start or a talk-over |
| [Response Delay Consistency](/docs/metrics-response-delay-consistency) | Its wait was more than 2 seconds off the agent's typical wait |

In the [hybrid eval mode](/docs/metrics-voice-introduction#choose-who-judges-with-eval-modes), `eval_mode` and `audio_decision_model` are passed to the two interruption parts, which [double-check](/docs/metrics-agent-interruption#second-check) each interruption before it counts.

Every part's result is mapped onto the agent's replies:

- An agent reply is agent speech with no pause of 1 second or more. Above, the agent's two stretches, 0.6 seconds apart, are one reply.
- Response Latency, Agent Interruption and Response Delay Consistency already judge agent replies, so each result counts on its reply.
- A User Interruption counts against the reply the caller cut into: the one playing when the caller started, or else the latest one that started before.
- A reply flagged by two parts counts once.
- The replies judged are every reply any part judged. A part that can't judge the call, such as Response Delay Consistency with fewer than 3 timed replies, is left out.

If no part had anything to judge, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

:::caution
Timings depend on the connector and its end-of-turn detection, so keep the connector fixed when tracking this score over time.
:::
