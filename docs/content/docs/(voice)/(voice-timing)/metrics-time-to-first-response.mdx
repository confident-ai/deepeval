The time to first response metric checks whether your voice agent **greets the caller promptly** once the call connects, rather than leaving the line silent. It returns 1 when the greeting came in time and 0 when it did not.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import TimeToFirstResponseMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = TimeToFirstResponseMetric(threshold=0.5, max_wait_seconds=3)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **SEVEN** optional parameters when creating a `TimeToFirstResponseMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `max_wait_seconds`: an integer for the longest wait, in seconds, between the call connecting and the agent starting to speak. Must be greater than 0. Defaulted to `3`.
- [Optional] `use_speech_detection`: a boolean which, when set to `True`, only counts the caller as talking when the sound on their channel is speech, so background noise is not mistaken for the caller. Only applies with a stereo `call_recording_path`. Defaulted to `True`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the greeting when it was late:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.0
print(metric.score_breakdown)
```

`turn` is the greeting's zero-based position in the conversation, and `first_response_seconds` is how long the caller waited for the agent's first word. `start_time` and `duration_seconds` place that wait on the call's clock, ending at the agent's first sound. With a call recording, the event carries `reply_start`, where in the recording the agent first made sound, instead of `turn`, and when the caller spoke first the wait starts where their first words ended. `timing_source` says whether the call recording or the turn timestamps were used.

## How Is It Calculated?

`TimeToFirstResponseMetric` looks at the first turn with audio on the call timeline:

<Equation formula="\text{Time to First Response} = \begin{cases} 1 & \text{if the agent's greeting starts within max\_wait\_seconds} \\ 0 & \text{otherwise} \end{cases}" />

With a call recording, the wait depends on who spoke first:

- **The agent speaks first:** from the start of the recording to the agent's first sound.
- **The caller speaks first:** from the end of the caller's first words (pauses under half a second kept inside them) to the agent's first sound, or zero if the agent starts before those words end. The silence before the caller's first words is not counted.

If the agent makes no sound on the recording, the metric is skipped.

Without a recording, the wait is the greeting's `start_time`, which counts from the moment the call connected. Read from turn timestamps, the metric only applies when the agent speaks first. When the caller opens the call, the agent was not expected to greet, so the metric is skipped; its reply is judged by [`ResponseLatencyMetric`](/docs/metrics-response-latency) instead. Every audio turn in the call needs a `start_time`; without one there is no honest way to tell when anyone spoke, so the metric is skipped.

The default of **3 seconds** is the two-second response-latency limit plus one second for the line to connect, since the clock starts at connection rather than at a caller's last word. It is a practical allowance rather than a published norm, so tune it to your telephony setup.
