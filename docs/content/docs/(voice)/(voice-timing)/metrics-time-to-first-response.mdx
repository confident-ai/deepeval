The time to first response metric checks whether your voice agent **greets the caller promptly** once the call connects, rather than leaving the line silent. It returns 1 when the first response came in time and 0 when it didn't.

<AudioSample name="time-to-first-response" />

## Required Arguments

To use the `TimeToFirstResponseMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with audio on at least one of:

- `audio` on the test case, a stereo recording of the whole call\*
- `audio` on the turns, each with a `start_time`

\* Full call audio has to be stereo, with the caller and agent on separate channels. Mono full call audio is ignored, because the two voices can't be told apart.

Read the [How Is It Calculated](#how-is-it-calculated) section below to learn how each is used.

## Usage

The `TimeToFirstResponseMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import TimeToFirstResponseMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = TimeToFirstResponseMetric(max_wait_seconds=3)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **TWO** optional parameters specific to the `TimeToFirstResponseMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `max_wait_seconds`: an integer for the longest wait, in seconds, before the agent's first response. Must be greater than 0. Defaulted to `3`.
- [Optional] `use_speech_detection`: a boolean which when set to `True`, only counts someone as talking when [speech is detected](/docs/metrics-voice-introduction#speech-detection), so background noise isn't mistaken for the caller's first words. It's never used on the agent's side, where any sound counts as the first response. Defaulted to `True`.

### As a standalone

You can also run the `TimeToFirstResponseMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

| Field | What it means |
| --- | --- |
| `turn` | Which turn holds the greeting, counting from 0 |
| `first_response_seconds` | How long after the call connected the agent's first sound started |

| `duration_seconds` | How long the wait lasted, the same as `first_response_seconds` |

</Tab>

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is 1, the agent's first response, and `turns_with_events` is 1 when it was slow. The score is 0 when it was and 1 when it wasn't.

## How Is It Calculated?

The `TimeToFirstResponseMetric` score is calculated according to the following equation:

<Equation formula="\text{Time to First Response} = \begin{cases} 1 & \text{if the first response starts within the wait limit} \\ 0 & \text{otherwise} \end{cases}" />

The metric reads [full call audio or per-turn audio](/docs/metrics-voice-introduction#full-call-audio-vs-per-turn-audio), and the two handle a caller who speaks first differently, as below.

### Finding the first response

<Tabs items={["Full call audio", "Per-turn audio"]}>
<Tab value="Full call audio">

<VoiceDiagram
  duration={6.5}
  lanes={[
    { label: "Caller", role: "caller", sounds: [{ start: 0.5, end: 1.0 }, { start: 1.3, end: 1.8 }] },
    { label: "Agent", role: "agent", sounds: [{ start: 3.0, end: 6.0 }] },
  ]}
  brackets={[
    { start: 1.8, end: 3.0, lane: 1, label: "wait" },
  ]}
  marks={[
    { at: 3.0, lane: 1, tone: "info", label: "first sound" },
  ]}
/>

The first response is the agent's first sound on its channel. The wait depends on who spoke first:

- **The agent speaks first:** from the start of the full call audio to the agent's first sound.
- **The caller speaks first, within `max_wait_seconds`:** from the end of the caller's first words to the agent's first sound, or 0 if the agent starts before those words end. Pauses under 0.5 seconds stay inside the first words, as above.
- **The caller speaks first, but only after more than `max_wait_seconds`:** the caller sat in silence waiting for a greeting that never came. The wait runs from the start of the full call audio to the caller's first words, so it's always too long.

</Tab>
<Tab value="Per-turn audio">

<VoiceDiagram
  duration={8}
  lanes={[
    { label: "Caller", role: "caller", clips: [{ start: 5.6, end: 8 }], sounds: [{ start: 5.8, end: 7.8 }] },
    { label: "Agent", role: "agent", clips: [{ start: 0.4, end: 5.2 }], sounds: [{ start: 2.6, end: 5.0 }] },
  ]}
  brackets={[
    { start: 0, end: 2.6, lane: 1, label: "wait" },
  ]}
  marks={[
    { at: 0.4, lane: 1, tone: "skip", label: "clip starts" },
  ]}
/>

The first response is the agent's first sound in any of its clips, a chime included, placed on the call's clock by its `start_time`. For the caller, only speech counts. The metric listens inside the clip, so silence at the start of the greeting clip counts as waiting. A clip that can't be decoded is placed by its `start_time`.

The wait runs from when the call connected to that first sound. If the caller's speech comes first, the agent wasn't expected to greet, so the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped). [Response Latency](/docs/metrics-response-latency) times the agent's reply instead.

</Tab>
</Tabs>

### Wait criteria

| Check | Rule |
| --- | --- |
| Wait | More than `max_wait_seconds`, 3 seconds by default |

The metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped) when the agent makes no sound in the full call audio, or, with per-turn audio, when the call has no timed audio or an audio turn has no `start_time`.

:::note
The default of 3 seconds is a practical allowance for how long a line can stay silent after it connects, not a published norm. It is separate from [Response Latency](/docs/metrics-response-latency)'s 4-second limit, so tune it to your telephony setup.
:::
