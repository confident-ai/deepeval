The user interruption metric checks whether **the caller starts speaking into your voice agent**: either a false start, where the caller starts as the agent speaks and backs off, or talking over the agent. It is [`AgentInterruptionMetric`](/docs/metrics-agent-interruption) from the other side. It returns the share of the caller's turns that interrupted no one, between 0 and 1.

Callers cutting in often is a sign that the agent's replies run long or miss what the caller wants.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import UserInterruptionMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = UserInterruptionMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

A simulated caller whose persona has [interruptions](/docs/conversation-simulator-voice-interruptions) turned on cuts in on purpose, and those cut-ins count. The metric is most useful on real calls.

There are **SEVEN** optional parameters when creating a `UserInterruptionMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `use_speech_detection`: a boolean which, when set to `True`, only counts the caller as talking when the sound on their channel is speech, so background noise is not mistaken for the caller. Only applies with a stereo `call_recording_path`. Defaulted to `True`.
- [Optional] `audio_decision_model`: an audio decision model, such as `HumeDecisionModel`, that hears a short clip of each flagged event and dismisses the ones it judges not real. See [Second check with an audio decision model](#second-check-with-an-audio-decision-model). Defaulted to `None`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the caller turns where the issue was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

`type` names the condition that fired (`false_start` or `talk_over`; `false_start` when both did). `caller_start` is where in the call recording the caller started; when the turn timestamps were used, events carry `turn`, the caller turn's zero-based position in the conversation, instead. `start_time` and `duration_seconds` place the stretch where both were talking on the call's clock, or the caller's interrupting stretch when the agent made no sound inside it. `caller_seconds` is how long the caller kept speaking and `overlap_seconds` how much of that the agent was making sound. Without a recording, turns whose audio could not be decoded are listed under `skipped`.

## How Is It Calculated?

`UserInterruptionMetric` checks every time the caller starts speaking after at least one second of their own silence and keeps going for at least one second, and scores the share that interrupted no one:

<Equation formula="\text{User Interruption} = \frac{\text{Caller turns that are neither a false start nor a talk-over}}{\text{Caller turns of 1 second or more}}" />

Only a caller who starts while **the agent has the floor** can interrupt: the agent is talking (it made sound in at least 0.2 of the 0.3 seconds before the caller started) and started more than **half a second** before the caller. When the two start within half a second of each other, the moment is a collision and is judged by [`AgentInterruptionMetric`](/docs/metrics-agent-interruption) instead, so the two metrics never flag the same moment.

An interruption is a **false start** or a **talk-over**:

- **False start:** the caller starts speaking while the agent has the floor, and stops within **1.5 seconds**.
- **Talk-over:** the caller starts speaking while the agent has the floor, and the agent makes **1 second** or more of sound while the caller keeps speaking.

Pauses under a second do not end either speaker's stretch of speech. Caller sounds under one second, such as an "mm-hm" while listening, are not turns and are left out entirely. The 1.5-second stop and the 1-second overlap mirror [`AgentInterruptionMetric`](/docs/metrics-agent-interruption).
