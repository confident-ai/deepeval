The response latency metric checks whether your voice agent **answers without a long wait**: the caller finishes speaking and does not sit in silence before the agent starts its reply. It returns the share of agent replies that started in time, between 0 and 1.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import ResponseLatencyMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = ResponseLatencyMetric(threshold=0.8, max_latency_seconds=4)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **SEVEN** optional parameters when creating a `ResponseLatencyMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `max_latency_seconds`: an integer for the longest wait, in seconds, between the caller finishing and the agent starting to speak. Must be greater than 0. Defaulted to `4`.
- [Optional] `use_speech_detection`: a boolean which, when set to `True`, only counts the caller as talking when the sound on their channel is speech, so background noise is not mistaken for the caller. Only applies with a stereo `call_recording_path`. Defaulted to `True`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the replies where the issue was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

`turn` is the agent reply's zero-based position in the conversation, and `response_delay_seconds` is how long the caller waited for it. `start_time` and `duration_seconds` place that wait on the call's clock, ending where the reply starts. Without a recording, agent replies whose audio, or the caller's audio before them, could not be decoded are listed under `skipped`. So are replies the agent started while the caller was still talking; those are judged by [`AgentInterruptionMetric`](/docs/metrics-agent-interruption) instead. With a call recording, events and `skipped` entries carry `reply_start`, where in the recording the agent started, instead of `turn`.

## How Is It Calculated?

`ResponseLatencyMetric` times every agent reply that follows a caller turn, and scores the share that started in time:

<Equation formula="\text{Response Latency} = \frac{\text{Agent replies that started within max\_latency\_seconds}}{\text{Agent replies that follow a caller turn}}" />

With a call recording, the wait runs from the caller's last sound to the agent's first sound, every time the agent starts speaking after at least one second of its own silence and the caller spoke last. When the agent speaks before the caller makes any sound, that opening line answers no one and is left out; [`TimeToFirstResponseMetric`](/docs/metrics-time-to-first-response) times it instead. When the caller opens the call, the agent's first reply is timed like any other. A start where the caller's sound runs on more than half a second past it is skipped.

Without a recording, the wait runs from the end of the caller's audio to the moment the agent starts speaking, both placed on the call timeline by each turn's `start_time`. When the two clips touch with no gap, the `latency_ms` your connector recorded for the reply is used instead; a reply with neither is listed under `skipped`. An overlap of up to half a second counts as no wait; a longer one is listed under `skipped`. Every audio turn in the call needs a `start_time`; without one there is no honest way to tell when anyone spoke, so the metric is skipped.

People answer each other in about **0.2 seconds** (Stivers et al., 2009), and conversation treats about **one second** of silence as the standard maximum (Jefferson, 1989). A voice agent also has to transcribe, think and speak before it can answer, so the default of **4 seconds** allows for that. On real phone calls labelled by human reviewers, 4 seconds matched their judgement best, while 2 seconds flagged almost every call.
