The agent interruption metric checks whether your voice agent **starts speaking into the caller**: either a false start, where it starts as the caller speaks and backs off, or talking over the caller. It returns the share of the agent's starts that interrupted no one, between 0 and 1.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AgentInterruptionMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AgentInterruptionMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **SEVEN** optional parameters when creating an `AgentInterruptionMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `max_caller_silence_seconds`: an integer. A false start is not counted when the caller's pause, from when they stopped speaking to when they started again, was longer than this. Must be greater than 0. Defaulted to `4`.
- [Optional] `use_speech_detection`: a boolean which, when set to `True`, only counts the caller as talking when the sound on their channel is speech, so background noise is not mistaken for the caller. Without a stereo `audio` on the test case, it finds where each speaker's speech starts and stops inside every turn's own audio instead. Defaulted to `True`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the agent starts where the issue was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

`type` names the condition that fired (`false_start` or `talk_over`; `false_start` when both did). `reply_start` is where in the call recording the agent started; when the turn timestamps were used, events carry `turn`, the reply's zero-based position in the conversation, instead. `start_time` and `duration_seconds` place the stretch where both were talking on the call's clock, or the agent's interrupting stretch when the caller made no sound inside it. `agent_seconds` is how long the agent kept speaking and `overlap_seconds` how much of that the caller was making sound. Without a recording, agent replies whose audio could not be decoded are listed under `skipped`.

## How Is It Calculated?

`AgentInterruptionMetric` checks every time the agent starts speaking after at least one second of its own silence, leaving out its opening line, and scores the share that interrupted no one. The opening line is the agent's first start when the caller had made no sound before it; when the caller opens the call, the agent's first reply is checked like any other, whether the timing comes from the recording or the turn timestamps:

<Equation formula="\text{Agent Interruption} = \frac{\text{Agent starts that are neither a false start nor a talk-over}}{\text{Agent starts other than the opening line}}" />

An interruption is a **false start** or a **talk-over**:

- **False start:** the agent starts speaking, the caller is already talking or starts within **half a second**, and the agent stops within **1.5 seconds**. It is not counted when the caller's pause, from when they stopped speaking to when they started again, was longer than `max_caller_silence_seconds`, since after a long silence the agent is expected to fill it.
- **Talk-over:** the agent starts speaking while the caller is already talking, and the caller makes **1 second** or more of sound while the agent keeps speaking.

The half-second window and `max_caller_silence_seconds` both shape the false start. Below, the caller pauses for less than `max_caller_silence_seconds` between speaking and starting again, and the agent starts during that pause, less than half a second before the caller starts again. The agent backs off within 1.5 seconds, so this counts as a false start. Had the caller paused for longer, or started again later after the agent, it would not.

<ImageDisplayer id="diagrams/in-house/metrics/agent-interruption-settings" />

The caller is already talking when they made sound in at least 0.2 of the 0.3 seconds before the agent started. Pauses under a second do not end the agent's stretch of speech. When the agent and the caller start within half a second of each other, the moment is a collision and belongs to this metric. The caller cutting in once the agent has been talking for longer is judged by [`UserInterruptionMetric`](/docs/metrics-user-interruption) instead, so the two metrics never flag the same moment. The half-second window, the 1.5-second stop and the 1-second overlap were chosen on human-labelled phone calls, where reviewers also excused an agent that spoke after about four seconds of caller silence.

Without a recording, who spoke when comes from the speech found inside each turn's audio, placed on the call timeline by its `start_time`. When both voices are mixed into one clip, talking over each other sounds like one speaker, so an overlap only shows where the clips themselves overlap. Every audio turn in the call needs a `start_time`; without one there is no honest way to tell when anyone spoke, so the metric is skipped.
