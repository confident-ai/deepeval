The agent interruption metric checks whether your voice agent **starts speaking into the caller**: either a false start, where it starts as the caller speaks and backs off, or talking over the caller. It returns the share of the agent's starts that interrupted no one, between 0 and 1.

<AudioSample name="agent-interruption" />

## Required Arguments

To use the `AgentInterruptionMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with audio on at least one of:

- `audio` on the test case, a stereo recording of the whole call\*
- `audio` on the caller's and agent's turns, each with a `start_time`

\* Full call audio has to be stereo, with the caller and agent on separate channels. Mono full call audio is ignored, because the two voices can't be told apart.

Read the [How Is It Calculated](#how-is-it-calculated) section below to learn how each is used.

## Usage

The `AgentInterruptionMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AgentInterruptionMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AgentInterruptionMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **FOUR** optional parameters specific to the `AgentInterruptionMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `max_caller_silence_seconds`: an integer. A false start isn't counted when the caller had been silent for longer than this before starting again, since after a long silence the agent is expected to fill it. Must be greater than 0. Defaulted to `4`.
- [Optional] `use_speech_detection`: a boolean which when set to `True`, only counts the caller as talking when [speech is detected](/docs/metrics-voice-introduction#speech-detection), so background noise isn't mistaken for the caller. With per-turn audio it's also used to find the agent's speech. Defaulted to `True`.
- [Optional] `eval_mode`: `"deterministic"` or `"hybrid"`. In `"hybrid"`, each interruption is [double-checked by an audio decision model](#second-check) before it counts. Defaulted to the configured voice eval mode (`"deterministic"` unless set).
- [Optional] `audio_decision_model`: the model that does the second check in `"hybrid"` mode. Defaulted to `HumeDecisionModel()`.

### As a standalone

You can also run the `AgentInterruptionMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each start where the agent interrupted shows up in `score_breakdown`. Here is what the two calls in the [example call](#example-call) return:

```python
{
    "eligible_turns": 5,
    "turns_with_events": 2,
    "events": [
        {
            "type": "false_start",
            "duration_seconds": 1.0,
            "start_time": 10.8,
            "mark": "range",
            "timing_source": "call_recording",
            "description": "Agent started over the caller, then stopped",
            "reply_start": 10.8,
            "agent_seconds": 1.0,
            "overlap_seconds": 1.0,
        },
        {
            "type": "talk_over",
            "duration_seconds": 2.0,
            "start_time": 17.6,
            "mark": "range",
            "timing_source": "call_recording",
            "description": "Agent talked over the caller for 2.0s",
            "reply_start": 17.6,
            "agent_seconds": 3.0,
            "overlap_seconds": 2.0,
        },
    ],
    "skipped": [],
    "timing_source": "call_recording",
}
```

| Field | What it means |
| --- | --- |
| `type` | False start or talk-over. False start when both apply |
| `reply_start` | When the agent started, in seconds into the call |
| `agent_seconds` | How long the agent kept speaking |
| `overlap_seconds` | How much of that the caller was also talking |
| `start_time` | Where both started talking at once |
| `duration_seconds` | How long both talked at once. The agent's whole stretch if the caller never spoke inside it |

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many agent starts were checked and `turns_with_events` how many interrupted the caller. The score is the share that didn't.

## How Is It Calculated?

The `AgentInterruptionMetric` score is calculated according to the following equation:

<Equation formula="\text{Agent Interruption} = \frac{\text{Number of Agent Starts Without an Interruption}}{\text{Total Number of Agent Starts}}" />

With per-turn audio instead of a call recording, the metric finds the speech inside each clip and places it on the call's clock by the clip's `Audio.start_time`, then finds starts the same way. Events name the agent turn instead of a time in the call.

### Counting agent starts

A start is each time the agent starts speaking after at least 1 second of its own silence. A pause under 1 second doesn't make a new start. The agent's opening line, spoken before the caller made any sound, isn't counted. When the caller opens the call, the agent's first start is checked like any other.

### Interruption criteria

<VoiceDiagram

    { label: "Agent", role: "agent", sounds: [{ start: 2.4, end: 3.4 }, { start: 7.4, end: 11.4 }] },

An agent start is an interruption when it's a **false start** or a **talk-over**:

- **False start:** the caller is already talking, or starts within 0.5 seconds after the agent, and the agent stops within 1.5 seconds.
- **Talk-over:** the caller is already talking, and makes 1 second or more of sound while the agent keeps speaking.

| Check | Rule |
| --- | --- |
| Caller already talking | Caller sound in at least 0.2 of the 0.3 seconds before the agent starts |
| Collision | The caller starts within 0.5 seconds after the agent |
| Backs off | The agent stops within 1.5 seconds |
| Talks over | 1 second or more of caller sound during the agent's stretch |

A false start isn't counted when the caller had been silent for more than `max_caller_silence_seconds`, 4 seconds by default, before starting again. After a long silence the agent is expected to fill it.

When the two start within 0.5 seconds of each other, the moment belongs to this metric. A caller cutting in after the agent has been talking for longer is judged by [User Interruption](/docs/metrics-user-interruption), so the two never flag the same moment.

If there's nothing to count, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

:::note
The 0.5-second window, the 1.5-second stop and the 1-second overlap were chosen on human-labelled phone calls, where reviewers also excused an agent that spoke after about 4 seconds of caller silence.
:::

### Second check

In the [hybrid eval mode](/docs/metrics-voice-introduction#choose-who-judges-with-eval-modes), each interruption is double-checked before it counts. The audio decision model hears about 5 seconds of the **caller's** audio around it, to confirm the caller was really talking when the agent cut in, and is asked:

> Is a person speaking in this clip, rather than only background noise, breathing or silence?

If the model judges "no" more likely than "yes", the interruption is dismissed and doesn't count against the score.
