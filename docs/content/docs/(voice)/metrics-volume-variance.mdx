The volume variance metric checks whether your voice agent's volume **drifts within a reply**, like a sentence that starts loud and fades to a mumble, or one that swells as it goes. It returns the share of agent replies that hold a steady volume, between 0 and 1.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import VolumeVarianceMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = VolumeVarianceMetric(threshold=0.8, max_drift_db=10)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **SIX** optional parameters when creating a `VolumeVarianceMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `max_drift_db`: an integer for how far, in dB, a reply's volume may rise or fall from start to end. Defaulted to `10`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the replies where the issue was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [{"type": "volume_drift", "turn": 3, "drift_db": -14.8}],
    "skipped": [{"turn": 5, "error": "Reply has under 3 seconds of speech to follow."}],
}
```

`turn` is the turn's zero-based position in the conversation, and `drift_db` is how much the volume changed from the start to the end of the reply (negative for a fade, positive for a swell). Agent replies whose audio could not be decoded, or that have under three seconds of speech to follow, are listed under `skipped`.

## How Is It Calculated?

`VolumeVarianceMetric` checks every agent reply with at least three seconds of speech and scores the share of them without the issue:

<Equation formula="\text{Volume Variance} = \frac{\text{Agent replies drifting by max\_drift\_db or less}}{\text{Agent replies with three or more seconds of speech}}" />

Each reply is cut into one-second windows. A window's level is the median of its five loudest 20 ms frames, so a window that is half pause still reads at its speech level; windows without that much speech are left out. The metric fits a line through the levels with a method that ignores single outlier windows, such as the fading tail of a word, and reports the line's rise or fall from the first window to the last.

The default of **10 dB** is roughly the step at which a voice sounds half (or twice) as loud. Natural speech rises and falls between sentences, but on real agent replies that trend stays within about 5 dB.

Only a steady fade or swell is reported. Quick ups and downs within a sentence are part of normal expressive speech and are not counted.

If no agent reply is long enough to follow, the metric is skipped.

      question: "How is this different from loudness?",

          holds steady within the reply, so a reply can pass one and fail the
          other.
        </>

          samples, so it has no model or token cost.
        </>
      ),
