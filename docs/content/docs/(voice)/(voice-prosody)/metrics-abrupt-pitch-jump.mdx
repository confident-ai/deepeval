The abrupt pitch jump metric checks whether your voice agent's voice **cracks or squeaks**: a sudden leap up in pitch, faster than a human voice can move, to above the voice's usual range. It returns the share of agent replies without one, between 0 and 1.

<AudioSample name="abrupt-pitch-jump" />

## Required Arguments

To use the `AbruptPitchJumpMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `audio` on the agent's turns, one clip per reply

## Usage

The `AbruptPitchJumpMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AbruptPitchJumpMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AbruptPitchJumpMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **TWO** optional parameters specific to the `AbruptPitchJumpMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `eval_mode`: `"deterministic"` or `"hybrid"`. In `"hybrid"`, the metric flags more possible jumps, and each is [double-checked by an audio decision model](/docs/metrics-voice-introduction#second-check-with-an-audio-decision-model) before it counts. Defaulted to the configured voice eval mode (`"deterministic"` unless set).
- [Optional] `audio_decision_model`: the model that does the second check in `"hybrid"` mode. Defaulted to `HumeDecisionModel()`.

The jump limit is fixed, since a crack is a defect rather than a matter of taste.

### As a standalone

You can also run the `AbruptPitchJumpMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each pitch jump shows up in `score_breakdown` as its own event. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [
        {
            "type": "pitch_jump",
            "turn": 3,
            "offset_seconds": 0.96,
            "duration_seconds": 0.08,
            "start_time": 7.96,
            "mark": "moment",
            "timing_source": "turn_timestamps",
            "description": "Pitch jumped abruptly to 4 semitones above the voice's usual range",
            "pitch_hz": 317.8,
        }
    ],
    "skipped": [{"turn": 9, "error": "Reply has no voiced speech."}],
}
```

| Field | What it means |
| --- | --- |
| `offset_seconds` | Where the jump is, in seconds from the start of the turn's clip: the 40 ms just before the step |
| `duration_seconds` | Always 0.08: the 40 ms either side of the step |
| `pitch_hz` | The pitch the jump lands on, in Hz. Not set in `"hybrid"` mode |

A crack that goes up and comes back down is one event, since only the step up lands above the voice's range. Replies with no voiced speech, or audio that can't be decoded, are listed under `skipped`.

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many agent replies were counted and `turns_with_events` how many had at least one jump. The score is the share that had none.

## How Is It Calculated?

The `AbruptPitchJumpMetric` score is calculated according to the following equation:

<Equation formula="\text{Abrupt Pitch Jump} = \frac{\text{Number of Agent Replies Without a Pitch Jump}}{\text{Total Number of Agent Replies}}" />

The metric reads per-turn audio, one agent clip at a time, or replies cut from stereo full call audio when no turn has audio. The caller's turns are never checked. A reply counts as having a jump at most once, however many it has.

### Which replies are scored

A reply is scored if any of it is voiced. The metric tracks the pitch of every 40 ms of the clip, between 70 and 500 Hz. Stretches that are near silent, or have no clear pitch (such as "s" or "f" sounds), are left out. In each 40 ms, the tracker takes the shortest repeat period that fits about as well as the best one, since any multiple of the true period fits just as well and would read an octave or more too low.

### Pitch jump criteria

<VoiceDiagram
  duration={4}
  lanes={[
    { label: "Agent", role: "agent", clips: [{ start: 0.2, end: 3.8, label: "turn 1" }], sounds: [{ start: 0.3, end: 3.7 }] },
  ]}
  highlights={[
    { start: 1.2, end: 1.9, lane: 0 },
  ]}
  marks={[
    { at: 1.2, lane: 0, tone: "bad", label: "jump up" },
    { at: 1.9, lane: 0, tone: "ok", label: "back down" },
  ]}
/>

A jump is a step in pitch from one 40 ms frame straight to the next, between two steady stretches:

| Check | Rule |
| --- | --- |
| Steady before | At least 5 frames (200 ms), each within 3 semitones of the one before |
| Steady after | At least 5 frames, the same way |
| No gap | The two stretches are back to back, with no unvoiced frame between |
| Step size | 6 semitones or more, between the median of the last 5 frames before and the first 5 frames after |
| Above the range | The first 5 frames after land at least 1 semitone above the 95th percentile of the agent's voiced pitch across the call |

A 6 semitone step in 40 ms is 150 semitones a second, about 2.5 times the fastest pitch change a speaker can make on purpose, so normal intonation never reaches it.

Two kinds of step are not counted:

- **Short stretches.** A stretch under 200 ms on either side is a slip of the tracker or one syllable's own movement, not the voice breaking.
- **Steps inside the voice's range.** A voice spends 5% of its time above the top of its usual range. A step that lands inside it, including any step down, is how the voice normally moves.

If no agent reply has voiced speech, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

### Second check

A stressed word steps up just like a glitch does, and only a listener can tell them apart. So in the [hybrid eval mode](/docs/metrics-voice-introduction#choose-who-judges-with-eval-modes), the metric doesn't use the rules above. It flags every step up that could be a crack, and has the audio decision model confirm each one. A step up is flagged when:

| Check | Rule |
| --- | --- |
| Step size | 6 semitones or more up, from the median of the 80 ms before |
| Held | The next 3 frames (120 ms) are voiced and stay within 3 semitones of their median |
| Gap | At most 80 ms of unvoiced frames between the two |
| Range | The 3 frames land at or above the 90th percentile of the agent's voiced pitch across the call |

The audio decision model hears about 5 seconds of the agent's audio around each step and is asked:

> Does the speaker's voice suddenly jump to a different pitch, as if it glitched or cracked?

If the model judges "no" more likely than "yes", the step is dismissed and doesn't count against the score.

          the top tenth of the voice's range are sent to the audio decision
          model, so it can catch shorter cracks.
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external speech model?",
      answer: (
        <>
          Not by default. Detection is deterministic and runs locally over the
          audio, so it has no model or token cost. In the{" "}
          <code>"hybrid"</code> eval mode, each possible jump is also checked by
          an audio decision model, at one paid request per jump.
        </>
      ),
    },
    {
      question: "Does it check the caller's audio too?",
      answer: (
        <>
          No. Only the agent's replies are scored. The caller's audio comes
          from your own TTS model, so a problem there is with the test harness,
          not the agent.
        </>
      ),

  ]}
