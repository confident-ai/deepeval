The pitch variation metric checks whether your voice agent's pitch **moves naturally within a reply**: not a flat, robotic reading with no rise or fall, and not a voice swinging wildly up and down. It returns the share of agent replies whose pitch varies within range, between 0 and 1.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import PitchVariationMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = PitchVariationMetric(
    threshold=0.8, min_spread_semitones=1, max_spread_semitones=6
)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **SEVEN** optional parameters when creating a `PitchVariationMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `min_spread_semitones`: an integer for the least pitch spread, in semitones, a reply may have before it counts as monotone. Defaulted to `1`.
- [Optional] `max_spread_semitones`: an integer for the most pitch spread, in semitones, a reply may have before it counts as erratic. Defaulted to `6`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`min_spread_semitones` must be 0 or more and lower than `max_spread_semitones`, or a `ValueError` is raised.

`score_breakdown` lists the replies where the issue was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [{"type": "monotone", "turn": 3, "pitch_spread_semitones": 0.6, "offset_seconds": 0.0, "duration_seconds": 4.2, "start_time": 10.5}],
    "skipped": [{"turn": 5, "error": "Reply has under 1s of voiced speech to follow its pitch."}],
}
```

`turn` is the turn's zero-based position in the conversation. An event's `type` is `monotone` or `erratic`, and `pitch_spread_semitones` is how widely the reply's pitch moved. The event covers the whole reply: `offset_seconds` is 0, `duration_seconds` is the reply's length, and `start_time` is where the reply starts on the call's clock (left out when the clip has no `Audio.start_time`). Agent replies whose audio could not be decoded, or that have under one second of voiced speech, are listed under `skipped`.

## How Is It Calculated?

`PitchVariationMetric` checks every agent reply with at least one second of voiced speech and scores the share of them without the issue:

<Equation formula="\text{Pitch Variation} = \frac{\text{Agent replies with a pitch spread from min to max}}{\text{Agent replies with one or more seconds of voiced speech}}" />

The pitch of every 40 ms frame is tracked with the YIN method (de Cheveigné & Kawahara, 2002), and brief jumps of an octave, a common tracking slip, are folded back: a stretch of up to three frames sitting within 3 semitones of an octave off its neighbours. The spread is how far the frames typically sit from the reply's median pitch, in semitones, so a deep voice and a high voice are judged the same way. It is the median distance scaled by 1.4826 (so it reads like a standard deviation), so a single cracked word does not move it; cracks are reported by [`AbruptPitchJumpMetric`](/docs/metrics-abrupt-pitch-jump).

Adults reading aloud vary their pitch by about **2.2 semitones** (the clinical "pitch sigma" measure). The default of **1 semitone** is flatter than normal speech; **6 semitones** is nearly three times the norm. Expressive TTS voices can run wider than people reading aloud, so raise `max_spread_semitones` if a lively voice is flagged as erratic.

If no agent reply has enough voiced speech, the metric is skipped.

      question: "Why semitones rather than Hz?",
      answer: (
        <>
          A 20 Hz swing is large for a deep voice and small for a high one.
          Semitones measure pitch the way listeners hear it, so the same limit
          works for any voice.
        </>

      question: "Does this metric call an LLM or an external speech model?",

          No. Detection is deterministic and runs locally over the audio
          samples, so it has no model or token cost.
        </>
      ),
    },
    {
      question: "Does it check the simulated user's audio too?",
      answer: (
        <>
          No. Only assistant turns are inspected. The caller's audio is produced
          by your own TTS model, so defects there are a problem with the test
          harness rather than with the agent under test.
