The speaking rate metric checks whether your voice agent **talks at a comfortable pace**, neither rushing through a reply nor dragging it out. It returns the share of agent replies spoken at a normal rate, between 0 and 1.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import SpeakingRateMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = SpeakingRateMetric(threshold=0.8, min_wpm=110, max_wpm=200)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **SEVEN** optional parameters when creating a `SpeakingRateMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `min_wpm`: an integer for the slowest rate, in words per minute, a reply may be spoken at. Defaulted to `110`.
- [Optional] `max_wpm`: an integer for the fastest rate, in words per minute, a reply may be spoken at. Defaulted to `200`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`min_wpm` must be 0 or more and lower than `max_wpm`, or a `ValueError` is raised.

`score_breakdown` lists the replies where the issue was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [{"type": "too_fast", "turn": 3, "speech_rate_wpm": 236, "offset_seconds": 0.0, "duration_seconds": 4.2, "start_time": 10.5}],
    "skipped": [{"turn": 5, "error": "Reply has no text or under 2 seconds of speech."}],
}
```

`turn` is the turn's zero-based position in the conversation. An event's `type` is `too_slow` or `too_fast`, and `speech_rate_wpm` is the reply's rate. The event covers the whole reply: `offset_seconds` is 0, `duration_seconds` is the reply's length, and `start_time` is where the reply starts on the call's clock (left out when the clip has no `Audio.start_time`). Agent replies whose audio could not be decoded, that have no text, or whose speech spans under two seconds from first to last sound are listed under `skipped`.

## How Is It Calculated?

`SpeakingRateMetric` checks every agent reply with text and at least two seconds from its first to its last spoken sound, and scores the share of them spoken at a normal rate:

<Equation formula="\text{Speaking Rate} = \frac{\text{Agent replies from min\_wpm to max\_wpm}}{\text{Agent replies with text, spanning two or more seconds of speech}}" />

The rate is the words in the reply's `content` divided by the time from its first to its last spoken sound. Pauses inside the reply count, the way conversational rates are usually measured, but silence before the agent starts and after it stops does not. Each whitespace-separated token with a letter in it counts as one word, and every digit counts as a word of its own, so a phone number read out digit by digit counts in full (`555-1234` is seven words). Tokens with neither, such as a lone dash, are not counted.

Conversation runs at about **120 to 190 words per minute**, and each default leaves a 10 wpm margin: **110** and **200**. TTS voices often speak faster than people do, so set `max_wpm` to match the pace you want from your agent.

The rate is an average over the reply. A rushed phone number inside an otherwise normal reply can be missed.

      question: "Why does it need the reply's text?",
      answer: (
        <>
          Counting words from audio alone needs a speech recognizer. The text
          the agent spoke is already on each turn, so the metric uses it and
          stays free and deterministic.
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external speech model?",
      answer: (
        <>
          No. Detection is deterministic and runs locally over the audio
          samples and the turn text, so it has no model or token cost.
        </>
      ),
    },
    {
      question: "Does it check the simulated user's audio too?",
      answer: (
        <>
          No. Only assistant turns are inspected. The caller's audio is produced
          by your own TTS model, so defects there are a problem with the test
          harness rather than with the agent under test.
        </>
      ),
    },
