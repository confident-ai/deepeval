The speaking rate metric checks whether your voice agent **talks at a comfortable pace**, neither rushing through a reply nor dragging it out. It returns the share of agent replies spoken at a normal rate, between 0 and 1.

<AudioSample name="speaking-rate" />

## Required Arguments

To use the `SpeakingRateMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `audio` on the agent's turns, one clip per reply

The `content` on the agent's turns is optional. When it's there, it's only used to [skip replies that spell something out](#which-replies-are-scored).

## Usage

The `SpeakingRateMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import SpeakingRateMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = SpeakingRateMetric(
    threshold=0.8, min_syllables_per_second=3.5, max_syllables_per_second=10
)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **FOUR** optional parameters specific to the `SpeakingRateMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `min_syllables_per_second`: a float for the slowest rate, in syllables per second, a reply may be spoken at. Must be 0 or more. Defaulted to `3.5`.
- [Optional] `max_syllables_per_second`: a float for the fastest rate, in syllables per second, a reply may be spoken at. Must be greater than `min_syllables_per_second`. Defaulted to `10.0`.
- [Optional] `eval_mode`: `"deterministic"` or `"hybrid"`. In `"hybrid"`, the metric also flags replies close to a limit, and each flagged reply is [double-checked by an audio decision model](/docs/metrics-voice-introduction#second-check-with-an-audio-decision-model) before it counts. Defaulted to the configured voice eval mode (`"deterministic"` unless set).
- [Optional] `audio_decision_model`: the model that does the second check in `"hybrid"` mode. Defaulted to `HumeDecisionModel()`.

A value outside these limits raises a `ValueError`.

### As a standalone

You can also run the `SpeakingRateMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each reply spoken too fast or too slowly shows up in `score_breakdown`. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 4,
    "turns_with_events": 2,
    "events": [
        {
            "type": "too_fast",
            "turn": 3,
            "timing_source": "turn_timestamps",
            "description": "Agent spoke too fast (12.1 syllables a second)",
            "syllables_per_second": 12.1,
            "offset_seconds": 0.0,
            "duration_seconds": 4.0,
            "start_time": 8.0,
            "mark": "whole_reply",
        },
        {
            "type": "too_slow",
            "turn": 7,
            "timing_source": "turn_timestamps",
            "description": "Agent spoke too slowly (3.1 syllables a second)",
            "syllables_per_second": 3.1,
            "offset_seconds": 0.0,
            "duration_seconds": 4.0,
            "start_time": 20.0,
            "mark": "whole_reply",
        },
    ],
    "skipped": [
        {"turn": 5, "error": "Reply spells something out."},
        {"turn": 9, "error": "Reply has under 2 seconds of speech."},
    ],
}
```

| Field | What it means |
| --- | --- |
| `type` | Too fast if over `max_syllables_per_second`, too slow if under `min_syllables_per_second` |
| `syllables_per_second` | The reply's rate, in syllables per second of speaking time |

Each event covers the whole reply: `offset_seconds` is 0 and `duration_seconds` is the clip's length. Replies with under 2 seconds of speaking time, replies that spell something out, or audio that can't be decoded are listed under `skipped`.

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many agent replies were counted and `turns_with_events` how many were too fast or too slow. The score is the share that were neither.

## How Is It Calculated?

The `SpeakingRateMetric` score is calculated according to the following equation:

<Equation formula="\text{Speaking Rate} = \frac{\text{Number of Agent Replies Spoken at a Normal Rate}}{\text{Total Number of Agent Replies}}" />

The metric reads per-turn audio, one agent clip at a time, or replies cut from stereo full call audio when no turn has audio. The caller's turns are never checked.

### Which replies are scored

  ]}
  brackets={[
    { start: 0.8, end: 4.0, lane: 0, label: "speaking time" },
    { start: 5.8, end: 7.0, lane: 0, tone: "skip", label: "too short" },

A reply is scored if:

- it has at least 2 seconds of speaking time, and
- its `content` doesn't spell something out.

Speaking time runs from the first to the last moment of the clip louder than silence (about −41 dBFS), minus every pause of 200 ms or more. Silence before the agent starts and after it stops is left out, and so are pauses inside the reply: an agent that stops to look something up is not talking slowly.

A reply spells something out when its `content` has:

- three letters or digits in a row, each said on its own, such as "B, Y, R",
- a letter given by a word, such as "B as in Boy", or
- a code of 6 or more characters with a digit in it, such as "SH5216742".

Reading out a name or an email letter by letter is slow on purpose, so these replies are skipped. A reply with no `content` is never skipped for this.

### Rate criteria

The rate is the number of syllables in the reply's audio divided by its speaking time, in seconds. Syllables are counted from the audio alone: the reply's loudness is read every 5 ms and smoothed over 35 ms, and each rise that stands at least 3 dB above the dips on both sides is one syllable (de Jong & Wempe, 2009).

| Check | Rule |
| --- | --- |
| Too fast | Over `max_syllables_per_second` (10 by default) |
| Too slow | Under `min_syllables_per_second` (3.5 by default) |

If no agent reply has enough speech, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

:::note
Agents on real calls speak at 5.1 to 7.7 syllables a second (the middle 90% of replies). The defaults sit beyond the slowest and fastest 1 in 1,000. The rate is an average over the reply, so a rushed phone number inside an otherwise normal reply can be missed.
:::

### Second check

In the [hybrid eval mode](/docs/metrics-voice-introduction#choose-who-judges-with-eval-modes), each flagged reply is double-checked before it counts. The syllable count alone can't tell a reply close to a limit from normal speech, so in this mode the metric also flags replies within 1.5 syllables a second of a limit: under 5 or over 8.5 with the defaults. The audio decision model hears the **agent's** whole reply, from that turn's own clip, and is asked:

> Is the speaker talking unnaturally slowly?

for a reply flagged as too slow, or:

> Is the speaker talking unnaturally fast?

for a reply flagged as too fast. If the model judges "no" more likely than "yes", the reply is dismissed and doesn't count against the score.

## FAQs

<FAQs
  qas={[
    {
      question: "Does it need the reply's text?",
      answer: (
        <>
          No. Syllables are counted from the audio, so the rate doesn't depend
          on the text. The text is only used to skip replies that spell
          something out. Without it, those replies are scored like any other.
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external speech model?",
      answer: (
        <>
          Not by default. Detection is deterministic and runs locally over the
          audio and the turn text, so it has no model or token cost. In the{" "}
          <code>"hybrid"</code> eval mode, each flagged reply is also checked by
          an audio decision model, at one paid request per flagged reply.
        </>
      ),
    },
    {
      question: "Does it check the caller's audio too?",
      answer: (
        <>
          No. Only the agent's replies are scored. The caller's audio comes
          from your own TTS model, so a problem there is with the test harness,
          not the agent.
        </>
      ),
    },
  ]}
