The silent reply metric checks whether your voice agent's replies **could actually be heard**: a reply that exists as text but was never played, or played as silence, leaves the caller hearing nothing. It returns the share of agent replies the caller could hear, between 0 and 1.

<AudioSample name="silent-reply" />

## Required Arguments

To use the `SilentReplyMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `audio` on the agent's turns
- `content` on the agent's turns, so a reply with text but no audio can be caught

The metric only reads [per-turn audio](/docs/metrics-voice-introduction#full-call-audio-vs-per-turn-audio). The test case's own `audio` is not used.

## Usage

The `SilentReplyMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import SilentReplyMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = SilentReplyMetric(threshold=1.0)
evaluate(test_cases=test_cases, metrics=[metric])
```

The `SilentReplyMetric` takes only the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics).

### As a standalone

You can also run the `SilentReplyMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each reply the caller couldn't hear shows up in `score_breakdown`. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 4,
    "turns_with_events": 2,
    "events": [
        {
            "type": "no_audio",
            "turn": 3,
            "timing_source": "turn_timestamps",
            "description": "Reply had no audio",
        },
        {
            "type": "no_speech",
            "turn": 5,
            "timing_source": "turn_timestamps",
            "description": "Reply had no audible speech",
            "offset_seconds": 0.0,
            "duration_seconds": 2.0,
            "start_time": 12.0,
            "mark": "whole_reply",
        },
    ],
    "skipped": [],
}
```

| Field | What it means |
| --- | --- |
| `type` | No audio if the reply has text but no audio, no speech if its audio holds no audible sound |
| `turn` | Which agent turn was silent, counting from 0 |
| `duration_seconds` | No speech only. The length of the reply's clip |
| `start_time` | No speech only. Where the reply starts, in seconds into the call. Missing when the clip has no `Audio.start_time` |

A reply with no audio has nothing to place on the call, so its event has no `start_time` or `mark`. Agent turns whose audio can't be decoded are listed under `skipped`.

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many agent replies were counted and `turns_with_events` how many were silent. The score is the share that could be heard.

## How Is It Calculated?

The `SilentReplyMetric` score is calculated according to the following equation:

<Equation formula="\text{Silent Reply} = \frac{\text{Number of Agent Replies With Audible Sound}}{\text{Total Number of Agent Replies}}" />

The metric reads [per-turn audio](/docs/metrics-voice-introduction#full-call-audio-vs-per-turn-audio) only, and only the agent's turns.

Every agent turn with text or audio is one reply, including a turn with text but no clip, and a clip with no text. An agent turn with neither isn't a silent reply but no reply at all, so it is left to [Failed Response](/docs/metrics-failed-response). Clips that can't be decoded are skipped.

### Silence criteria

A reply is silent when:

| Check | Rule |
| --- | --- |
| No audio | The turn has text but no `audio` |
| No audible sound | Every 20 ms of the clip is below an RMS level of 300, about −41 dBFS |

A reply that goes quiet only partway through is [Dead Stream](/docs/metrics-dead-stream)'s to report. The level metrics, such as [Loudness](/docs/metrics-loudness), skip inaudible replies and leave them to this metric. If no turn has audio, or no agent turn has text or audio, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).
