The silent reply metric checks whether your voice agent's replies **could actually be heard**: a reply that exists as text but was never played, or played as silence, leaves the caller hearing nothing. It returns the share of agent replies the caller could hear, between 0 and 1.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import SilentReplyMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = SilentReplyMetric(threshold=1.0)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **FIVE** optional parameters when creating a `SilentReplyMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the replies where the issue was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [{"type": "no_audio", "turn": 3}],
    "skipped": [{"turn": 5, "error": "Audio is not a decodable PCM WAV."}],
}
```

`turn` is the turn's zero-based position in the conversation. An event's `type` is `no_audio` when the reply has text but no audio, or `no_speech` when its audio holds nothing above the speech floor. A `no_speech` event covers the whole reply: `offset_seconds` is 0, `duration_seconds` is the reply's length, and `start_time` is where the reply starts on the call's clock (left out when the clip has no `Audio.start_time`). Agent replies whose audio could not be decoded are listed under `skipped`.

## How Is It Calculated?

`SilentReplyMetric` checks every agent turn that has text to say, and scores the share the caller could hear:

<Equation formula="\text{Silent Reply} = \frac{\text{Agent replies with audible speech}}{\text{Agent replies with text}}" />

A reply is silent when it carries no audio at all, or when every 20 ms frame of its audio sits below the level counted as speech. An agent turn with neither text nor audio is not a silent reply but no reply at all, and is reported by [`FailedResponseMetric`](/docs/metrics-failed-response). A reply that goes dead partway through is reported by [`DeadStreamMetric`](/docs/metrics-dead-stream). A conversation with no audio on any turn is not a voice call, so the metric is skipped, as it is when no agent turn has text to say.
