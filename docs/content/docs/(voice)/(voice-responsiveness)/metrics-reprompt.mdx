The reprompt metric checks whether the caller **had to speak again before your voice agent replied**, as in "Can you check my order?" followed by "Hello? Are you there?". It finds likely repeats from the call's timing, then asks a decision model whether each one really is a repeat. It returns the share of caller lines the agent answered without being prompted again, between 0 and 1.

## Required Arguments

To use the `RepromptMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `content` on each turn, which the decision model reads
- `audio` on the turns, with `Audio.start_time` set so the wait before a repeat can be measured. A line whose wait can't be measured is never flagged

A stereo recording on the test case isn't enough on its own: the metric matches each transcript line to its turn's audio, so without per-turn audio it's skipped and says why.

## Usage

The `RepromptMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import RepromptMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks a question that requires the agent to look up an account.",
    expected_outcome="The agent answers without the user having to repeat themselves.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = RepromptMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **TWO** optional parameters specific to the `RepromptMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `system_one_model`: the Jev model that decides whether each likely repeat is real, as a string or a `DeepEvalBaseSystemOneModel`. It is used whatever the [eval mode](/docs/evaluation-eval-modes), but only when the call has a likely repeat. It is built the first time it's needed, so creating the metric needs no TypeSafe AI key. Defaulted to <DefaultSystemOneModel />.
- [Optional] `use_speech_detection`: a boolean which when set to `True`, finds where the speech is inside each turn's clip with [speech detection](/docs/metrics-voice-introduction#speech-detection), so silence or noise at a clip's edges isn't counted as speaking. It decides which caller turns join into one line, and how long the caller waited. Defaulted to `True`.

### As a standalone

You can also run the `RepromptMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each caller line the caller had to repeat shows up in `score_breakdown`. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 6,
    "turns_with_events": 1,
    "events": [
        {
            "type": "user_reprompted",
            "turn": 1,
            "duration_seconds": 6.24,
            "start_time": 4.76,
            "mark": "range",
            "timing_source": "turn_timestamps",
            "description": "Caller repeated themselves after 6.2s",
            "reprompt_turn": 2,
        }
    ],
    "skipped": [],
}
```

| Field | What it means |
| --- | --- |
| `turn` | The first turn of the caller line that wasn't answered in time, counting from 0. Unlike most voice metrics, this is a caller turn |
| `reprompt_turn` | The caller turn that came straight after, where they spoke again |
| `start_time` | Where the caller line's speech ends, in seconds into the call |
| `duration_seconds` | How long the caller waited in silence before speaking again |

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many caller lines needed a reply and `turns_with_events` how many had to be repeated. The score is the share that didn't.

## How Is It Calculated?

The `RepromptMetric` score is calculated according to the following equation:

<Equation formula="\text{Reprompt} = \frac{\text{Number of Caller Lines Answered Without a Repeat}}{\text{Total Number of Caller Lines That Needed a Reply}}" />

The metric only uses the audio to time the caller's turns. It never judges how they sound.

Caller turns in a row are one line when the next one's speech starts less than 1 second after the previous one's speech ends, as with turns 0 and 1 above. A transcriber splitting a sentence isn't the caller speaking again. The metric listens inside each clip for where the speech starts and stops. A turn without an `Audio.start_time` can't be timed, so it is always a line of its own. Lines that close the call, ending in "bye", "goodbye", "thank you", "thanks", "that's all" or "that is all", aren't counted.

A caller line is a likely repeat when the caller's very next turn starts a new line, and the agent replies later in the call. Each likely repeat then goes to a decision model, which reads:

- the agent's line before it,
- the caller's line,
- how long the caller waited, and
- what the caller said next.

It answers one question: does the next line only say the line again, or check that someone is still there, without adding anything new? If yes, the line counts as repeated. A caller who adds something new isn't repeating, even when they start by saying the line again: more detail, the rest of an unfinished sentence, a different answer, thanks or a goodbye. Nor is a caller who says something unrelated or talks to someone else.

| Check | Rule |
| --- | --- |
| Waited | At least 2.5 seconds of silence from the end of the line's speech to the start of the next line's. A shorter pause is the caller still talking. Both turns need an `Audio.start_time`, or the wait isn't known and the line isn't flagged |
| Not just a greeting | When the next line is only a greeting, such as "hi", "hello", "hey" or "hello there", the wait must be at least 4 seconds |
| Not an echo | Neither the line nor the next line is mostly the agent's own words. When a line has 3 or more words and at least 80% of them are in the agent's line before it, it is the agent's voice echoing on the caller's line |
| Answered later | An agent turn comes later in the call. A line never answered at all is left to [Failed Response](/docs/metrics-failed-response) |
| Really a repeat | The decision model says yes, with a probability of 0.5 or more |

All the likely repeats in a call go to the model in one request. If it returns no answer for one of them, the metric raises an error rather than guess. If no turn has audio, or no caller line needed a reply, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

          costs nothing. Because a model makes the final call, the score can
          differ between runs on the same audio. The cost is added to{" "}
          <code>evaluation_cost</code>, and the model's name is on{" "}
          <code>evaluation_model</code>.
        </>

    },
    {
      question: "Why does a caller who just keeps talking not count?",
      answer: (
        <>
          Speaking again isn't a repeat on its own. A pause under 2.5 seconds is
          the caller still talking, and after a longer one the decision model
          still has to hear the same request, a rewording or a "hello?", with
          nothing new added, before the line counts.
        </>
      ),
    },
