The failed response metric checks whether your voice agent **answered every caller line that needed an answer**, rather than letting the call end, or replying with nothing, after the caller spoke. It returns the share of caller lines that got a reply, between 0 and 1.

<AudioSample name="failed-response" />

## Required Arguments

To use the `FailedResponseMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `content` on each turn, to tell which caller lines needed a reply
- `audio` on the turns, with `Audio.start_time` set so caller turns can be placed on the call's clock

The metric only reads [turn audio](/docs/metrics-voice-introduction#call-audio-vs-turn-audio). The test case's own `audio` is not used.

## Usage

The `FailedResponseMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import FailedResponseMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = FailedResponseMetric(threshold=1.0)
evaluate(test_cases=test_cases, metrics=[metric])
```

There is **ONE** optional parameter specific to the `FailedResponseMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `use_speech_detection`: a boolean which when set to `True`, finds where the speech is inside each turn's clip with [speech detection](/docs/metrics-voice-introduction#speech-detection), so silence or noise at a clip's edges isn't counted as speaking. It decides which caller turns join into one line, and where the silence after a line starts. Defaulted to `True`.

### As a standalone

You can also run the `FailedResponseMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each caller line that went unanswered shows up in `score_breakdown`. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 4,
    "turns_with_events": 2,
    "events": [
        {
            "type": "empty_reply",
            "turn": 4,
            "duration_seconds": 2.74,
            "start_time": 12.26,
            "mark": "range",
            "timing_source": "turn_timestamps",
            "description": "Agent's reply was empty",
            "reply_turn": 5,
        },
        {
            "type": "call_ended_without_reply",
            "turn": 8,
            "duration_seconds": 0.24,
            "start_time": 22.76,
            "mark": "range",
            "timing_source": "turn_timestamps",
            "description": "Call ended without a reply",
        },
    ],
    "skipped": [],
}
```

| Field | What it means |
| --- | --- |
| `type` | Call ended without reply if no agent turn came after the line, empty reply if the agent's next turn had no text and no audio |
| `turn` | The caller line's first turn, counting from 0. Unlike most voice metrics, this is a caller turn |
| `reply_turn` | Empty replies only. The agent turn that was empty |
| `start_time` | Where the caller line's speech ends, in seconds into the call |
| `duration_seconds` | The silence after it: up to where the next turn's speech starts, or to the end of the call's last audio |

`start_time` and `duration_seconds` are missing when the line's last turn has no `Audio.start_time`.

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many caller lines needed a reply and `turns_with_events` how many went unanswered. The score is the share that were answered.

## How Is It Calculated?

The `FailedResponseMetric` score is calculated according to the following equation:

<Equation formula="\text{Failed Response} = \frac{\text{Number of Caller Lines Answered}}{\text{Total Number of Caller Lines That Needed a Reply}}" />

The metric reads [turn audio](/docs/metrics-voice-introduction#call-audio-vs-turn-audio) only, to time the caller's turns. It never judges how they sound.

A transcriber often splits one sentence into several turns. Caller turns in a row are one line when the next one's speech starts less than 1 second after the previous one's speech ends, as with turns 0 and 1 above. The metric listens inside each clip for where the speech starts and stops. A turn without an `Audio.start_time` can't be timed, so it is always a line of its own.

### Reply criteria

A caller line needs a reply unless it closes the call. It is unanswered when:

- no agent turn comes after it before the call ends, or
- the agent's next turn has no text and no audio.

Several caller lines in a row share the agent's next reply, so if the call ends after them, each one is unanswered.

| Check | Rule |
| --- | --- |
| Closes the call | The text of the line's last turn ends in "bye", "goodbye", "thank you", "thanks", "that's all" or "that is all", ignoring trailing periods and exclamation marks |
| Answered | Any agent turn after the line, with text or audio |

A reply only has to exist. Whether it could be heard is [Silent Reply](/docs/metrics-silent-reply)'s job, and how long it took is [Response Latency](/docs/metrics-response-latency)'s. If no turn has audio, or no caller line needed a reply, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).
