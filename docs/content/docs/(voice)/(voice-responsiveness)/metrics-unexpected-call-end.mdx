The unexpected call end metric checks whether your voice agent's call **ended properly**: not with the agent hanging up mid-conversation, and not with an error or a timeout. It returns 1 when the call ended normally and 0 when it did not.

<AudioSample name="unexpected-call-end" />

## Required Arguments

To use the `UnexpectedCallEndMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `content` on each turn, to tell whether the call wrapped up
- `metadata` saying how the call ended, as the [`ConversationSimulator`](/docs/conversation-simulator-voice-mode) records it under `"Stop reason"`, or as your platform records it under `"end_reason"`
- `audio` on at least one turn, so it is a voice call

The metric only reads [per-turn audio](/docs/metrics-voice-introduction#full-call-audio-vs-per-turn-audio), and only to place the call's end. The test case's own `audio` is not used.

## Usage

The `UnexpectedCallEndMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import UnexpectedCallEndMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = UnexpectedCallEndMetric(threshold=1.0)
evaluate(test_cases=test_cases, metrics=[metric])
```

The `UnexpectedCallEndMetric` takes only the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics).

### As a standalone

You can also run the `UnexpectedCallEndMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

A call that ended badly shows up in `score_breakdown` as one event. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 1,
    "turns_with_events": 1,
    "events": [
        {
            "type": "unexpected_end",
            "turn": 3,
            "duration_seconds": 0.0,
            "start_time": 11.0,
            "mark": "moment",
            "timing_source": "turn_timestamps",
            "description": "Call ended unexpectedly (agent_ended_call)",
            "end_reason": "agent_ended_call",
        }
    ],
    "skipped": [],
}
```

| Field | What it means |
| --- | --- |
| `end_reason` | Agent ended call when the simulator recorded the agent hanging up. Otherwise the test case's own `end_reason`, such as `ERROR` |
| `turn` | The call's last turn, counting from 0 |
| `start_time` | Where the call's last timed audio ends, in seconds into the call. Missing when no turn has an `Audio.start_time` |
| `duration_seconds` | Always 0: the end is a single moment |

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is always 1, the call, and `turns_with_events` is 1 when it ended badly. The score is 0 if it did and 1 if it didn't.

## How Is It Calculated?

The `UnexpectedCallEndMetric` score is calculated according to the following equation:

<Equation formula="\text{Unexpected Call End} = \begin{cases} 0 & \text{if the call ended unexpectedly} \\ 1 & \text{otherwise} \end{cases}" />

### Counting calls

Each test case is one call, so there is one thing to judge: how it ended.

### Ending criteria

The agent hanging up is only a problem if the call hadn't wrapped up. Above, a hang-up right after the question would be unexpected, while one after the caller's goodbye is normal. The checks run in this order:

| Check | Rule |
| --- | --- |
| Error or timeout | The `metadata` `end_reason` (or `endReason`) is `ERROR` or `IDLE_TIMEOUT`, in any letter case. Always unexpected, however the call went |
| Wrapped up | The caller's last line ends in "bye", "goodbye", "thank you", "thanks", "that's all" or "that is all", ignoring trailing periods and exclamation marks, or the agent's last line contains the word "bye" or "goodbye". Then the end is normal |
| Agent hung up | The `metadata` `"Stop reason"` is "The agent ended the call", or `end_reason` is `AGENT_HANGUP`. Unexpected |

A call with none of these, such as a simulation that ran its full number of turns, ended normally. If no turn has audio, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).
