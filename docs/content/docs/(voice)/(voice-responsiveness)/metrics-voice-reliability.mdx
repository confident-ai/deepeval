The voice reliability metric is the **operational summary** of a call: did the agent answer, and did its audio arrive intact? It runs every check of [agent responsiveness](/docs/metrics-agent-responsiveness) and [audio integrity](/docs/metrics-audio-integrity) together, and returns the share of exchanges none of them flagged, between 0 and 1.

:::note
Use this as the one number to gate a CI run on. It answers "did the call work?" rather than "was the call good?" — quality lives in [voice naturalness](/docs/metrics-voice-naturalness), [speech intelligibility](/docs/metrics-speech-intelligibility), and your usual multi-turn metrics.
:::

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import VoiceReliabilityMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user calls to cancel an appointment and reschedule it.",
    expected_outcome="The agent cancels the old appointment and books a new one.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = VoiceReliabilityMetric(threshold=0.9)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **SIX** optional parameters when creating a `VoiceReliabilityMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `use_speech_detection`: a boolean which, when set to `True`, only counts the caller as talking when the sound on their channel is speech, so background noise is not mistaken for the caller. Only applies with a stereo `call_recording_path`, and is passed to the [Abrupt Cut-off](/docs/metrics-abrupt-cut-off) check. Defaulted to `True`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

Every voice metric records what it measured on `score_breakdown`. Read it after a standalone `measure()` call, or turn on `verbose_mode` to have it printed during an `evaluate()` run:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.5
print(metric.score_breakdown)
```

For `VoiceReliabilityMetric` the breakdown counts the exchanges, lists every issue found, and gives each part's own result. Here the agent's second reply looped, and the agent hung up on the caller's last question:

```python
{

    "turns_with_events": 2,
    "events": [
        {"type": "call_ended_without_reply", "turn": 6, "offset_seconds": 0.0, "duration_seconds": 2.1, "start_time": 16.0, "metric": "Failed Response"},
        {"type": "unexpected_end", "turn": 6, "end_reason": "agent_ended_call", "offset_seconds": 0.0, "duration_seconds": 2.1, "start_time": 16.0, "metric": "Unexpected Call End"},
        {"type": "audio_loop", "turn": 3, "offset_seconds": 1.5, "duration_seconds": 0.75, "start_time": 7.5, "metric": "Audio Loop"},
    ],
    "skipped": [],
    "metrics": {
        "Failed Response": {"score": 0.75, "eligible_turns": 4, "turns_with_events": 1},
        "Silent Reply": {"score": 1.0, "eligible_turns": 3, "turns_with_events": 0},
        "Unexpected Call End": {"score": 0.0, "eligible_turns": 1, "turns_with_events": 1},
        "Reprompt": {"score": 1.0, "eligible_turns": 4, "turns_with_events": 0},
        "Abrupt Cut-off": {"score": 1.0, "eligible_turns": 3, "turns_with_events": 0},
        "Audio Loop": {"score": 0.6666666666666667, "eligible_turns": 3, "turns_with_events": 1},
        "Audio Dropout": {"score": 1.0, "eligible_turns": 3, "turns_with_events": 0},
        "Audio Clipping": {"score": 1.0, "eligible_turns": 3, "turns_with_events": 0},
    },
}
```

Here `eligible_turns` is how many **exchanges** were judged and `turns_with_events` how many had at least one issue. `events` holds each part's events unchanged, tagged with the `metric` that raised them; the part's own page explains its fields. `skipped` collects the turns a part could not judge. `metrics` gives each part's own `score`, `eligible_turns` and `turns_with_events`, counted the part's own way, or `{"score": None, "reason": ...}` when that part could not judge the call. The reason for the call above reads "2 of 4 exchanges had an issue: Failed Response (1), Unexpected Call End (1), Audio Loop (1)."

When the call has no agent turns, or an agent turn's audio cannot be decoded, the breakdown is the critical failure instead:

```python
{
    "critical_failure": True,
    "events": [{"type": "audio_undecodable", "turn": 3, "reason": "Audio is not a decodable PCM WAV."}],
}
```

## How Is It Calculated?

`VoiceReliabilityMetric` runs the parts of both metrics it combines, each with its default settings:

| Part                                                     | From                 | Flags                                                   |
| -------------------------------------------------------- | -------------------- | ------------------------------------------------------- |
| [Failed Response](/docs/metrics-failed-response)         | Agent Responsiveness | a caller line the agent never answered.                 |
| [Silent Reply](/docs/metrics-silent-reply)               | Both                 | an agent reply the caller could not hear.               |
| [Unexpected Call End](/docs/metrics-unexpected-call-end) | Agent Responsiveness | a call that ended badly.                                |
| [Reprompt](/docs/metrics-reprompt)                       | Agent Responsiveness | a caller line the caller had to repeat.                 |
| [Abrupt Cut-off](/docs/metrics-abrupt-cut-off)           | Audio Integrity      | an agent reply that stops mid-sound.                    |
| [Audio Loop](/docs/metrics-audio-loop)                   | Audio Integrity      | an agent reply stuck repeating the same chunk of audio. |
| [Audio Dropout](/docs/metrics-audio-dropout)             | Audio Integrity      | an agent reply that cuts out mid-speech.                |
| [Audio Clipping](/docs/metrics-audio-clipping)           | Audio Integrity      | an agent reply distorted from being too loud.           |

Each issue is counted against an **exchange**: a caller line and the agent's reply to it. Caller turns that start less than 1 second after the previous one ends are one line, as in [Reprompt](/docs/metrics-reprompt). An agent turn spoken before the caller's first line is an exchange of its own. The score is the share of judged exchanges that none of the parts flagged:

<Equation formula="\text{Voice Reliability} = 1 - \frac{\text{Exchanges flagged by at least one part}}{\text{Exchanges judged}}" />

Two issues in the same exchange count once. A part that cannot judge the call is left out of the score, and if no part can judge it, the metric is skipped.

Like Audio Integrity, two checks run before the parts and force the score to 0, with the reason "A critical failure occurred: ..." naming them: `assistant_turn_missing` when the conversation has no agent turns, and `audio_undecodable` when an agent turn's audio cannot be decoded. Nothing else zeroes the score.

With a stereo call recording (`call_recording_path`), cut-offs are read from the recording, and each one counts against the agent reply that started last before the cut. A cut before the test case's first agent reply, such as one in turns left out of the test case, is not counted. That needs `start_time` on every audio turn; without it, cut-offs are read from each reply's own audio.

:::tip
Run this alongside a quality metric — [`VoiceNaturalnessMetric`](/docs/metrics-voice-naturalness) or [`SpeechIntelligibilityMetric`](/docs/metrics-speech-intelligibility) — rather than instead of one. A score of 1 here means every exchange got a reply with usable audio — it says nothing about whether those replies were helpful, natural, or correct.
:::
