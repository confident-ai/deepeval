The voice reliability metric is the **operational summary** of a call: did the agent answer, and did its audio arrive intact? It runs every part of [Agent Responsiveness](/docs/metrics-agent-responsiveness) and [Audio Integrity](/docs/metrics-audio-integrity) together, and returns the share of exchanges none of them flagged, between 0 and 1.

:::note
Use this as the one number to gate a CI run on. It answers "did the call work?" rather than "was the call good?". Quality lives in [Voice Naturalness](/docs/metrics-voice-naturalness), [Speech Intelligibility](/docs/metrics-speech-intelligibility) and your usual multi-turn metrics.
:::

## Required Arguments

To use the `VoiceReliabilityMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `content` on each turn
- `audio` on the turns, with `Audio.start_time` set so caller turns can be timed
- `metadata` saying how the call ended, for [Unexpected Call End](/docs/metrics-unexpected-call-end#required-arguments)
- optionally, `audio` on the test case, a stereo recording of the whole call\*, for the [Abrupt Cut-off](/docs/metrics-abrupt-cut-off) check

\* Full call audio has to be stereo, with the caller and agent on separate channels. Mono full call audio is ignored, because the two voices can't be told apart.

Read the [How Is It Calculated](#how-is-it-calculated) section below to learn how each is used.

## Usage

The `VoiceReliabilityMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import VoiceReliabilityMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user calls to cancel an appointment and reschedule it.",
    expected_outcome="The agent cancels the old appointment and books a new one.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = VoiceReliabilityMetric(threshold=0.9)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **TWO** optional parameters specific to the `VoiceReliabilityMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `use_speech_detection`: a boolean which when set to `True`, uses [speech detection](/docs/metrics-voice-introduction#speech-detection) to tell when someone is talking. It is passed to [Failed Response](/docs/metrics-failed-response), [Reprompt](/docs/metrics-reprompt) and [Abrupt Cut-off](/docs/metrics-abrupt-cut-off), and also decides which caller turns join into one exchange. Defaulted to `True`.
- [Optional] `system_one_model`: the Jev model [Reprompt](/docs/metrics-reprompt#reprompt-criteria) uses to decide whether each likely repeat is real, as a string or a `DeepEvalBaseSystemOneModel`. Defaulted to <DefaultSystemOneModel />.

### As a standalone

You can also run the `VoiceReliabilityMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

```python
{
    "critical_failure": True,
    "events": [
        {
            "type": "audio_undecodable",
            "turn": 3,
            "reason": "Audio is not a decodable PCM WAV.",
        }
    ],
}
```

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

The score is the share of exchanges with no issue. The reason names the parts, as in "3 of 5 exchanges had an issue: Failed Response (1), Unexpected Call End (1), Reprompt (1), Audio Clipping (1)."

## How Is It Calculated?

The `VoiceReliabilityMetric` score is calculated according to the following equation:

<Equation formula="\text{Voice Reliability} = \frac{\text{Number of Exchanges Without an Issue}}{\text{Total Number of Exchanges}}" />

It runs the parts of both roll-ups once each, Silent Reply being in both:

| Part | From | Flags |
| --- | --- | --- |
| [Failed Response](/docs/metrics-failed-response) | Agent Responsiveness | A caller line never answered |
| [Silent Reply](/docs/metrics-silent-reply) | Both | An agent reply the caller couldn't hear |
| [Unexpected Call End](/docs/metrics-unexpected-call-end) | Agent Responsiveness | A call that ended badly |
| [Reprompt](/docs/metrics-reprompt) | Agent Responsiveness | A caller line the caller had to repeat |
| [Abrupt Cut-off](/docs/metrics-abrupt-cut-off) | Audio Integrity | An agent reply that stops mid-sound |
| [Audio Loop](/docs/metrics-audio-loop) | Audio Integrity | An agent reply stuck repeating the same chunk |
| [Audio Dropout](/docs/metrics-audio-dropout) | Audio Integrity | An agent reply that cuts out mid-speech |
| [Audio Clipping](/docs/metrics-audio-clipping) | Audio Integrity | An agent reply distorted from being too loud |

### Combining the parts

Issues are counted per exchange, exactly as in [Agent Responsiveness](/docs/metrics-agent-responsiveness#counting-exchanges): a caller line and the agent turns after it. An issue in an agent reply counts against the exchange that reply is in. An exchange flagged by two parts counts once.

Abrupt Cut-off is the only part that prefers [full call audio](/docs/metrics-voice-introduction#full-call-audio-vs-per-turn-audio). The others read per-turn audio, or replies cut from stereo full call audio when no turn has audio. With stereo full call audio, each cut counts against the agent turn that started last before it. A cut before the first agent turn, such as one in turns left out of the test case, isn't counted. This needs `Audio.start_time` on every turn with audio. Without it, the full call audio is ignored and every part reads per-turn audio.

A part that can't judge the call is left out of the score. If no part can, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped), as for a call with no per-turn audio.

### Critical failures

Two checks run before the parts and force the score to 0, with the reason "A critical failure occurred: ..." naming them:

| Event | Meaning |
| --- | --- |
| `assistant_turn_missing` | The conversation has no agent turns at all, even if it has no audio either |
| `audio_undecodable` | An agent turn's audio can't be decoded. Carries the `turn` and a `reason` |

Nothing else zeroes the score.
