The agent responsiveness metric checks whether your voice agent **answered when it was spoken to**. It runs four single-issue voice metrics for replies that never came, replies the caller could not hear, calls that ended badly, and lines the caller had to repeat, and returns the share of exchanges none of them flagged, between 0 and 1.

:::note
Like the other responsiveness metrics, it reads the conversation's shape rather than how the audio sounded. A caller who has to say "hello? are you there?" is the failure it is built to catch — the kind that a transcript-based metric scores as a perfectly relevant exchange.
:::

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AgentResponsivenessMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks a question that requires the agent to look up an account.",
    expected_outcome="The agent answers without the user having to repeat themselves.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AgentResponsivenessMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **FIVE** optional parameters when creating an `AgentResponsivenessMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

Every voice metric records what it measured on `score_breakdown`. Read it after a standalone `measure()` call, or turn on `verbose_mode` to have it printed during an `evaluate()` run:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

For `AgentResponsivenessMetric` the breakdown counts the exchanges, lists every issue found, and gives each part's own result:

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [
        {"type": "user_reprompted", "turn": 2, "reprompt_turn": 3, "offset_seconds": 0.0, "duration_seconds": 1.8, "start_time": 7.2, "metric": "Reprompt"},
    ],
    "skipped": [],
    "metrics": {
        "Failed Response": {"score": 1.0, "eligible_turns": 4, "turns_with_events": 0},
        "Silent Reply": {"score": 1.0, "eligible_turns": 3, "turns_with_events": 0},
        "Unexpected Call End": {"score": 1.0, "eligible_turns": 1, "turns_with_events": 0},
        "Reprompt": {"score": 0.75, "eligible_turns": 4, "turns_with_events": 1},
    },
}
```

Here `eligible_turns` is how many **exchanges** were judged and `turns_with_events` how many had at least one issue. `events` holds each part's events unchanged, tagged with the `metric` that raised them; the part's own page explains its fields, including which turn `turn` points to. `skipped` collects the turns a part could not judge. `metrics` gives each part's own `score`, `eligible_turns` and `turns_with_events`, counted the part's own way, or `{"score": None, "reason": ...}` when that part could not judge the call. The reason for the call above reads "1 of 4 exchanges had an issue: Reprompt (1)."

## How Is It Calculated?

`AgentResponsivenessMetric` runs these single-issue metrics on the call, each with its default settings:

| Part                                                     | Flags                                                            |
| -------------------------------------------------------- | ---------------------------------------------------------------- |
| [Failed Response](/docs/metrics-failed-response)         | a caller line the agent never answered, or answered with an empty turn. |
| [Silent Reply](/docs/metrics-silent-reply)               | an agent reply the caller could not hear.                        |
| [Unexpected Call End](/docs/metrics-unexpected-call-end) | a call that ended with an agent hang-up mid-conversation, an error or a timeout. |
| [Reprompt](/docs/metrics-reprompt)                       | a caller line the caller had to follow with another before the agent replied. |

Each issue is counted against an **exchange**: a caller line and the agent's reply to it. Caller turns that start less than 1 second after the previous one ends are one line, as in [Reprompt](/docs/metrics-reprompt). An agent turn spoken before the caller's first line is an exchange of its own. The score is the share of judged exchanges that none of the parts flagged:

<Equation formula="\text{Agent Responsiveness} = 1 - \frac{\text{Exchanges flagged by at least one part}}{\text{Exchanges judged}}" />

Two issues in the same exchange count once: an agent that hangs up right after a question fails both Failed Response and Unexpected Call End, and costs one exchange. A part that cannot judge the call is left out of the score. A conversation with no audio on any turn is not a voice call, so the metric is skipped with the reason "The call has no audio to evaluate."
