The agent responsiveness metric checks whether your voice agent **answered when it was spoken to**. It runs four single-issue voice metrics, for replies that never came, replies the caller couldn't hear, calls that ended badly and lines the caller had to repeat, and returns the share of exchanges none of them flagged, between 0 and 1.

## Required Arguments

To use the `AgentResponsivenessMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `content` on each turn
- `audio` on the turns, with `Audio.start_time` set so caller turns can be timed
- `metadata` saying how the call ended, for [Unexpected Call End](/docs/metrics-unexpected-call-end#required-arguments)

The metric only reads [per-turn audio](/docs/metrics-voice-introduction#full-call-audio-vs-per-turn-audio). The test case's own `audio` is not used.

## Usage

The `AgentResponsivenessMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AgentResponsivenessMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks a question that requires the agent to look up an account.",
    expected_outcome="The agent answers without the user having to repeat themselves.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AgentResponsivenessMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **TWO** optional parameters specific to the `AgentResponsivenessMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `use_speech_detection`: a boolean which when set to `True`, finds where the speech is inside each turn's clip with [speech detection](/docs/metrics-voice-introduction#speech-detection). It is passed to [Failed Response](/docs/metrics-failed-response) and [Reprompt](/docs/metrics-reprompt), and also decides which caller turns join into one exchange. Defaulted to `True`.
- [Optional] `system_one_model`: the Jev model [Reprompt](/docs/metrics-reprompt#reprompt-criteria) uses to decide whether each likely repeat is real, as a string or a `DeepEvalBaseSystemOneModel`. Defaulted to <DefaultSystemOneModel />.

### As a standalone

You can also run the `AgentResponsivenessMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

| Field | What it means |
| --- | --- |
| `eligible_turns` | How many exchanges were judged |
| `turns_with_events` | How many exchanges had at least one issue |
| `metric` | On each event. The part that raised it. The part's own page explains its other fields |
| `skipped` | The turns any part couldn't judge, such as agent audio that won't decode |
| `metrics` | Each part's own score and counts, counted the part's own way. A part that couldn't judge the call shows a score of `None` and its reason |

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

The score is the share of exchanges with no issue. The reason names the parts, as in "2 of 5 exchanges had an issue: Failed Response (1), Unexpected Call End (1), Reprompt (1)."

## How Is It Calculated?

The `AgentResponsivenessMetric` score is calculated according to the following equation:

<Equation formula="\text{Agent Responsiveness} = \frac{\text{Number of Exchanges Without an Issue}}{\text{Total Number of Exchanges}}" />

It runs these four metrics on the call, each with its default settings apart from the two parameters above:

| Part | Flags | Counted against |
| --- | --- | --- |
| [Failed Response](/docs/metrics-failed-response) | A caller line never answered | That line's exchange |
| [Silent Reply](/docs/metrics-silent-reply) | An agent reply the caller couldn't hear | The exchange it replies in |
| [Unexpected Call End](/docs/metrics-unexpected-call-end) | A call that ended badly | The exchange holding the call's last turn |
| [Reprompt](/docs/metrics-reprompt) | A caller line the caller had to repeat | That line's exchange |

An exchange is one caller line and the agent turns after it, up to the next caller line. Caller turns join into one line as in [Failed Response](/docs/metrics-failed-response#counting-caller-lines), when the next one's speech starts less than 1 second after the previous one's ends. An agent turn before the caller's first line, such as a greeting, is an exchange of its own.

### Combining the parts

Each part's flagged items are counted against an exchange, as in the table above. An exchange flagged by two parts counts once: an agent that hangs up on a question fails both Failed Response and Unexpected Call End, and costs one exchange.

A part that can't judge the call is left out of the score. If no turn has audio, every part is skipped, and so is this metric, with the reason "The call has no audio to evaluate." There is no critical failure that zeroes the score: agent audio that won't decode is listed under `skipped`.

## FAQs

<FAQs
  qas={[
    {
      question: "Why did my score change?",
      answer: (
        <>
          This metric used to subtract 0.25 per reprompt and drop to 0 on a
          missed reply, a reply with no audio or a bad call ending. It now rolls
          up the single-issue metrics above and scores the share of exchanges
          with no issue, so nothing zeroes the score on its own.
        </>
      ),
    },
    {
      question: "How is this different from the single-issue metrics it runs?",
      answer: (
        <>
          Each part, such as{" "}
          <a href="/docs/metrics-failed-response">FailedResponseMetric</a>,
          checks one issue and points to the turns where it happened. This
          metric gives one number for all four, counted per exchange.
        </>
      ),
    },
    {
      question: "Does this metric measure response latency?",
      answer: (
        <>
          No, it measures whether a response happened at all. Latency is
          scored by{" "}
          <a href="/docs/metrics-response-latency">ResponseLatencyMetric</a>.
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external model?",
      answer: (
        <>
          Only through Reprompt. When the call has a likely repeat, Reprompt
          asks a Jev decision model whether it's real, in one request per
          call, so the score can differ between runs. A call with no likely
          repeat makes no model call. The other three parts are deterministic
          and run locally.
        </>
      ),
    },
  ]}
