The loudness metric checks whether your voice agent **speaks too quietly or too loudly**, for example so quietly that the caller has to turn the volume up. It returns the share of agent replies whose speech level falls inside an accepted range, between 0 and 1.

<AudioSample name="loudness" />

## Required Arguments

To use the `LoudnessMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `audio` on the agent's turns

The metric reads [per-turn audio](/docs/metrics-voice-introduction#full-call-audio-vs-per-turn-audio). If no turn has audio, it uses replies cut from stereo full call audio instead.

## Usage

The `LoudnessMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import LoudnessMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = LoudnessMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **TWO** optional parameters specific to the `LoudnessMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `min_dbfs`: an integer for the quietest speech level, in dBFS, a reply may have. Must be lower than `max_dbfs`. Defaulted to `-32`.
- [Optional] `max_dbfs`: an integer for the loudest speech level, in dBFS, a reply may have. Must be `0` or lower. Defaulted to `-6`.

### As a standalone

You can also run the `LoudnessMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each reply that was too quiet or too loud shows up in `score_breakdown`. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 4,
    "turns_with_events": 2,
    "events": [
        {
            "type": "too_quiet",
            "turn": 3,
            "timing_source": "turn_timestamps",
            "description": "Reply was too quiet (-36 dBFS)",
            "speech_dbfs": -35.7,
            "offset_seconds": 0.0,
            "duration_seconds": 3.0,
            "start_time": 8.5,
            "mark": "whole_reply",
        },
        {
            "type": "too_loud",
            "turn": 7,
            "timing_source": "turn_timestamps",
            "description": "Reply was too loud (-4 dBFS)",
            "speech_dbfs": -4.0,
            "offset_seconds": 0.0,
            "duration_seconds": 3.0,
            "start_time": 20.5,
            "mark": "whole_reply",
        },
    ],
    "skipped": [],
}
```

| Field | What it means |
| --- | --- |
| `type` | Too quiet or too loud |
| `speech_dbfs` | The reply's speech level, in dBFS |

Each event covers the whole reply, so `offset_seconds` is 0 and `duration_seconds` is the clip's length. Replies that are silent or can't be decoded are listed under `skipped`.

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many agent replies were counted and `turns_with_events` how many were out of range. The score is the share that weren't.

## How Is It Calculated?

The `LoudnessMetric` score is calculated according to the following equation:

<Equation formula="\text{Loudness} = \frac{\text{Number of Agent Replies Within the Loudness Range}}{\text{Total Number of Agent Replies}}" />

### Loudness criteria

<VoiceDiagram
  duration={6}
  hideAxis
  lanes={[
    { label: "Agent", role: "agent", sounds: [{ start: 0.3, end: 1.9, level: 0.15 }, { start: 2.2, end: 3.8, level: 0.55 }, { start: 4.1, end: 5.7, level: 1 }] },

  highlights={[
    { start: 0.3, end: 1.9, lane: 0 },
    { start: 4.1, end: 5.7, lane: 0 },
  ]}
  marks={[
    { at: 1.1, lane: 0, tone: "bad", label: "too quiet" },
    { at: 3.0, lane: 0, tone: "ok", label: "in range" },
    { at: 4.9, lane: 0, tone: "bad", label: "too loud" },
  ]}
/>

Each reply is cut into 20 ms frames. Its speech level is the 90th percentile of the frames at speech volume (about −41 dBFS or louder), so pauses don't make a reply look quiet.

| Check | Rule |
| --- | --- |
| Too quiet | Speech level below `min_dbfs` (−32 dBFS) |
| Too loud | Speech level above `max_dbfs` (−6 dBFS) |

If no reply has audible, decodable audio, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

:::note
Phone test speech sits near −22 dBFS on this scale (ITU-T P.56). −32 dBFS is 10 dB below that, about half as loud. −6 dBFS leaves under 6 dB before the loudest syllables clip.
:::
