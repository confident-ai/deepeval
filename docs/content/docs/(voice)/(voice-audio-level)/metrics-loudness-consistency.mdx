The loudness consistency metric checks whether your voice agent **keeps the same volume from one reply to the next**, rather than one reply being clearly louder or quieter than the rest. It returns the share of agent replies that stay close to the agent's typical loudness, between 0 and 1.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import LoudnessConsistencyMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = LoudnessConsistencyMetric(threshold=0.8, max_shift_db=5)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **SIX** optional parameters when creating a `LoudnessConsistencyMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `max_shift_db`: an integer for how far, in dB, a reply's loudness may sit from the agent's typical loudness. Must be greater than `0`. Defaulted to `5`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the replies where the issue was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [
        {"type": "loudness_shift", "turn": 3, "speech_dbfs": -9.1, "shift_db": 6.4, "offset_seconds": 0.0, "duration_seconds": 4.2, "start_time": 10.5}
    ],
    "skipped": [],
}
```

`turn` is the turn's zero-based position in the conversation, `speech_dbfs` is the reply's speech level, and `shift_db` is how far that sits from the agent's typical level (negative when quieter). The event covers the whole reply: `offset_seconds` is 0, `duration_seconds` is the reply's length, and `start_time` is where the reply starts on the call's clock (left out when the clip has no `Audio.start_time`). Agent replies whose audio could not be decoded, or that have no audible sound, are listed under `skipped`.

## How Is It Calculated?

`LoudnessConsistencyMetric` compares every agent reply against the agent's typical reply, and scores the share that stay close:

<Equation formula="\text{Loudness Consistency} = \frac{\text{Agent replies within max\_shift\_db of the typical loudness}}{\text{Audible agent replies with decodable audio}}" />

Each reply's level is the same speech level [`LoudnessMetric`](/docs/metrics-loudness) uses: the 90th percentile of its 20 ms speech frames, so pauses don't pull it down. The agent's typical level is the median across its replies, so a single odd reply is flagged on its own rather than dragging the reply after it down too. This needs at least **three** audible replies to tell which one is off; with fewer, the metric is skipped. A reply with no audible sound at all (no 20 ms frame reaches speech level, about −41 dBFS) is skipped and left out of the median; [`SilentReplyMetric`](/docs/metrics-silent-reply) reports it.

The default of **5 dB** is the change listeners clearly notice; 3 dB is only just perceptible. On real agent calls, replies stay within about 2.5 dB of each other.

          <a href="/docs/metrics-loudness">LoudnessMetric</a> checks each reply

      question: "Does this metric call an LLM or an external speech model?",

          No. Detection is deterministic and runs locally over the audio
          samples, so it has no model or token cost.
        </>
      ),
    },
    {
      question: "Does it check the simulated user's audio too?",
      answer: (
        <>
          No. Only assistant turns are inspected. The caller's audio is produced
          by your own TTS model, so defects there are a problem with the test
          harness rather than with the agent under test.
        </>
      ),
