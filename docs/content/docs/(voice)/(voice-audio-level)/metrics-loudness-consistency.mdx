The loudness consistency metric checks whether your voice agent **keeps the same volume from one reply to the next**, rather than one reply being clearly louder or quieter than the rest. It returns the share of agent replies that stay close to the agent's typical loudness, between 0 and 1.

<AudioSample name="loudness-consistency" />

## Required Arguments

To use the `LoudnessConsistencyMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `audio` on at least three of the agent's turns

## Usage

The `LoudnessConsistencyMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import LoudnessConsistencyMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = LoudnessConsistencyMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There is **ONE** optional parameter specific to the `LoudnessConsistencyMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `max_shift_db`: an integer for how far, in dB, a reply's loudness may sit from the agent's typical loudness. Must be greater than `0`. Defaulted to `5`.

### As a standalone

You can also run the `LoudnessConsistencyMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each reply that was clearly louder or quieter than usual shows up in `score_breakdown`. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [
        {
            "type": "loudness_shift",
            "turn": 5,
            "timing_source": "turn_timestamps",
            "description": "Reply was 8 dB quieter than usual",
            "speech_dbfs": -27.1,
            "shift_db": -8.0,
            "offset_seconds": 0.0,
            "duration_seconds": 3.0,
            "start_time": 14.5,
            "mark": "whole_reply",
        }
    ],
    "skipped": [],
}
```

| Field | What it means |
| --- | --- |
| `speech_dbfs` | The reply's speech level, in dBFS |
| `shift_db` | How far that sits from the agent's typical level. Negative when quieter |

Each event covers the whole reply, so `offset_seconds` is 0 and `duration_seconds` is the clip's length. Replies that are silent or can't be decoded are listed under `skipped`.

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many agent replies were compared and `turns_with_events` how many were off. The score is the share that weren't.

## How Is It Calculated?

The `LoudnessConsistencyMetric` score is calculated according to the following equation:

<Equation formula="\text{Loudness Consistency} = \frac{\text{Number of Agent Replies Near the Typical Loudness}}{\text{Total Number of Agent Replies}}" />

Every reply is scored, however long, except one with no audible sound at all, which [Silent Reply](/docs/metrics-silent-reply) reports instead.

At least **3** replies are needed to tell which one is off. With fewer, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

### Shift criteria

    { start: 0.2, end: 4.8, lane: 0, label: "typical" },
  ]}
  marks={[
    { at: 6.2, lane: 0, tone: "bad", label: "much quieter" },
    { at: 8.7, lane: 0, tone: "ok", label: "close" },

/>

Each reply's speech level is the same one [Loudness](/docs/metrics-loudness) uses: the 90th percentile of its 20 ms frames at speech volume. The agent's typical level is the median across its replies, so one odd reply is flagged on its own instead of shifting what counts as typical.

| Check | Rule |
| --- | --- |
| Shift | The reply's speech level minus the typical level |
| Off | The shift is more than `max_shift_db` (5 dB) either way |

:::note
A 3 dB change is only just noticeable, and 5 dB is clearly noticeable.
:::

## FAQs

<FAQs
  qas={[
    {
      question: "How is this different from loudness?",
      answer: (
        <>
          <a href="/docs/metrics-loudness">LoudnessMetric</a> checks each reply
          against a fixed range. This metric checks replies against each other.
          A reply that is far too quiet next to normal ones can fail both.
        </>
      ),
    },
    {
      question: "How is this different from volume variance?",
      answer: (
        <>
          <a href="/docs/metrics-volume-variance">VolumeVarianceMetric</a>{" "}
          checks whether the volume drifts within one reply. This metric
          compares whole replies with each other.
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external speech model?",
      answer: (
        <>
          No. Detection is deterministic and runs locally over the audio, so it
          has no model or token cost.
        </>
      ),
    },
    {
      question: "Does it check the caller's audio too?",
      answer: (
        <>
          No. Only the agent's replies are scored. The caller's audio comes from
          your own TTS model, so a problem there is with the test harness, not
          the agent.
        </>
      ),
    },
  ]}
