The volume variance metric checks whether your voice agent's volume **drifts within a reply**, like a sentence that starts loud and fades to a mumble, or one that swells as it goes. It returns the share of agent replies that hold a steady volume, between 0 and 1.

<AudioSample name="volume-variance" />

## Required Arguments

To use the `VolumeVarianceMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `audio` on the agent's turns

## Usage

The `VolumeVarianceMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import VolumeVarianceMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = VolumeVarianceMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There is **ONE** optional parameter specific to the `VolumeVarianceMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `max_drift_db`: an integer for how far, in dB, a reply's volume may rise or fall from its start to its end. Must be greater than `0`. Defaulted to `15`.

### As a standalone

You can also run the `VolumeVarianceMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each reply whose volume drifted shows up in `score_breakdown`. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 3,
    "turns_with_events": 1,
    "events": [
        {
            "type": "volume_drift",
            "turn": 3,
            "timing_source": "turn_timestamps",
            "description": "Volume faded 17 dB during the reply",
            "drift_db": -17.2,
            "offset_seconds": 0.0,
            "duration_seconds": 7.0,
            "start_time": 12.5,
            "mark": "whole_reply",
        }
    ],
    "skipped": [
        {
            "turn": 5,
            "error": "Reply has under 6 seconds of speech to follow.",
        }
    ],
}
```

| Field | What it means |
| --- | --- |
| `drift_db` | How much the volume changed across the reply, in dB. Negative for a fade, positive for a swell |

Each event covers the whole reply, so `offset_seconds` is 0 and `duration_seconds` is the clip's length. Replies that are too short, silent or can't be decoded are listed under `skipped`.

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many agent replies were counted and `turns_with_events` how many drifted. The score is the share that didn't.

## How Is It Calculated?

The `VolumeVarianceMetric` score is calculated according to the following equation:

<Equation formula="\text{Volume Variance} = \frac{\text{Number of Agent Replies Without a Volume Drift}}{\text{Total Number of Agent Replies}}" />

### Which replies are scored

Each reply is cut into 1-second windows. A window is kept when it holds at least 0.3 seconds of speech (15 frames of 20 ms at about −41 dBFS or louder). A window with less, such as the tail of a word, and a last window under 1 second, are left out.

A reply is skipped when it:

- has fewer than 6 windows kept, since a fade needs several seconds to tell apart from speech moving up and down, or
- has no audible sound at all, which [Silent Reply](/docs/metrics-silent-reply) reports instead.

### Drift criteria

<VoiceDiagram
  duration={5}
  lanes={[
    { label: "Steady", role: "agent", sounds: [{ start: 0.1, end: 4.9, level: 0.7 }] },
    { label: "Fading", role: "agent", sounds: [{ start: 0.1, end: 1.0, level: 0.9 }, { start: 1.0, end: 2.0, level: 0.6 }, { start: 2.0, end: 3.0, level: 0.4 }, { start: 3.0, end: 4.0, level: 0.25 }, { start: 4.0, end: 4.9, level: 0.15 }] },
  ]}
  highlights={[
    { start: 0.1, end: 4.9, lane: 1 },
  ]}
  marks={[
    { at: 2.5, lane: 0, tone: "ok", label: "steady" },
    { at: 2.5, lane: 1, tone: "bad", label: "fades" },
  ]}
/>

| Check | Rule |
| --- | --- |
| Window level | The median of the window's 5 loudest 20 ms frames, so pauses don't pull it down |
| Steady trend | The window levels keep moving one way: their rank correlation with time is 0.8 or more, up or down. Otherwise the drift is 0 |
| Drift | The trend from the first kept window to the last, using the median slope between every pair of windows |
| Drifted | The drift is more than `max_drift_db` (15 dB) either way |

Speech rises and falls by 10 dB from one second to the next on its own, so only a volume that keeps fading or swelling through the reply is flagged. The median slope also ignores one odd window.

If no reply is long enough to follow, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

:::note
10 dB is roughly the step at which a voice sounds half, or twice, as loud. Listeners only minded fades past 15 dB.
:::

      question: "Does this metric call an LLM or an external speech model?",

        </>
      ),
    },
    {
      question: "Does it check the caller's audio too?",
      answer: (
        <>
          No. Only the agent's replies are scored. The caller's audio comes from
          your own TTS model, so a problem there is with the test harness, not
          the agent.
        </>
