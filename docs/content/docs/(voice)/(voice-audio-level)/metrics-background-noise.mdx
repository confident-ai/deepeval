The background noise metric checks whether your voice agent's speech has **a constant hiss, hum or room noise behind it**. It compares how loud the agent's speech is with the noise underneath it, and returns the share of agent replies where the speech stands well clear of the noise, between 0 and 1.

<AudioSample name="background-noise" />

## Required Arguments

To use the `BackgroundNoiseMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with:

- `audio` on the agent's turns

## Usage

The `BackgroundNoiseMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import BackgroundNoiseMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = BackgroundNoiseMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **THREE** optional parameters specific to the `BackgroundNoiseMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `min_snr_db`: an integer for the lowest signal-to-noise ratio, in dB, a reply may have before it counts as noisy. Must be `0` or more. Defaulted to `20`.
- [Optional] `eval_mode`: `"deterministic"` or `"hybrid"`. In `"hybrid"`, each noisy reply is [double-checked by an audio decision model](/docs/metrics-voice-introduction#second-check-with-an-audio-decision-model) before it counts. Defaulted to the configured voice eval mode (`"deterministic"` unless set).
- [Optional] `audio_decision_model`: the model that does the second check in `"hybrid"` mode. Defaulted to `HumeDecisionModel()`.

### As a standalone

You can also run the `BackgroundNoiseMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each noisy reply shows up in `score_breakdown`. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 3,
    "turns_with_events": 1,
    "events": [
        {
            "type": "background_noise",
            "turn": 3,
            "timing_source": "turn_timestamps",
            "description": "Background noise was high (SNR 13 dB)",
            "estimated_snr_db": 13.3,
            "offset_seconds": 0.0,
            "duration_seconds": 3.0,
            "start_time": 8.5,
            "mark": "whole_reply",
        }
    ],
    "skipped": [
        {
            "turn": 5,
            "error": "Reply is under 2 seconds, too short to measure its noise.",
        }
    ],
}
```

| Field | What it means |
| --- | --- |
| `estimated_snr_db` | How far the reply's speech sits above its background noise, in dB |

Each event covers the whole reply, so `offset_seconds` is 0 and `duration_seconds` is the clip's length. Replies that are too short, silent or can't be decoded are listed under `skipped`.

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many agent replies were counted and `turns_with_events` how many were noisy. The score is the share that weren't.

## How Is It Calculated?

The `BackgroundNoiseMetric` score is calculated according to the following equation:

<Equation formula="\text{Background Noise} = \frac{\text{Number of Agent Replies Without Background Noise}}{\text{Total Number of Agent Replies}}" />

A reply is skipped when it:

- is under 2 seconds long, since noise is measured in the pauses between words and a short reply rarely has one, or
- has no audible sound at all, which [Silent Reply](/docs/metrics-silent-reply) reports instead.

### Noise criteria

Speech should sit far above the noise in its pauses. A noisy reply has a raised floor between words.

Each reply is cut into 20 ms frames, and a reply is noisy when:

| Check | Rule |
| --- | --- |
| Speech level | The 90th percentile of frames at speech volume (about −41 dBFS or louder) |
| Noise level | The 10th percentile of all frames, leaving out digital silence |
| Noisy | Speech level is less than `min_snr_db` (20 dB) above the noise level |

If no reply is long enough, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

:::note
The default of 20 dB is 5 dB above the +15 dB speech-to-noise ratio that intelligibility guidance treats as the minimum for clear speech. Clean synthetic speech usually measures above 40 dB.
:::

### Second check

In the [hybrid eval mode](/docs/metrics-voice-introduction#choose-who-judges-with-eval-modes), each noisy reply is double-checked before it counts. The audio decision model hears the **agent's** whole reply, from that turn's own clip, and is asked:

> Is there distracting background noise behind the speaker?

If the model judges "no" more likely than "yes", the reply is dismissed and doesn't count against the score.
