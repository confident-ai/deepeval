The pitch consistency metric checks whether your voice agent **keeps the same voice from one reply to the next**, rather than sounding clearly deeper or higher in one of them. It returns the share of agent replies that stay close to the agent's typical pitch, between 0 and 1.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import PitchConsistencyMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = PitchConsistencyMetric(threshold=0.8, max_shift_semitones=4)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **SIX** optional parameters when creating a `PitchConsistencyMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `max_shift_semitones`: an integer for how far, in semitones, a reply's pitch may sit from the agent's typical pitch. Defaulted to `4`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the replies where the issue was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [
        {"type": "pitch_shift", "turn": 3, "pitch_median_hz": 212.4, "shift_semitones": 5.1}
    ],
    "skipped": [{"turn": 5, "error": "Reply has under 1s of voiced speech to follow its pitch."}],
}
```

`turn` is the turn's zero-based position in the conversation, `pitch_median_hz` is the reply's median pitch, and `shift_semitones` is how far that sits from the agent's typical pitch (negative when deeper). Agent replies whose audio could not be decoded, or that have under one second of voiced speech, are listed under `skipped`.

## How Is It Calculated?

`PitchConsistencyMetric` compares every agent reply with at least one second of voiced speech against the agent's typical reply, and scores the share that stay close:

<Equation formula="\text{Pitch Consistency} = \frac{\text{Agent replies within max\_shift\_semitones of the typical pitch}}{\text{Agent replies with one or more seconds of voiced speech}}" />

Each reply's pitch is the median of its 40 ms frames, tracked with the YIN method (de Cheveigné & Kawahara, 2002). The agent's typical pitch is the median across its replies, so a single odd reply is flagged on its own rather than dragging the reply after it down too. This needs at least **three** replies to tell which one is off; with fewer, the metric is skipped.

The default of **4 semitones** comes from 't Hart (1981): differences under about 3 semitones don't matter to listeners in conversation, and some can't tell differences under 4 apart.
