The speech intelligibility metric checks whether your voice agent is **easy to hear and make out**. It runs four single-issue voice metrics on the agent's replies and returns the share of replies none of them flagged, between 0 and 1.

## Required Arguments

To use the `SpeechIntelligibilityMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with `audio` on the agent's turns.

Read the [How Is It Calculated](#how-is-it-calculated) section below to learn how it's used.

## Usage

The `SpeechIntelligibilityMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import SpeechIntelligibilityMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks for the store's opening hours on a public holiday.",
    expected_outcome="The agent states the holiday opening hours.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = SpeechIntelligibilityMetric(threshold=0.7)
evaluate(test_cases=test_cases, metrics=[metric])
```

The `SpeechIntelligibilityMetric` takes only the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics). Its parts always run with their default limits. To change a limit, run that part on its own.

### As a standalone

You can also run the `SpeechIntelligibilityMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Every event a part raised shows up in `score_breakdown`, tagged with that part. Here is what the [example call](#example-call) returns:

```python

    "turns_with_events": 2,
    "events": [
        {
            "type": "background_noise",
            "turn": 3,
            "timing_source": "turn_timestamps",
            "description": "Background noise was high (SNR 11 dB)",
            "estimated_snr_db": 11.4,
            "metric": "Background Noise",
            "offset_seconds": 0.0,
            "duration_seconds": 3.0,
            "start_time": 10.5,
            "mark": "whole_reply",
        },
        {
            "type": "too_quiet",
            "turn": 5,
            "timing_source": "turn_timestamps",
            "description": "Reply was too quiet (-36 dBFS)",
            "speech_dbfs": -35.7,
            "metric": "Loudness",
            "offset_seconds": 0.0,
            "duration_seconds": 3.0,
            "start_time": 17.5,
            "mark": "whole_reply",
        },
    ],
    "skipped": [
        {"turn": 7, "error": "Reply is under 2 seconds, too short to measure its noise."},
    ],
    "metrics": {
        "Background Noise": {"score": 0.75, "eligible_turns": 4, "turns_with_events": 1},
        "Loudness": {"score": 0.8, "eligible_turns": 5, "turns_with_events": 1},
        "Audio Clipping": {"score": 1.0, "eligible_turns": 5, "turns_with_events": 0},
        "Audio Dropout": {"score": 1.0, "eligible_turns": 5, "turns_with_events": 0},
    },
}
```

| Field | What it means |
| --- | --- |
| `metric` | The part that raised the event. That part's page explains the event's other fields |
| `skipped` | Replies a part couldn't judge, one entry per part, so a reply can appear more than once |
| `metrics` | Each part's own score and counts. A part that couldn't judge any reply shows a `score` of `None` and a `reason` instead |

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`. There's no top-level `timing_source`, as only per-turn audio is read.

`eligible_turns` is how many agent replies at least one part judged and `turns_with_events` how many at least one part flagged. The score is the share that weren't flagged.

## How Is It Calculated?

The `SpeechIntelligibilityMetric` score is calculated according to the following equation:

<Equation formula="\text{Speech Intelligibility} = \frac{\text{Number of Agent Replies No Part Flagged}}{\text{Total Number of Agent Replies Judged}}" />

The metric only reads per-turn audio: each agent turn's own clip. Full call audio and the caller's turns are ignored.

### Parts

Each agent turn with audio is one reply. These four parts judge it, each with its default limits:

| Part | Flags a reply that | Judges a reply with |
| --- | --- | --- |
| [Background Noise](/docs/metrics-background-noise) | has speech under 20 dB above the noise | a clip of 2 seconds or more that isn't silent |
| [Loudness](/docs/metrics-loudness) | has speech under −32 or over −6 dBFS | a clip that isn't silent |
| [Audio Clipping](/docs/metrics-audio-clipping) | is distorted from being too loud | audio that decodes |
| [Audio Dropout](/docs/metrics-audio-dropout) | cuts out for a moment mid-speech | audio that decodes |

A reply with no audible sound at all isn't flagged here: Loudness and Background Noise skip it. [Silent Reply](/docs/metrics-silent-reply) catches it instead.

### Combining parts

- A reply counts if at least one part judged it.
- A reply is flagged if at least one part flagged it. Two parts flagging the same reply count once.
- A part that can't judge any reply, such as Background Noise when every reply is under 2 seconds, is left out.

If no part can judge any reply, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).
