The transcription accuracy metric checks whether your voice agent's **own speech-to-text heard the caller correctly**, as in the caller saying "Kavanagh" and the agent hearing "Cavanaugh". It returns the share of caller lines the agent heard faithfully, between 0 and 1. For a recorded call with no scripted caller, it can instead re-transcribe each turn's audio and check the call's transcript against it, for the caller and the agent.

:::note
This is the metric for an agent that answers sensibly but answers the wrong question. If the caller says one thing and the agent hears another, every reply after it can be coherent and wrong, and the transcript alone won't tell you why.
:::

## Required Arguments

To use the `TranscriptionAccuracyMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with `role` and `content` on every turn, and:

- `provider_transcript` on at least one agent turn that follows something the caller said, or
- `audio` on at least one turn, with `compare_against="audio"`

`provider_transcript` is what the agent's own speech-to-text reported hearing. Only [voice connectors](/docs/conversation-simulator-voice-connectors) that report it fill it in. A text conversation, or a phone call over SIP, never has one.

Read the [How Is It Calculated](#how-is-it-calculated) section below to learn how each is used.

## Usage

<include cwd>snippets/metrics/set-eval-mode.mdx</include>

The `TranscriptionAccuracyMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). There, `content` holds what the simulated caller was scripted to say and `provider_transcript` what the agent heard:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import TranscriptionAccuracyMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="A recruiter's voice agent screens a candidate for a backend role.",
    expected_outcome="The candidate states their name and their notice period.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = TranscriptionAccuracyMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

For a recorded call, cut the recording into one clip per turn, attach each as the turn's `audio` with its `start_time`, and set `compare_against="audio"`:

```python
from deepeval.metrics import TranscriptionAccuracyMetric
from deepeval.test_case import Audio, ConversationalTestCase, Turn

test_case = ConversationalTestCase(
    turns=[
        Turn(
            role="assistant",
            content="Are you able to start from January 2027?",
            audio=Audio(url="./turn-0.wav", start_time=12.0),
        ),
        Turn(
            role="user",
            content="",
            audio=Audio(url="./turn-1.wav", start_time=18.4),
        ),
    ]
)
metric = TranscriptionAccuracyMetric(compare_against="audio")
```

There are **SEVEN** optional parameters specific to the `TranscriptionAccuracyMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `model`: a string specifying which of OpenAI's GPT models to use, **OR** [any custom LLM model](/docs/metrics-introduction#configure-llm-judges) of type `DeepEvalBaseLLM`. Defaulted to <DefaultLLMModel />.
- [Optional] `system_one_model`: the Jev model to use, as a string or a `DeepEvalBaseSystemOneModel`. Only used in the `"hybrid"` and `"system_one"` eval modes. Defaulted to <DefaultSystemOneModel />.
- [Optional] `eval_mode`: `"llm"`, `"hybrid"` or `"system_one"`, choosing who judges, as in [Eval modes](#eval-modes). Defaulted to the configured [eval mode](/docs/evaluation-eval-modes) (`"llm"` unless set).
- [Optional] `use_llm`: a boolean which when set to `False`, counts misheard words instead of asking a judge, as in [Without an LLM](#without-an-llm). Passing `model`, `system_one_model` or `eval_mode` with it raises a `ValueError`. Defaulted to `True`.
- [Optional] `max_word_error_percent`: the most words in a line, in percent, that may be misheard before the line fails. Only accepted with `use_llm=False`, and must be 0 or more, or a `ValueError` is raised. Defaulted to `20`.
- [Optional] `compare_against`: `"content"` to check the agent's `provider_transcript` against the caller's `content`, or `"audio"` to check the call's transcript against each turn's re-transcribed `audio`. Defaulted to `"content"`.
- [Optional] `stt_model`: the speech-to-text model that re-transcribes each clip, as a string or a `DeepEvalBaseSTT`. Only accepted with `compare_against="audio"`, or a `ValueError` is raised. Defaulted to the configured [STT provider](/integrations/stt/openai), which is OpenAI's `gpt-4o-transcribe` unless set.

It also takes `async_mode`, a boolean which when set to `True`, enables [concurrent execution within the `measure()` method](/docs/metrics-introduction#using-metrics-async). Defaulted to `True`.

### As a standalone

You can also run the `TranscriptionAccuracyMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.verdicts)
```

See [Verdicts](#verdicts) for what `verdicts` and `score_breakdown` contain.

## How Is It Calculated?

The `TranscriptionAccuracyMetric` score is calculated according to the following equation:

<Equation formula="\text{Transcription Accuracy} = \frac{\text{Number of Exchanges Heard Faithfully}}{\text{Total Number of Exchanges}}" />

### Counting exchanges

Each turn with `audio`, caller or agent, is one exchange. The clip is re-transcribed by `stt_model`, and that is checked against the text the call ran on:

| Turn | Checked against |
| --- | --- |
| Agent | What it meant to say: `metadata["intended_content"]` if a duplex simulation recorded one, otherwise its `content` |
| Caller | Its own `provider_transcript`, else the next agent turn's `provider_transcript` if this turn is the caller's whole line, else its `content` |

For the agent, `content` must be the text sent to text-to-speech, not a transcription of the agent's audio, or agent-side noise can never fail. Turns without a clip are left out.

</Tab>
</Tabs>

The two modes count different things, so keep a metric on one `compare_against` when comparing runs.

If there's no exchange to judge, the metric raises a `MissingTestCaseParamsError` rather than scoring 0, so a call it can't measure is never mistaken for one the agent failed. That happens when:

- no turn has a `provider_transcript`, or none follows something the caller said, with `compare_against="content"`
- no turn has `audio`, with `compare_against="audio"`

In the `"system_one"` eval mode only the first `provider_transcript` check is made: Jev is sent an empty list of exchanges instead of the metric raising.

### Mishearing criteria

The judge doesn't count these as errors, because they are the same words written differently:

- punctuation, capitals and sentence splitting
- numbers written as digits or as words, as in "fifteen years" and "15 years"
- dropped filler words, such as "um" and "you know"
- the same words repeated twice, which some speech-to-text engines do

It does count these, because they change what the agent was told:

- a name or other proper noun heard as a different word, as in "Kavanagh" and "Cavanaugh"
- a number, date or duration with a different value, as in "two weeks" and "two months"
- a negation gained or lost, as in "I can't start" and "I can start"
- words missing or invented so the meaning changes
- an empty transcript when the caller spoke

With `compare_against="audio"`, two rules sharpen:

- An empty or near-empty transcript while the clip has the person making any sound, such as thinking out loud or a false start, is an error. The agent treated speech as silence.
- Speech or noise in the clip that the transcript doesn't account for is an error. On an agent turn, that's garbled words or noise after the sentence it meant to say.

A name spelled differently but pronounced the same, as in "Karthik" and "Kartik", isn't an error here, since a recording carries sound, not spelling. A failed verdict gives the clip's `start_time`, so the moment can be found in the recording.

### Eval modes

| Eval mode | Who gives each verdict | Score |
| --- | --- | --- |
| `"llm"` (default) | The LLM judge, from one prompt over all exchanges | Share of `"yes"` verdicts |
| `"hybrid"` | Jev, one yes/no question per exchange: P(yes) of 0.5 or more is `"yes"`. If Jev fails, the LLM decides instead | Share of `"yes"` verdicts |
| `"system_one"` | No verdicts. Jev judges the whole call in one request | Weighted mean of Jev's answers |

In the `"system_one"` eval mode, Jev is sent the exchanges and asked three questions:

| Question | Type | Weight |
| --- | --- | --- |
| In most exchanges, `transcribed` captures what was said in `spoken`, with only harmless differences | Noul | 1 |
| No exchange has a name, number, date or duration with a different value, a negation gained or lost, or an empty `transcribed` where the caller spoke | Noul | 1 |
| Across exchanges, how faithfully did `transcribed` capture what was said? (Mostly mis-heard → Every turn heard correctly) | Score | 2 |

With `compare_against="audio"`, the questions cover the caller and the agent, and the second also fails on an empty transcript where the clip has the person making a sound, or on sounds the transcript doesn't account for.

:::note
The two Noul questions are all-or-nothing, so a call with any meaning-changing error scores lower in `"system_one"` than the share of exchanges would suggest.
:::

### Without an LLM

With `use_llm=False`, no judge decides. Each exchange is a line, scored by its word error rate: the words swapped, missing or added in the transcript, divided by the words actually spoken.

| Check | Rule |
| --- | --- |
| Line passes | At most `max_word_error_percent` of its words misheard, 20% by default |
| Not counted as errors | Capitals, punctuation, curly or straight apostrophes, the fillers "um", "uh", "er", "ah", "hmm" and "mm", and a phrase of two or more words said twice in a row |
| Numbers | Number words become digits first, so "one hundred and five" matches "105", "1,000" matches "1000" and "five five five" matches "555" |
| Left out | A line with no spoken words after the above. If every line is left out, the score is 1 |

Every other difference is one misheard word, whether it's a dropped "the" or a wrong surname. "fifteenth" and "15th" don't match, since only plain number words are read. Use the LLM judge when only meaning-changing errors should fail.

With `compare_against="content"` this makes no model call at all. With `compare_against="audio"` the clips are still re-transcribed, so only the speech-to-text is billed.

:::note
With the LLM judge, a verdict that isn't `"yes"` or `"no"` is dropped. If none are left, the score is 1.
:::
