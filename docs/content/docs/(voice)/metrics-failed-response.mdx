The failed response metric checks whether your voice agent **answered every caller line that needed an answer**, rather than letting the call end, or replying with nothing, after the caller spoke. It returns the share of caller lines that got a reply, between 0 and 1.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import FailedResponseMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = FailedResponseMetric(threshold=1.0)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **FIVE** optional parameters when creating a `FailedResponseMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the caller lines that went unanswered:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [{"type": "call_ended_without_reply", "turn": 7}],
    "skipped": [],
}
```

Unlike most voice metrics, `turn` here is the zero-based position of the **caller** line that went unanswered. An event's `type` is `call_ended_without_reply` when the call ended before the agent spoke again, or `empty_reply` when the agent's next turn had neither text nor audio; `reply_turn` then points to that empty turn.

## How Is It Calculated?

`FailedResponseMetric` checks every caller line that needed a reply, and scores the share the agent answered:

<Equation formula="\text{Failed Response} = \frac{\text{Caller lines followed by an agent reply}}{\text{Caller lines that needed a reply}}" />

A caller line needs a reply unless it closes the call, such as "thanks", "that's all" or "bye". Several caller lines in a row share the agent's next reply, so when the call ends after them, each of them counts as unanswered. A reply only has to exist; whether it was heard is checked by [`SilentReplyMetric`](/docs/metrics-silent-reply), and how long it took by [`ResponseLatencyMetric`](/docs/metrics-response-latency). When the agent hangs up right after a question, this metric and [`UnexpectedCallEndMetric`](/docs/metrics-unexpected-call-end) both fail: one reports the unanswered question, the other how the call ended. A conversation with no audio on any turn is not a voice call, so the metric is skipped.
