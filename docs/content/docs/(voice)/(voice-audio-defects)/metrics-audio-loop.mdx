The audio loop metric checks whether your voice agent's audio **gets stuck repeating** the same chunk, as in "Your order, your order, your order". It returns the share of agent replies with no loop, between 0 and 1.

<AudioSample name="audio-loop" />

## Required Arguments

To use the `AudioLoopMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with `audio` on the agent's turns.

With [per-turn audio](/docs/metrics-voice-introduction#per-turn-audio), an `Audio.start_time` on each clip is optional, and only used to place events on the call's clock.

## Usage

The `AudioLoopMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AudioLoopMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AudioLoopMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

The `AudioLoopMetric` has no optional parameters of its own. It takes only the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics).

### As a standalone

You can also run the `AudioLoopMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each loop shows up in `score_breakdown` as its own event. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [
        {
            "type": "audio_loop",
            "turn": 3,
            "offset_seconds": 1.25,
            "duration_seconds": 0.76,
            "start_time": 8.75,
            "mark": "range",
            "timing_source": "turn_timestamps",
            "description": "Audio repeated for 0.8s",
        }
    ],
    "skipped": [],
}
```

Loop events carry only the [fields all voice events share](/docs/metrics-voice-introduction#events). `offset_seconds` is where the first repeat starts, and `duration_seconds` covers every repeat after the original. Clips that can't be decoded are listed under `skipped`.

`eligible_turns` is how many agent replies were counted and `turns_with_events` how many had a loop. A reply with several loops counts once. The score is the share that had none.

## How Is It Calculated?

The `AudioLoopMetric` score is calculated according to the following equation:

<Equation formula="\text{Audio Loop} = \frac{\text{Number of Agent Replies Without a Loop}}{\text{Total Number of Agent Replies}}" />

Each agent clip that decodes is one reply. The caller's clips are never checked.

### Loop criteria

A loop is a chunk of audio that plays three or more times in a row. Matching is by how alike the sound is, not identical bytes, so a loop is still found after the audio is re-encoded on its way through the call.

<VoiceDiagram
  duration={6}
  lanes={[
    { label: "Caller", role: "caller" },
    { label: "Agent", role: "agent", sounds: [{ start: 0.3, end: 1.6 }, { start: 1.6, end: 2.4 }, { start: 2.4, end: 3.2 }, { start: 3.2, end: 4.0 }, { start: 4.0, end: 5.6 }] },
  ]}
  highlights={[
    { start: 2.4, end: 4.0, lane: 1 },
  ]}
  brackets={[
    { start: 1.6, end: 2.4, lane: 1, label: "chunk" },
    { start: 2.4, end: 4.0, lane: 1, tone: "bad", label: "repeats" },
  ]}
/>

| Check | Rule |
| --- | --- |
| Chunk length | 0.2 to 2 seconds, and no more than a third of the clip |
| Match | Each 40 ms of the chunk matches the same 40 ms one chunk later, at 0.9 correlation or more |
| Repeats | The match holds for at least two chunk lengths, so the chunk plays three times |
| Not a steady sound | The level inside the chunk varies by at least 3 dB |

Near-silent moments neither confirm nor break a match, so pauses inside a repeated phrase don't split it. A steady drone matches itself at every delay, which is why the last check is there; that's [Held Tone](/docs/metrics-held-tone)'s to judge.

If there's nothing to count, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

## FAQs

<FAQs
  qas={[
    {
      question: "Can natural speech be flagged as a loop?",
      answer: (
        <>
          Rarely. Speech doesn't repeat itself that closely, chunk after
          chunk, for that long. A replayed audio buffer does, even after
          re-encoding.
        </>
      ),
    },
    {
      question: "How is this different from echo?",
      answer: (
        <>
          A loop is the agent's own stream playing the same chunk again.{" "}
          <a href="/docs/metrics-echo">EchoMetric</a> looks for the agent's
          voice coming back on the caller's side of the call.
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external speech model?",
      answer: (
        <>
          No. Detection is deterministic and runs locally over the audio, so it
          has no model or token cost.
        </>
      ),
    },
    {
      question: "Does it check the caller's audio for loops too?",
      answer: (
        <>
          No. Only the agent's replies are scored. The caller's audio comes from
          your own TTS model, so a loop there is a problem with the test
          harness, not the agent.
        </>
      ),
    },
  ]}
