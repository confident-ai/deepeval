The audio loop metric checks whether your voice agent's audio **gets stuck repeating** the same chunk, as in "Your order, your order, your order". It returns the share of agent replies with no loop, between 0 and 1.

<AudioSample name="audio-loop" />

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AudioLoopMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AudioLoopMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **FIVE** optional parameters when creating an `AudioLoopMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the replies where the defect was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [{"type": "audio_loop", "turn": 3, "offset_seconds": 1.5, "duration_seconds": 0.75, "start_time": 12.0}],
    "skipped": [],
}
```

`turn` is the turn's zero-based position in the conversation. Each looped span is its own event: `offset_seconds` and `duration_seconds` cover the audio that played again inside the reply (every replayed copy after the first, as one span), and `start_time` places it on the call's clock (left out when the clip has no `Audio.start_time`). A reply with several looped spans still counts once toward the score. Agent replies whose audio could not be decoded are listed under `skipped` with the error.

## How Is It Calculated?

`AudioLoopMetric` checks every agent reply that has audio and scores the share of them without the defect:

<Equation formula="\text{Audio Loop} = \frac{\text{Agent replies without the defect}}{\text{Agent replies with decodable audio}}" />

A loop is found by similarity rather than identical bytes, so it still shows after the audio is re-encoded or resampled on its way through the call:

1. **Candidate loop lengths.** The reply is resampled to 8 kHz and its autocorrelation is computed. Lengths from **0.2 s to 2.0 s** whose normalised autocorrelation is **0.2 or more** are candidates, strongest first, and up to **five** distinct lengths are tried.
2. **Frame matching.** For each length, every 40 ms frame is compared with the frame one loop length later. A pair **matches** when their correlation is **0.9 or more**. Near-silent frames neither confirm nor break a run, so the pauses inside a replayed phrase do not split it.
3. **A loop.** A matching run must last at least **two loop lengths**, so the audio plays three times. The level across one loop length of the run must also vary by at least **3 dB**, so a steady held tone, which matches itself at every delay, is not reported as a loop (see [Held Tone](/docs/metrics-held-tone)).

Natural speech does not repeat itself closely for that long, so this catches a replayed buffer.

If no agent reply has decodable audio, the metric is skipped.

## FAQs

  qas={[
    {
      question: "Can natural speech be flagged as a loop?",
      answer: (
        <>
          Rarely. A loop needs a stretch of audio between 0.2 and 2 seconds
          long to match its next copy, frame by frame, for at least two loop
          lengths in a row, with the level rising and falling inside it. Real
          or synthesized speech does not repeat that closely; a replayed audio
          buffer does, even after re-encoding.
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external speech model?",
      answer: (
        <>
          No. Detection is deterministic and runs locally over the audio
          samples, so it has no model or token cost.
        </>
      ),
    },
    {
      question: "Does it check the simulated user's audio too?",
      answer: (
        <>
          No. Only assistant turns are inspected. The caller's audio is produced
          by your own TTS model, so defects there are a problem with the test
          harness rather than with the agent under test.
        </>
      ),
    },
  ]}
