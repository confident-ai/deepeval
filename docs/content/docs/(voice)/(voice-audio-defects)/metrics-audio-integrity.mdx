The audio integrity metric checks whether your voice agent's audio **arrived intact**. It runs five single-issue voice metrics for cut-off, looping, dropping, clipped or silent replies, and returns the share of agent replies none of them flagged, between 0 and 1.

:::note
This is a pipeline health check rather than a quality judgment. It catches the failures that make a call unusable — silence where a reply should be, a repeating buffer, a reply that stops mid-word — not whether the agent sounded good.
:::

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AudioIntegrityMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AudioIntegrityMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **SIX** optional parameters when creating an `AudioIntegrityMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `use_speech_detection`: a boolean which, when set to `True`, only counts the caller as talking when the sound on their channel is speech, so background noise is not mistaken for the caller. Only applies with a stereo `call_recording_path`, and is passed to the [Abrupt Cut-off](/docs/metrics-abrupt-cut-off) check. Defaulted to `True`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

Every voice metric records what it measured on `score_breakdown`. Read it after a standalone `measure()` call, or turn on `verbose_mode` to have it printed during an `evaluate()` run:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

For `AudioIntegrityMetric` the breakdown counts the replies, lists every issue found, and gives each part's own result:

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [
        {"type": "abrupt_cutoff", "turn": 3, "offset_seconds": 3.42, "duration_seconds": 0.02, "start_time": 13.92, "metric": "Abrupt Cut-off"},
        {"type": "audio_dropout", "turn": 3, "offset_seconds": 1.12, "duration_seconds": 0.08, "start_time": 11.62, "metric": "Audio Dropout"},
        {"type": "audio_dropout", "turn": 3, "offset_seconds": 2.9, "duration_seconds": 0.06, "start_time": 13.4, "metric": "Audio Dropout"},
    ],
    "skipped": [],
    "metrics": {
        "Abrupt Cut-off": {"score": 0.75, "eligible_turns": 4, "turns_with_events": 1},
        "Audio Loop": {"score": 1.0, "eligible_turns": 4, "turns_with_events": 0},
        "Audio Dropout": {"score": 0.75, "eligible_turns": 4, "turns_with_events": 1},
        "Audio Clipping": {"score": 1.0, "eligible_turns": 4, "turns_with_events": 0},
        "Silent Reply": {"score": 1.0, "eligible_turns": 4, "turns_with_events": 0},
    },
}
```

`eligible_turns` is how many agent replies were judged and `turns_with_events` how many had at least one issue. `events` holds each part's events unchanged, tagged with the `metric` that raised them; the part's own page explains its fields. `skipped` collects the replies a part could not judge. `metrics` gives each part's own `score`, `eligible_turns` and `turns_with_events`, or `{"score": None, "reason": ...}` when that part could not judge the call. The reason for the call above reads "1 of 4 agent replies had an issue: Abrupt Cut-off (1), Audio Dropout (1)."

When the call has no agent turns, or an agent turn's audio cannot be decoded, the breakdown is the critical failure instead:

```python
{
    "critical_failure": True,
    "events": [{"type": "audio_undecodable", "turn": 3, "reason": "Audio is not a decodable PCM WAV."}],
}
```

## How Is It Calculated?

`AudioIntegrityMetric` runs these single-issue metrics on the call, each with its default limits:

| Part                                           | Flags an agent reply that                       |
| ---------------------------------------------- | ----------------------------------------------- |
| [Abrupt Cut-off](/docs/metrics-abrupt-cut-off) | stops mid-sound instead of fading out.          |
| [Audio Loop](/docs/metrics-audio-loop)         | gets stuck repeating the same chunk of audio.   |
| [Audio Dropout](/docs/metrics-audio-dropout)   | cuts out for a fraction of a second mid-speech. |
| [Audio Clipping](/docs/metrics-audio-clipping) | is distorted from being too loud.               |
| [Silent Reply](/docs/metrics-silent-reply)     | has text but no audio, or audio with no audible sound. |

The score is the share of judged agent replies that none of the parts flagged:

<Equation formula="\text{Audio Integrity} = 1 - \frac{\text{Agent replies flagged by at least one part}}{\text{Agent replies judged}}" />

A reply flagged by two parts counts once, however many events it lists. A part that cannot judge the call at all is left out of the score, and if no part can judge it, the metric is skipped.

Two checks run before the parts and force the score to 0, with the reason "A critical failure occurred: ..." naming them:

| Event                    | Meaning                                                    |
| ------------------------ | ---------------------------------------------------------- |
| `assistant_turn_missing` | The conversation contains no agent turns at all.           |
| `audio_undecodable`      | An agent turn's audio could not be decoded. Carries the `turn` and a `reason`. |

Nothing else zeroes the score: a reply with no audio at all is one flagged reply, counted by Silent Reply.

With a stereo call recording (`call_recording_path`), cut-offs are read from the recording, and each one counts against the agent reply that started last before the cut. A cut before the test case's first agent reply, such as one in turns left out of the test case, is not counted. That needs `start_time` on every audio turn; without it, cut-offs are read from each reply's own audio. A reply that stops because the caller [barged in](/docs/conversation-simulator-voice-interruptions) is not counted as cut off.
