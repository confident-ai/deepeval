The audio integrity metric checks whether your voice agent's audio **arrived intact**: no reply cut off, looping, dropping out, clipped or silent. It rolls five single-issue metrics into one score, the share of agent replies none of them flagged, between 0 and 1.

:::note
This is a pipeline health check, not a quality judgment. It catches the failures that make a call unusable, not whether the agent sounded good.
:::

## Required Arguments

To use the `AudioIntegrityMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with `audio` on the agent's turns, and `content` on them so a reply with no audio can be counted.

Stereo `audio` on the test case is also used, but only by the cut-off part. See [Full call audio](#call-audio) below.

## Usage

The `AudioIntegrityMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AudioIntegrityMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AudioIntegrityMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There is **ONE** optional parameter specific to the `AudioIntegrityMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `use_speech_detection`: a boolean which when set to `True`, only counts the caller as talking when [speech is detected](/docs/metrics-voice-introduction#speech-detection) on their channel. Passed to the [Abrupt Cut-off](/docs/metrics-abrupt-cut-off) part, and only used with full call audio. Defaulted to `True`.

The metric doesn't take `eval_mode`. Its Abrupt Cut-off part follows the configured [voice eval mode](/docs/metrics-voice-introduction#choose-who-judges-with-eval-modes).

### As a standalone

You can also run the `AudioIntegrityMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

| `metric` | Which part raised the event |

When the call has no agent turns, or an agent turn's audio can't be decoded, the breakdown is a critical failure instead, and the score is 0:

```python
{
    "critical_failure": True,

        {"type": "audio_undecodable", "turn": 3, "reason": "Audio is not a decodable PCM WAV."}

```

| Field | What it means |
| --- | --- |
| `critical_failure` | Always True. The parts weren't run |
| `reason` | Why the turn's audio couldn't be decoded |

Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), where it has a place on the call.

`eligible_turns` is how many agent replies were counted and `turns_with_events` how many at least one part flagged. The score is the share no part flagged.

## How Is It Calculated?

The `AudioIntegrityMetric` score is calculated according to the following equation:

<Equation formula="\text{Audio Integrity} = \frac{\text{Number of Agent Replies No Part Flagged}}{\text{Total Number of Agent Replies}}" />

### Counting agent replies

The metric runs five single-issue metrics on the call, each with its default limits:

| Part | Flags an agent reply that |
| --- | --- |
| [Abrupt Cut-off](/docs/metrics-abrupt-cut-off) | Stops mid-sound instead of fading out |
| [Audio Loop](/docs/metrics-audio-loop) | Gets stuck repeating the same chunk |
| [Audio Dropout](/docs/metrics-audio-dropout) | Cuts out for a fraction of a second mid-speech |
| [Audio Clipping](/docs/metrics-audio-clipping) | Is distorted from being too loud |
| [Silent Reply](/docs/metrics-silent-reply) | Has text but no audio, or audio with no audible sound |

A reply counts if any part counted it, and is flagged if any part flagged it. So an agent turn with text and no audio counts, through Silent Reply. A reply flagged by two parts counts once. A part with nothing to judge is left out, and if no part has anything to judge, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

### Critical failures

Two checks run before the parts. Either one sets the score to 0, with the reason "A critical failure occurred: ..." naming it:

| Event | When |
| --- | --- |
| `assistant_turn_missing` | The call has no agent turns at all |
| `audio_undecodable` | An agent turn's audio can't be decoded |

Nothing else sets the score to 0. A reply with no audio is one flagged reply, counted by Silent Reply.

### Full call audio

Audio Loop, Audio Dropout, Audio Clipping and Silent Reply only read per-turn audio. Abrupt Cut-off reads stereo full call audio when the test case has it. Each cut-off it finds there counts against the agent turn that started last before the stop, so every audio turn needs an `Audio.start_time`. Without one on every turn, Abrupt Cut-off reads per-turn audio too. A cut before the test case's first agent turn is dropped, and a stop where the caller [barged in](/docs/conversation-simulator-voice-interruptions) isn't a cut-off.
