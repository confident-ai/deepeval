The audio glitch metric checks whether your voice agent's audio **carried sounds nobody meant to make**: a stuck tone, a stream that goes dead, a reply cut off mid-sound, or clipping. It rolls four single-issue metrics into one score, the share of agent replies none of them flagged, between 0 and 1.

:::note
A transcript can't show these failures. A buzzing tone after a sentence, or a stream that drops to digital silence mid-answer, leaves nothing for speech-to-text to write down. This metric reads the audio itself.
:::

## Required Arguments

To use the `AudioGlitchMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with `audio` on the agent's turns.

Stereo `audio` on the test case is also used, but only by the cut-off and dead stream parts. See [Full call audio](#call-audio) below.

## Usage

The `AudioGlitchMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AudioGlitchMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to confirm their start date.",
    expected_outcome="The agent reads back the date and asks a follow-up.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AudioGlitchMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **TWO** optional parameters specific to the `AudioGlitchMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `use_speech_detection`: a boolean which when set to `True`, only counts the caller as talking when [speech is detected](/docs/metrics-voice-introduction#speech-detection). Passed to the [Abrupt Cut-off](/docs/metrics-abrupt-cut-off) and [Dead Stream](/docs/metrics-dead-stream) parts. Defaulted to `True`.
- [Optional] `stt_model`: the speech-to-text model that transcribes the agent's audio around each dead stretch, as a string or a `DeepEvalBaseSTT`. Passed to the [Dead Stream](/docs/metrics-dead-stream) part, where a dead stretch after a finished sentence then isn't counted. Defaulted to `None`, which skips that check.

`model`, `async_mode` and `evaluation_template` are still accepted so older code keeps working, but they're ignored. The metric doesn't take `eval_mode`. Its Abrupt Cut-off part follows the configured [voice eval mode](/docs/metrics-voice-introduction#choose-who-judges-with-eval-modes).

### As a standalone

You can also run the `AudioGlitchMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## How Is It Calculated?

The `AudioGlitchMetric` score is calculated according to the following equation:

<Equation formula="\text{Audio Glitch} = \frac{\text{Number of Agent Replies No Part Flagged}}{\text{Total Number of Agent Replies}}" />

### Counting agent replies

The metric runs four single-issue metrics on the call, each with its default limits:

| Part | Flags an agent reply that |
| --- | --- |
| [Held Tone](/docs/metrics-held-tone) | Has a stuck tone or drone |
| [Dead Stream](/docs/metrics-dead-stream) | Goes dead partway through |
| [Abrupt Cut-off](/docs/metrics-abrupt-cut-off) | Stops mid-sound, including a stream cut the agent picked back up |
| [Audio Clipping](/docs/metrics-audio-clipping) | Is distorted from being too loud |

A reply counts if any part counted it, and is flagged if any part flagged it. A reply flagged by two parts counts once. A part with nothing to judge is left out, and if no part has anything to judge, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

### Full call audio

Held Tone, Dead Stream and Audio Clipping read per-turn audio, or replies cut from stereo full call audio when no turn has audio. Dead Stream also uses stereo full call audio, when the test case has it, to tell whether the caller was talking and for its `stt_model` check. Abrupt Cut-off reads stereo full call audio when the test case has it. Each cut-off it finds there counts against the agent turn that started last before the stop, so every audio turn needs an `Audio.start_time`. Without one on every turn, Abrupt Cut-off reads per-turn audio too. A cut before the test case's first agent turn is dropped.

## FAQs

  qas={[
    {
      question: "Why did my score change?",
      answer: (
        <>
          This metric used to judge every turn with audio, caller and agent
          alike, and had an LLM write its reason. It now rolls up the
          single-issue metrics above, judges only the agent's replies, and
          writes a fixed reason without an LLM.
        </>
      ),
    },
    {
      question: "How is this different from Audio Integrity?",
      answer: (
        <>
          Both run the cut-off and clipping checks.{" "}
          <a href="/docs/metrics-audio-integrity">AudioIntegrityMetric</a>{" "}
          adds loops, dropouts and silent replies, and scores 0 when agent
          audio can't be decoded. This metric adds held tones and dead stream,
          and skips undecodable audio instead.
        </>
      ),
    },
    {
      question: "What about words the transcript got wrong?",
      answer: (
        <>
          That's{" "}
          <a href="/docs/metrics-transcription-accuracy">
            TranscriptionAccuracyMetric
          </a>
          's job. Transcription accuracy covers "the words were wrong", this
          metric covers "the sound was wrong".
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external speech model?",
      answer: (
        <>
          No LLM. Every part runs locally over the audio. With full call audio and{" "}
          <code>use_speech_detection</code> on, the cut-off part runs the small
          Silero VAD model locally over the caller's channel, so there's no
          token cost. With an <code>stt_model</code>, the dead stream part
          transcribes the agent's audio around each dead stretch, and the cost
          is added to <code>evaluation_cost</code>.
        </>
      ),
    },
  ]}
