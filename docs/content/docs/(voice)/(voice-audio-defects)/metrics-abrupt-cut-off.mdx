The abrupt cut-off metric checks whether your voice agent's replies **stop mid-sound**, as in "Your balance is two hundred and" followed by nothing. It returns the share of agent replies that end cleanly, between 0 and 1.

<AudioSample name="abrupt-cut-off" />

## Required Arguments

To use the `AbruptCutoffMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with audio on at least one of:

- `audio` on the test case, a stereo recording of the whole call
- `audio` on the agent's turns

Read the [How Is It Calculated](#how-is-it-calculated) section below to learn how each is used.

## Usage

The `AbruptCutoffMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AbruptCutoffMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AbruptCutoffMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **THREE** optional parameters specific to the `AbruptCutoffMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `use_speech_detection`: a boolean which when set to `True`, only counts the caller as talking when [speech is detected](/docs/metrics-voice-introduction#speech-detection) on their channel, so background noise doesn't excuse a cut-off. Only used with call audio, since turn audio doesn't hear the caller. Defaulted to `True`.
- [Optional] `eval_mode`: `"deterministic"` or `"hybrid"`. In `"hybrid"`, each cut-off is [double-checked by an audio decision model](/docs/metrics-voice-introduction#second-check-with-an-audio-decision-model) before it counts. Defaulted to the configured voice eval mode (`"deterministic"` unless set).
- [Optional] `audio_decision_model`: the model that does the second check in `"hybrid"` mode. Defaulted to `HumeDecisionModel()`.

### As a standalone

You can also run the `AbruptCutoffMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

`eligible_turns` is how many agent replies were counted and `turns_with_events` how many were cut off. The score is the share that weren't.

## How Is It Calculated?

The `AbruptCutoffMetric` score is calculated according to the following equation:

<Equation formula="\text{Abrupt Cut-off} = \frac{\text{Number of Agent Replies Without a Cut-off}}{\text{Total Number of Agent Replies}}" />

The metric reads [call audio or turn audio](/docs/metrics-voice-introduction#call-audio-vs-turn-audio), and the two count replies and check stops differently, as below. A reply counts as cut off at most once, however many times its sound stops.

### Cut-off criteria

A finished reply fades out. A cut one stops at near full volume.

<Tabs items={["Call audio", "Turn audio"]}>
<Tab value="Call audio">

<VoiceDiagram
  duration={8}
  lanes={[
    { label: "Caller", role: "caller", sounds: [{ start: 0.2, end: 1.6 }] },
    { label: "Agent", role: "agent", sounds: [{ start: 2.0, end: 4.4, ending: "fade" }, { start: 5.4, end: 7.4, ending: "cut" }] },
  ]}
  marks={[
    { at: 4.4, lane: 1, tone: "ok", label: "fades out" },
    { at: 7.4, lane: 1, tone: "bad", label: "stops at full volume" },
  ]}
/>

Every point where the agent's sound stops is checked. A reply is flagged if any stop is a cut-off, except a stop where:

- the caller made 0.2 seconds or more of sound from 1 second before it to 0.2 seconds after, or
- the call audio ends within 0.05 seconds, which [Unexpected Call End](/docs/metrics-unexpected-call-end) judges instead.

</Tab>
<Tab value="Turn audio">

<VoiceDiagram
  duration={8}
  lanes={[
    { label: "Agent", role: "agent", clips: [{ start: 0.3, end: 3.4, label: "turn 0" }, { start: 4.4, end: 7.4, label: "turn 2" }], sounds: [{ start: 0.4, end: 3.2, ending: "fade" }, { start: 4.5, end: 7.0, ending: "cut" }] },
  ]}
  marks={[
    { at: 3.2, lane: 0, tone: "ok", label: "fades out" },
    { at: 7.0, lane: 0, tone: "bad", label: "stops at full volume" },
  ]}
/>

Only the end of each clip is checked. A clip is also flagged as a **stream cut** if it ends mid-sound or in 1 second or more of digital silence, and the agent's own next clip starts within 15 seconds. Clips with `interrupted=True` are never flagged.

</Tab>
</Tabs>

A stop is a cut-off when the last 20 ms of sound before it are:

| Check | Rule |
| --- | --- |
| Still at speech volume | At least 80% of the median level of the second before |
| Above the background | More than 10 dB above the background noise. With turn audio, only checked on clips of 2 seconds or more |
| Not quiet residue | Above about −30 dBFS |

If there's nothing to count, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

:::note
A stop between two words sounds like a normal ending, so it isn't flagged.
:::

### Second check

In the [hybrid eval mode](/docs/metrics-voice-introduction#choose-who-judges-with-eval-modes), each cut-off is double-checked before it counts. The audio decision model hears about 5 seconds of the agent's audio around it and is asked:

> Does the speaker's voice cut off abruptly, mid-word or mid-sentence?

If the model judges "no" more likely than "yes", the cut-off is dismissed and doesn't count against the score.

## FAQs

<FAQs
  qas={[
    {
      question: "Why isn't a reply the simulated caller interrupted flagged?",
      answer: (
        <>
          A successful{" "}
          <a href="/docs/conversation-simulator-voice-interruptions">barge-in</a>{" "}
          stops the agent mid-word on purpose. With turn audio, those turns
          carry <code>interrupted=True</code> and count as clean replies. With
          call audio, the caller is heard speaking up, so the stop is excused
          the same way.
        </>
      ),
    },
    {
      question: "Why is a cut that the agent picked up again not a dead stream?",
      answer: (
        <>
          The listener hears a reply that stops, so it is reported here once.{" "}
          <a href="/docs/metrics-dead-stream">DeadStreamMetric</a> only reports
          stretches of true silence inside a reply.
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external speech model?",
      answer: (
        <>
          Not by default. Detection is deterministic and runs locally over the
          audio, so it has no model or token cost. In the{" "}
          <code>"hybrid"</code> eval mode, each cut-off is also checked by an
          audio decision model, at one paid request per cut-off.
        </>
      ),
    },
    {
      question: "Does it check the caller's audio for cut-offs too?",
      answer: (
        <>
          No. Only the agent's replies are scored. The caller's audio comes from
          your own TTS model, so a cut-off there is a problem with the test
          harness, not the agent. With call audio, the caller's channel is only
          used to tell whether the caller spoke up when the agent stopped.
        </>
      ),
    },
  ]}
/>
