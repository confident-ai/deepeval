The abrupt cut-off metric checks whether your voice agent's replies **stop mid-sound**, as in "Your balance is two hundred and" followed by nothing. It returns the share of agent replies that end cleanly, between 0 and 1.

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AbruptCutoffMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AbruptCutoffMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **FIVE** optional parameters when creating an `AbruptCutoffMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the replies where the defect was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [{"type": "stream_cut", "turn": 3, "role": "assistant", "offset_seconds": 1.125, "duration_seconds": 0.0, "start_time": 11.625, "position": "end", "evidence": "abrupt_end", "gap_seconds": 0.5, "resumed_turn": 4}],
    "skipped": [],
    "timing_source": "turn_timestamps",
}
```

`turn` is the turn's zero-based position in the conversation. A reply that ends mid-sound and is picked up again by the agent within 15 seconds (its next clip in the call, which needs `Audio.start_time` on every clip) is reported as a `stream_cut`, with `gap_seconds` and the `resumed_turn`. Any other reply that ends mid-sound is reported as `{"type": "abrupt_cutoff", "turn": 3, "offset_seconds": 3.42, "duration_seconds": 0.02, "start_time": 13.92}`, which places the last 20 ms before the sound stops inside the reply and on the call's clock (`start_time` is left out when the clip has no `Audio.start_time`). Agent replies whose audio could not be decoded are listed under `skipped` with the error. With a call recording, events read `{"type": "abrupt_cutoff", "duration_seconds": 0.02, "start_time": 44.84, "reply_start": 41.2, "stopped_at_seconds": 44.86}`: `reply_start` is where in the recording the reply started, `stopped_at_seconds` where its sound stopped, and `start_time` and `duration_seconds` the last 20 ms before that, all in seconds on the call's clock. `eligible_turns` then counts the agent's replies on the recording and `skipped` is always empty. `timing_source` says whether the call recording (`"call_recording"`) or each turn's own audio (`"turn_timestamps"`) was used.

## How Is It Calculated?

`AbruptCutoffMetric` checks every agent reply that has audio and scores the share of them without the defect:

<Equation formula="\text{Abrupt Cut-off} = \frac{\text{Agent replies without the defect}}{\text{Agent replies with decodable audio}}" />

A reply is cut off when its sound **stops at near full volume**: the last 20 ms of sound are at least 80% as loud as the speech in the second before them (its median level), and stand more than 10 dB above the background noise and above a fixed floor of about −30 dBFS. Where the sound stops is found on a 5 ms grid. A finished reply fades out; a cut one does not. Only cuts in the middle of a sound can be heard this way: an agent that stops between two words sounds like a normal ending.

With a stereo call recording (`call_recording_path`, caller on the left channel, agent on the right), each stretch of the agent's speech is one reply (pauses shorter than 1 second do not split it), and every point where its sound stops is checked. A stop only counts while the caller is silent, with under 0.2 seconds of caller sound from one second before it to 0.2 seconds after: an agent that stops because the caller spoke up was not cut off. A stop within 0.05 seconds of the end of the recording (sound still going when the recording ends) is left to [`UnexpectedCallEndMetric`](/docs/metrics-unexpected-call-end).

Without a recording, each agent turn's own audio is checked. Replies the simulated caller [barged into](/docs/conversation-simulator-voice-interruptions) (`interrupted=True` on the turn) are never counted: stopping mid-word is exactly what a successful interruption should cause.

If no agent reply has decodable audio, or the agent made no sound on the call recording, the metric is skipped.
