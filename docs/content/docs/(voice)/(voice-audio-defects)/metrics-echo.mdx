The echo metric checks whether your voice agent's audio carries **a fainter, delayed copy of itself**, as when the agent's own voice bleeds back through a microphone or echo cancellation fails. It returns the share of agent replies with no echo, between 0 and 1.

<AudioSample name="echo" />

## Usage

Voice metrics evaluate calls produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode). Start with one `ConversationalGolden`, simulate one call, then hand what it returns to `evaluate()`:

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import EchoMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = EchoMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **FIVE** optional parameters when creating an `EchoMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the replies where the defect was found:

```python
metric.measure(test_cases[0])

print(metric.score)  # e.g. 0.75
print(metric.score_breakdown)
```

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [{"type": "echo", "turn": 3, "delay_seconds": 0.18, "strength": 0.0312, "offset_seconds": 0.0, "duration_seconds": 4.2, "start_time": 10.5}],
    "skipped": [],
}
```

`turn` is the turn's zero-based position in the conversation. `delay_seconds` is how far behind the original the echo plays, and `strength` is how clearly it stands out (higher is a louder echo). The event covers the whole reply: `offset_seconds` is 0, `duration_seconds` is the reply's length, and `start_time` is where the reply starts on the call's clock (left out when the clip has no `Audio.start_time`). Agent replies whose audio could not be decoded are listed under `skipped` with the error.

## How Is It Calculated?

`EchoMetric` checks every agent reply that has audio and scores the share of them without the defect:

<Equation formula="\text{Echo} = \frac{\text{Agent replies without the defect}}{\text{Agent replies with decodable audio}}" />

An echo makes the reply look like itself shifted in time. The metric compares each reply with delayed versions of itself, from **60 ms to 500 ms** behind, after flattening the reply's frequency balance so that the ordinary similarity of speech to itself does not count. A reply has an echo when one delay stands out with a strength of **0.015 or more**.

On real agent speech, clean replies stay below 0.01, and an echo at 20% of the reply's loudness or more (about −14 dB) scores above 0.017. Fainter echoes are hard to hear and are not reported.

A reply that also loops is left to [Audio Loop](/docs/metrics-audio-loop): a replayed buffer repeats at a fixed delay too, and is reported there once.

If no agent reply has decodable audio, the metric is skipped.

      question: "Will room reverb be reported as an echo?",
      answer: (
        <>
          Usually not. Reverb arrives within a few tens of milliseconds and
          blurs into the voice, while this metric looks for a distinct copy 60
          to 500 ms later.
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external speech model?",
      answer: (
        <>
          No. Detection is deterministic and runs locally over the audio
          samples, so it has no model or token cost.
        </>
      ),
    },
    {
      question: "Does it check the simulated user's audio too?",
      answer: (
        <>
          No. Only assistant turns are inspected. The caller's audio is produced

          harness rather than with the agent under test.
