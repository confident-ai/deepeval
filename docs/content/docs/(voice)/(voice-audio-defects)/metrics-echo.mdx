The echo metric checks whether **the agent's own voice comes back through the caller's side of the call**, as when the caller's speaker is loud enough for their microphone to pick the agent up again. It returns the share of agent replies that were not heard back, between 0 and 1.

<AudioSample name="echo" />

## Usage

Echo reads a stereo recording of the whole call, with the caller on the left channel and the agent on the right. For a real call, attach yours as `call_recording_path`:

```python
from deepeval.metrics import EchoMetric
from deepeval.test_case import ConversationalTestCase, Turn

test_case = ConversationalTestCase(
    turns=[
        Turn(role="assistant", content="Hi, thanks for calling. How can I help?"),
        Turn(role="user", content="I'd like to check on an order."),
    ],
    call_recording_path="call.wav",
)

metric = EchoMetric(threshold=0.8)
metric.measure(test_case)
```

The [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode) writes the same recording when `record_call=True`. A simulated caller never plays the agent's voice back, so simulated calls are expected to pass.

There are **FIVE** optional parameters when creating an `EchoMetric`:

- [Optional] `threshold`: a number representing the minimum passing score. Set it to `None` to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [Optional] `include_reason`: a boolean which, when set to `True`, includes a summary of the evaluation score. Defaulted to `True`.
- [Optional] `strict_mode`: a boolean which, when set to `True`, requires a perfect score. Any score below 1 becomes 0, and the threshold is set to 1. Defaulted to `False`.
- [Optional] `verbose_mode`: a boolean which, when set to `True`, includes the score breakdown in verbose metric logs. Defaulted to `False`.
- [Optional] `flaky`: a boolean which, when set to `True`, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`.

`score_breakdown` lists the replies that came back:

```python
print(metric.score)  # e.g. 0.9
print(metric.score_breakdown)
```

```python
{
    "eligible_turns": 10,
    "turns_with_events": 1,
    "events": [{"type": "echo", "start_time": 343.706, "duration_seconds": 4.1, "reply_start": 343.2, "delay_seconds": 0.506, "level_db": -5.8}],
    "skipped": [],
    "timing_source": "call_recording",
}
```

`reply_start` is where in the recording the agent's reply started. `delay_seconds` is how long after the agent its voice came back on the caller's side, and `level_db` is how loud that copy was compared with the agent (0 is as loud, −40 is barely audible). `start_time` and `duration_seconds` place the copy on the caller's side, in seconds on the call's clock.

## How Is It Calculated?

`EchoMetric` checks every stretch of the agent's speech lasting **2 seconds** or more and scores the share of them that did not come back:

<Equation formula="\text{Echo} = \frac{\text{Agent replies not heard back}}{\text{Agent replies of 2 seconds or more}}" />

For each reply, the metric looks for the same sound on the caller's channel up to 1.5 seconds later, comparing only the timing of the two signals so that the phone line and the room changing the sound does not matter. A reply came back when all three hold:

- **The match stands out.** Its correlation peak is at least 12 times the typical correlation, so background noise that happens to line up does not count.
- **It came back 0.3 to 0.6 seconds later**, the round trip from the agent out of the caller's speaker and into their microphone.
- **It was loud enough to hear**: the part of the caller's channel that matches the agent is no more than 40 dB below the agent.

These limits come from phone calls labelled by a human reviewer, where real leaks returned 0.37 to 0.51 seconds after the agent and copies more than 40 dB down were inaudible. A phone setup with a much longer round trip would need a wider delay range.

Without a stereo call recording the metric is skipped, as the leak is only visible on the caller's own channel.

      question: "Is this the agent's fault?",
      answer: (
        <>
          Not directly. The leak comes from the caller's speaker and microphone,
          but it still harms the call: the caller hears a delayed copy of the
          agent, and the agent's own speech detection can hear itself and stop
          or reply to its own words.
        </>

    {
      question: "Will background noise be reported as an echo?",
      answer: (
        <>
          Rarely. Noise has to repeat the agent's sound at a steady 0.3 to 0.6
          second delay and stand out clearly to count. Noise that happens to
          line up with the agent lands at random delays and is ignored.
        </>
      ),
    },
    {
      question: "How is this different from audio loop?",
      answer: (
        <>
          <a href="/docs/metrics-audio-loop">AudioLoopMetric</a> catches the
          same chunk of the agent's audio played again in the agent's own
          stream. Echo looks for the agent's voice arriving on the caller's
          side.
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external speech model?",
      answer: (
        <>
          No. Detection is deterministic and runs locally over the recording,
          so it has no model or token cost.
        </>
      ),
    },
