The dead stream metric checks whether your voice agent's audio **goes completely dead** partway through a reply: the stream drops to exact digital silence, not a pause with room noise. It returns the share of agent replies with no dead stretch, between 0 and 1.

<AudioSample name="dead-stream" />

## Required Arguments

To use the `DeadStreamMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with `audio` on the agent's turns.

The metric reads [per-turn audio](/docs/metrics-voice-introduction#full-call-audio-vs-per-turn-audio). If no turn has audio, it uses replies cut from stereo full call audio instead. Give every clip an `Audio.start_time` so a [stream cut](#dead-stream-criteria) can be told apart from a dead stream.

## Usage

The `DeadStreamMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import DeadStreamMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = DeadStreamMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

There are **TWO** optional parameters specific to the `DeadStreamMetric`, on top of the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics):

- [Optional] `use_speech_detection`: a boolean which when set to `True`, only counts the caller as talking when [speech is detected](/docs/metrics-voice-introduction#speech-detection), so background noise isn't mistaken for the caller speaking during a dead stretch. Defaulted to `True`.
- [Optional] `stt_model`: the speech-to-text model that transcribes the agent's audio around each dead stretch, as a string or a `DeepEvalBaseSTT`. When set, a dead stretch after a finished sentence isn't counted, as in [Dead stream criteria](#dead-stream-criteria). Only used with stereo full call audio and clips that have an `Audio.start_time`. Defaulted to `None`, which skips that check.

### As a standalone

You can also run the `DeadStreamMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each dead stretch shows up in `score_breakdown` as its own event. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 5,
    "turns_with_events": 1,
    "events": [
        {
            "type": "dead_stream",
            "turn": 5,
            "role": "assistant",
            "offset_seconds": 1.0,
            "duration_seconds": 0.7,
            "start_time": 13.8,
            "mark": "range",
            "timing_source": "turn_timestamps",
            "description": "Agent's audio went dead for 0.7s",
            "position": "middle",
            "runs_to_end": False,
        }
    ],
    "skipped": [],
}
```

| Field | What it means |
| --- | --- |
| `runs_to_end` | Always `False` here, since silence that runs to the end of the clip isn't counted |
| `position` | Whether the dead stretch is near the start, middle or end of the clip |

Clips that can't be decoded are listed under `skipped`. Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many agent replies were counted and `turns_with_events` how many went dead. The score is the share that didn't.

## How Is It Calculated?

The `DeadStreamMetric` score is calculated according to the following equation:

<Equation formula="\text{Dead Stream} = \frac{\text{Number of Agent Replies Without a Dead Stream}}{\text{Total Number of Agent Replies}}" />

### Dead stream criteria

A pause in a recorded voice keeps some room noise. A stream that drops leaves exact zeros.

<VoiceDiagram
  duration={10}
  lanes={[
    { label: "Agent", role: "agent", clips: [{ start: 0.2, end: 4.4, label: "turn 1" }, { start: 5.0, end: 7.8, label: "turn 2" }, { start: 8.2, end: 9.8, label: "turn 3" }], sounds: [{ start: 0.3, end: 1.6 }, { start: 1.6, end: 2.4, silent: true }, { start: 2.4, end: 4.3 }, { start: 5.1, end: 6.4 }, { start: 6.4, end: 7.8, silent: true }, { start: 8.3, end: 9.7 }] },
  ]}
  highlights={[
    { start: 1.6, end: 2.4, lane: 0 },
  ]}
  marks={[
    { at: 2.0, lane: 0, tone: "bad", label: "dead stream" },
    { at: 7.1, lane: 0, tone: "skip", label: "stream cut" },
  ]}
/>

A stretch of 20 ms frames where every sample is within 2 of zero is dead when it comes after the agent has started talking and is:

| Check | Rule |
| --- | --- |
| Mid-reply | At least 0.5 seconds, with sound after it in the clip |
| Caller not talking | The caller made less than 0.2 seconds of sound during it. An agent going quiet while the caller talks is listening, even when all the caller says is "yes". Only checked when the clip has an `Audio.start_time` |

Silence that runs to the end of a clip isn't counted here.

Exceptions:

- If the agent's typical pause, across all its clips in the call, is at least 20% exact zeros, its voice writes pauses as silence. Nothing is reported for it.
- A dead end of clip is a **stream cut** when the agent's own clip is next on the call, within 15 seconds. When [Abrupt Cut-off](/docs/metrics-abrupt-cut-off) reads per-turn audio, it reports it as a `stream_cut`. This needs `Audio.start_time` on every clip.
- With an `stt_model`, a dead stretch isn't counted when the agent's last word before it ends a sentence, with `.`, `?` or `!`. The agent paused after a finished sentence, such as to look something up or wait for an answer, rather than its audio dying. The metric transcribes about 4 seconds of the agent's audio before the stretch, and the span from there to 3 seconds after it, to read that word's punctuation. Speech that trails off, ending in `...` or `…`, still counts as unfinished.

If there's nothing to count, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).

## FAQs

<FAQs
  qas={[
    {
      question: "Why are silent pauses ignored for some voices?",
      answer: (
        <>
          Some synthetic voices write their pauses as exact zeros. When the
          agent's typical pause is at least 20% zeros, a dropped stream can't
          be told apart from a normal pause, so nothing is reported.
        </>
      ),
    },
    {
      question: "Why is a stream cut not counted here?",
      answer: (
        <>
          The listener hears a reply that stops and then picks up again, so
          it's reported once, by{" "}
          <a href="/docs/metrics-abrupt-cut-off">AbruptCutoffMetric</a>, rather
          than by both metrics.
        </>
      ),
    },
    {
      question: "Does this metric call an LLM or an external speech model?",
      answer: (
        <>
          Not by default. Detection is deterministic and runs locally over the
          audio, so it has no model or token cost. With an{" "}
          <code>stt_model</code>, the agent's audio around each dead stretch is
          transcribed, at up to two requests per stretch. The cost is added to{" "}
          <code>evaluation_cost</code>.
        </>
      ),
    },
    {
      question: "Does it check the caller's audio too?",
      answer: (
        <>
          No. Only the agent's replies are scored. The caller's audio comes from
          your own TTS model, so a dead stream there is a problem with the test
          harness, not the agent.
        </>
      ),
    },
  ]}
/>
