The audio clipping metric checks whether your voice agent's audio is **distorted from being too loud**, so the voice turns crackly and harsh on loud syllables. It returns the share of agent replies with no clipping, between 0 and 1.

<AudioSample name="audio-clipping" />

## Required Arguments

To use the `AudioClippingMetric`, you'll have to provide a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) with `audio` on the agent's turns.

With [per-turn audio](/docs/metrics-voice-introduction#per-turn-audio), an `Audio.start_time` on each clip is optional, and only used to place events on the call's clock.

## Usage

The `AudioClippingMetric()` can be used for [end-to-end](/docs/evaluation-end-to-end-multi-turn) evaluation of voice calls, such as ones produced by the [`ConversationSimulator` in voice mode](/docs/conversation-simulator-voice-mode):

```python
from deepeval import evaluate
from deepeval.dataset import ConversationalGolden
from deepeval.metrics import AudioClippingMetric
from deepeval.simulator import ConversationSimulator
from deepeval.voice import ElevenLabsConnector, VoiceConfig


golden = ConversationalGolden(
    scenario="The user asks the agent to look up an order by its number.",
    expected_outcome="The agent reads back the order status.",
)

simulator = ConversationSimulator(
    voice_config=VoiceConfig(
        connector=ElevenLabsConnector(agent_id="your-agent-id"),
    )
)
test_cases = simulator.simulate([golden])

metric = AudioClippingMetric(threshold=0.8)
evaluate(test_cases=test_cases, metrics=[metric])
```

The `AudioClippingMetric` has no optional parameters of its own. It takes only the [common voice metric parameters](/docs/metrics-voice-introduction#using-voice-metrics).

### As a standalone

You can also run the `AudioClippingMetric` on a single test case as a standalone, one-off execution:

```python
metric.measure(test_cases[0])

print(metric.score, metric.reason)
print(metric.score_breakdown)
```

See [Events](#events) for what `score_breakdown` contains.

## Events

Each clipped reply shows up in `score_breakdown` as one event. Here is what the [example call](#example-call) returns:

```python
{
    "eligible_turns": 4,
    "turns_with_events": 1,
    "events": [
        {
            "type": "clipping",
            "turn": 5,
            "role": "assistant",
            "offset_seconds": 0.048,
            "duration_seconds": 1.657,
            "start_time": 12.548,
            "mark": "range",
            "timing_source": "turn_timestamps",
            "description": "Audio was clipped",
            "position": "start",
            "fraction": 0.0836,
        }
    ],
    "skipped": [],
}
```

| Field | What it means |
| --- | --- |
| `offset_seconds` | Where the first clipped sample is, in seconds from the start of the clip |
| `duration_seconds` | From the first clipped sample to the last |
| `fraction` | The share of the clip's samples that were clipped |
| `position` | Whether the clipped stretch starts near the start, middle or end of the clip |

Clips that can't be decoded are listed under `skipped`. Every event also has the [fields all voice events share](/docs/metrics-voice-introduction#events), such as `mark` and `description`.

`eligible_turns` is how many agent replies were counted and `turns_with_events` how many were clipped. The score is the share that weren't.

## How Is It Calculated?

The `AudioClippingMetric` score is calculated according to the following equation:

<Equation formula="\text{Audio Clipping} = \frac{\text{Number of Agent Replies Without Clipping}}{\text{Total Number of Agent Replies}}" />

Each agent clip that decodes is one reply. The caller's clips are never checked.

### Clipping criteria

Audio that's too loud hits the top of what a 16-bit sample can hold, and gets flattened there.

<VoiceDiagram
  duration={8}
  lanes={[
    { label: "Caller", role: "caller" },
    { label: "Agent", role: "agent", sounds: [{ start: 0.3, end: 3.6, level: 0.8 }, { start: 4.4, end: 7.6, level: 1, ending: "flat" }] },
  ]}
  highlights={[
    { start: 4.4, end: 7.6, lane: 1 },
  ]}
  marks={[
    { at: 2.0, lane: 1, tone: "ok", label: "loud" },
    { at: 6.0, lane: 1, tone: "bad", label: "clipped" },
  ]}
/>

A reply is clipped when:

| Check | Rule |
| --- | --- |
| Clipped sample | 32,000 or more, either way from zero, near the 32,767 a 16-bit sample can hold |
| Share of the clip | More than 0.1% of its samples are clipped |

Reviewers heard clipping when as little as 0.1% of a reply's samples sat near full scale, so light clipping counts. A few clipped samples on one loud syllable don't. If there's nothing to count, the metric is [skipped](/docs/metrics-voice-introduction#when-a-metric-is-skipped).
