The conversational tool correctness metric is a deterministic multi-turn agentic metric. It checks whether your AI agent called the tools it was expected to call over the course of a conversation. It collects every tool the assistant called, across all turns and in order, and compares that list with the test case's <Term py="expected_tools" ts="expectedTools"/> using the [tool correctness](/docs/metrics-tool-correctness) rules. You can also pin an expected tool to a specific turn. No LLM is used.

:::note
Use this metric when you know which tools a conversation should end up calling (for example, `track_parcel` and then `transfer_to_human` for a user who asks about a late parcel and then for a person). Because expected tools are set on the whole conversation rather than on individual turns, they work for [simulated conversations](/docs/conversation-simulator), whose turns aren't known in advance. If you don't have expected tools and want an LLM to judge tool selection and arguments instead, use the [tool use metric](/docs/metrics-tool-use).
:::

## Required Arguments

To use the `ConversationalToolCorrectnessMetric`, you'll have to provide the following arguments when creating a [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases):

- `turns`, where assistant turns that called tools set <Term py="tools_called" ts="toolsCalled"/>
- <Term py="expected_tools" ts="expectedTools"/>, the tools the assistant should call over the whole conversation. An empty list means no tools should be called.

To require a tool on a specific turn, set `turn` on its `ToolCall` in <Term py="expected_tools" ts="expectedTools"/>. `turn` is the index in `turns` (starting at 0) of the assistant turn that should make the call. It must point at an assistant turn, or the metric raises an error. Pinning only works when the turns are known in advance, so leave `turn` unset for simulated conversations.

You can also set <Term py="expected_tools" ts="expectedTools"/> on a `ConversationalGolden`. It's copied onto the test case each golden produces, including simulated ones.

## Usage

<Switch>

<Case id="python">

```python
from deepeval import evaluate
from deepeval.metrics import ConversationalToolCorrectnessMetric
from deepeval.test_case import ConversationalTestCase, ToolCall, ToolCallParams, Turn

test_case = ConversationalTestCase(
    turns=[
        Turn(role="user", content="Where is parcel 8670940983?"),
        Turn(
            role="assistant",
            content="It's out for delivery today.",
            tools_called=[ToolCall(name="track_parcel", input_parameters={"pin": "8670940983"})],
        ),
        Turn(role="user", content="Can I talk to a person?"),
        Turn(role="assistant", content="Sure, one moment."),
    ],
    expected_tools=[
        ToolCall(name="track_parcel", input_parameters={"pin": "8670940983"}),
        # Must be called on turns[3], the second assistant reply
        ToolCall(name="transfer_to_human", turn=3),
    ],
)
metric = ConversationalToolCorrectnessMetric(
    threshold=0.5,
    evaluation_params=[ToolCallParams.INPUT_PARAMETERS],
)

# To run metric as a standalone
# metric.measure(test_case)
# print(metric.score, metric.reason)

evaluate(test_cases=[test_case], metrics=[metric])
```

```typescript
import { evaluate } from "deepeval";
import { ConversationalToolCorrectnessMetric } from "deepeval/metrics";
import { ConversationalTestCase, ToolCall, ToolCallParams, Turn } from "deepeval/test-case";

const testCase = new ConversationalTestCase({
  turns: [
    new Turn({ role: "user", content: "Where is parcel 8670940983?" }),
    new Turn({
      role: "assistant",
      content: "It's out for delivery today.",
      toolsCalled: [new ToolCall({ name: "track_parcel", inputParameters: { pin: "8670940983" } })],
    }),
    new Turn({ role: "user", content: "Can I talk to a person?" }),
    new Turn({ role: "assistant", content: "Sure, one moment." }),
  ],
  expectedTools: [
    new ToolCall({ name: "track_parcel", inputParameters: { pin: "8670940983" } }),
    // Must be called on turns[3], the second assistant reply
    new ToolCall({ name: "transfer_to_human", turn: 3 }),
  ],
});
const metric = new ConversationalToolCorrectnessMetric({
  threshold: 0.5,
  evaluationParams: [ToolCallParams.INPUT_PARAMETERS],
});

await evaluate({ testCases: [testCase], metrics: [metric] });
```

There are **SIX** optional parameters when creating a `ConversationalToolCorrectnessMetric`:

- [Optional] `threshold`: a float representing the minimum passing threshold, defaulted to 0.5.
- [Optional] <Term py="evaluation_params" ts="evaluationParams"/>: a list of `ToolCallParams` to compare besides the tool name. `INPUT_PARAMETERS` also compares arguments, `OUTPUT` also compares outputs. Defaulted to `[]`.
- [Optional] <Term py="should_exact_match" ts="shouldExactMatch"/>: a boolean which, when `true`, requires the tools called across the conversation to match the expected tools exactly (same tools, same count, same order). Defaulted to `false`.
- [Optional] <Term py="should_consider_ordering" ts="shouldConsiderOrdering"/>: a boolean which, when `true`, requires the expected tools to be called in order across the conversation. Defaulted to `false`.
- [Optional] <Term py="include_reason" ts="includeReason"/>: a boolean which when set to `true`, will include a reason naming the expected tools that weren't called. Defaulted to `true`.
- [Optional] <Term py="strict_mode" ts="strictMode"/>: a boolean which when set to `true`, enforces a binary metric score: 1 for perfection, 0 otherwise. It also overrides the current threshold and sets it to 1. Defaulted to `false`.

## How Is It Calculated?

The metric splits <Term py="expected_tools" ts="expectedTools"/> into checks and scores each one with the same rules as the [tool correctness metric](/docs/metrics-tool-correctness#how-is-it-calculated):

- **One check per pinned turn.** The tools pinned to a turn are compared with that turn's own <Term py="tools_called" ts="toolsCalled"/>.
- **One check for everything else.** The expected tools without `turn` are compared with the <Term py="tools_called" ts="toolsCalled"/> of every other assistant turn, in turn order. Turns that have pinned tools are left out of this check, so their calls don't count as extra calls. If nothing is pinned, this check covers the whole conversation.

Tools on user turns are ignored. The final score is the mean of the checks:

<Equation formula="\text{Conversational Tool Correctness} = \frac{\sum \text{Check Scores}}{\text{Number of Checks}}" />

In the example above, `track_parcel` is checked across the conversation and `transfer_to_human` on turn 3. The agent never transfers, so the turn 3 check scores 0, the other check scores 1, and the final score is 0.5.

With <Term py="should_consider_ordering" ts="shouldConsiderOrdering"/> or <Term py="should_exact_match" ts="shouldExactMatch"/>, order is judged within each check. For unpinned tools that's across the conversation, so calling `transfer_to_human` before `track_parcel` lowers the score. Exact match fails whenever the agent repeats a call, which is common in conversations, so most conversations are better served by the default or by ordering.

Each check's score and reason is available on <Term py="metric.group_scores" ts="metric.groupScores"/>, and every tool the assistant called is on <Term py="metric.tools_called" ts="metric.toolsCalled"/>.
