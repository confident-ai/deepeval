[OpenAI](https://platform.openai.com/docs/) provides chat completions and responses APIs for building LLM applications.

The `deepeval` integration instruments OpenAI's client in place. Every `client.chat.completions.create(...)` and `client.responses.create(...)` call becomes an LLM span you can evaluate, without rewriting how you call the API.

`deepeval`'s OpenAI integration enables you to:

- <Switch><Case id="python">**Drop in `deepeval.openai.OpenAI`** — every chat completion or response produces an LLM span with input, output, and `tools_called` captured automatically.</Case><Case id="typescript">**Patch your client with `instrumentOpenAI(client)`** — every chat completion or response produces an LLM span with input, output, and `toolsCalled` captured automatically.</Case></Switch>
- **Evaluate LLM calls** with any `deepeval` metric through `LlmSpanContext`.
- **Run evals from scripts or CI/CD** — same client, different surfaces.
- **Compose with <Term py="@observe" ts="observe()"/> and <Term py="with trace(...)" ts="setTracingContext(...)"/>** to evaluate larger flows that wrap one or more OpenAI calls.

## Getting Started

<Steps>

<Step>

### Installation

<Switch>

<Case id="python">

```bash
pip install -U deepeval openai
```

`deepeval.openai.OpenAI` and `deepeval.openai.AsyncOpenAI` import OpenAI's classes and patch them in place. Existing kwargs, async paths, streaming, and tool-calling behavior all work unchanged.

</Case>

<Case id="typescript">

```bash
npm install -D deepeval openai
```

`instrumentOpenAI(client)` patches the client you hand it in place. Existing options, streaming, and tool-calling behavior all work unchanged.

</Case>

</Switch>

</Step>

<Step>

### Instrument and evaluate

<Switch>

<Case id="python">

Replace `from openai import OpenAI` with `from deepeval.openai import OpenAI`. Wrap each call you want to evaluate in `with trace(llm_span_context=LlmSpanContext(metrics=[...]))`.

```python title="openai_app.py" showLineNumbers
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.tracing import trace, LlmSpanContext
from deepeval.metrics import AnswerRelevancyMetric
from deepeval.openai import OpenAI

client = OpenAI()

# Goldens are the inputs you want to evaluate.
dataset = EvaluationDataset(goldens=[Golden(input="What's the capital of France?")])

for golden in dataset.evals_iterator():
    with trace(llm_span_context=LlmSpanContext(metrics=[AnswerRelevancyMetric()])):
        client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": "Be concise."},
                {"role": "user", "content": golden.input},
            ],
        )
```

</Case>

<Case id="typescript">

Call `instrumentOpenAI(client)` once on the client you already construct. Wrap each call you want to evaluate in `setTracingContext({ llmSpanContext: { metrics: [...] } }, ...)`.

```typescript title="openai-app.ts" showLineNumbers
import { OpenAI } from "openai";

import { EvaluationDataset, Golden } from "deepeval/dataset";
import { AnswerRelevancyMetric } from "deepeval/metrics";
import { setTracingContext } from "deepeval/tracing";
import { instrumentOpenAI } from "deepeval/openai";

const client = new OpenAI();
instrumentOpenAI(client);

export const respond = (prompt: string) =>
  setTracingContext(
    { llmSpanContext: { metrics: [new AnswerRelevancyMetric()] } },
    () =>
      client.chat.completions.create({
        model: "gpt-4o",
        messages: [
          { role: "system", content: "Be concise." },
          { role: "user", content: prompt },
        ],
      }),
  );

// Goldens are the inputs you want to evaluate.
const dataset = new EvaluationDataset({
  goldens: [new Golden({ input: "What's the capital of France?" })],
});

for await (const golden of dataset.evalsIterator()) {
  await respond((golden as Golden).input);
}
```

</Case>

</Switch>

Done ✅. You've run your first eval against an OpenAI call with full traceability via `deepeval`.

</Step>

</Steps>

<Only id="typescript">

:::caution[One client per process]
`instrumentOpenAI` patches the **first** client it is given and returns early on every later call, so a second client constructed elsewhere in your app stays untraced. Instrument the one client you share across your code.
:::

</Only>

## What gets traced

Each patched OpenAI call produces one **LLM span** under the active trace. When the call uses tool-calling, the span's <Term py="tools_called" ts="toolsCalled"/> field captures every tool invocation the model returned — no extra wiring needed.

- **LLM spans** — one per `chat.completions.create(...)`, `chat.completions.parse(...)`, or `responses.create(...)` call. Captures input messages, output text, token counts, and <Term py="tools_called" ts="toolsCalled"/>.
- **Trace** — auto-created when the call has no parent. If the call runs inside <Term py="with trace(...)" ts="setTracingContext(...)"/> or <Term py="@observe" ts="observe()"/>, the LLM span nests under that trace instead.

```text
Trace                          ← auto-created or user-owned
└── LLM: gpt-4o                ← one client.chat.completions.create(...) call
```

The trace and its LLM span are independently evaluable.

## Running evals

There are two surfaces for running evals against OpenAI calls. Pick by where you want results to surface — your terminal during development, or your CI pipeline as a pass/fail gate.

### In CI/CD

<Switch>

<Case id="python">

Use the `deepeval` pytest integration. Each parametrized test invocation becomes one OpenAI call; failing metrics fail the test, which fails the build.

```python title="test_openai_app.py" showLineNumbers
import pytest
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.tracing import trace, LlmSpanContext
from deepeval.metrics import AnswerRelevancyMetric
from deepeval.openai import OpenAI
from deepeval import assert_test

client = OpenAI()
dataset = EvaluationDataset(goldens=[
    Golden(input="What's the capital of France?"),
    Golden(input="Who wrote Hamlet?"),
])

@pytest.mark.parametrize("golden", dataset.goldens)
def test_openai_app(golden: Golden):
    with trace(llm_span_context=LlmSpanContext(metrics=[AnswerRelevancyMetric()])):
        client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": "Be concise."},
                {"role": "user", "content": golden.input},
            ],
        )
    assert_test(golden=golden)
```

Run it with:

```bash
deepeval test run test_openai_app.py
```

</Case>

<Case id="typescript">

Use the `toPass()` matcher. The golden is the subject; `task` produces the trace judged against it. A failing metric fails the test, which fails the build.

```typescript title="openai-app.test.ts" showLineNumbers
import { it, expect } from "vitest";
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { respond } from "./openai-app";
import "deepeval/vitest";

const dataset = new EvaluationDataset({
  goldens: [
    new Golden({ input: "What's the capital of France?" }),
    new Golden({ input: "Who wrote Hamlet?" }),
  ],
});

it.each(dataset.goldens as Golden[])("answers the question", async (golden) => {
  await expect(golden).toPass([], { task: (g) => respond(g.input) });
});
```

The matcher takes an empty metric array because `AnswerRelevancyMetric` is already staged on the LLM span inside `respond`.

Run it with:

```bash
npx deepeval test run openai-app.test.ts
```

</Case>

</Switch>

### In a script

Use `EvaluationDataset` + <Term py="evals_iterator" ts="evalsIterator"/>. Each `Golden` becomes one OpenAI call; metrics score the resulting LLM span.

<Switch>

<Case id="python">

```python title="openai_app.py" showLineNumbers
import asyncio

from deepeval.dataset import EvaluationDataset, Golden
from deepeval.tracing import trace, LlmSpanContext
from deepeval.metrics import AnswerRelevancyMetric
from deepeval.evaluate.configs import AsyncConfig
from deepeval.openai import AsyncOpenAI

client = AsyncOpenAI()
dataset = EvaluationDataset(goldens=[
    Golden(input="What's the capital of France?"),
    Golden(input="Who wrote Hamlet?"),
])

async def call_openai(prompt: str):
    with trace(llm_span_context=LlmSpanContext(metrics=[AnswerRelevancyMetric()])):
        return await client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
        )

for golden in dataset.evals_iterator(async_config=AsyncConfig(run_async=True)):
    task = asyncio.create_task(call_openai(golden.input))
    dataset.evaluate(task)
```

Sync (`OpenAI`) and async (`AsyncOpenAI`) clients both work; pick whichever matches your code.

</Case>

<Case id="typescript">

```typescript title="openai-app.ts" showLineNumbers
const dataset = new EvaluationDataset({
  goldens: [
    new Golden({ input: "What's the capital of France?" }),
    new Golden({ input: "Who wrote Hamlet?" }),
  ],
});

for await (const golden of dataset.evalsIterator()) {
  await respond((golden as Golden).input);
}
```

The OpenAI client is promise-based, so there is one code path rather than a sync and an async client.

</Case>

</Switch>

## Applying metrics to LLM spans

Passing `metrics` to `LlmSpanContext` evaluates the OpenAI call's LLM span specifically. The same context lets you attach extra evaluation parameters that some metrics need.

<Switch>

<Case id="python">

```python title="openai_app.py" showLineNumbers
from deepeval.metrics import AnswerRelevancyMetric, FaithfulnessMetric
from deepeval.tracing import trace, LlmSpanContext
from deepeval.openai import OpenAI

client = OpenAI()

with trace(
    llm_span_context=LlmSpanContext(
        metrics=[AnswerRelevancyMetric(), FaithfulnessMetric()],
        retrieval_context=["Paris is the capital of France."],
    ),
):
    client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": "What's the capital of France?"}],
    )
```

</Case>

<Case id="typescript">

```typescript title="openai-app.ts" showLineNumbers
import { AnswerRelevancyMetric, FaithfulnessMetric } from "deepeval/metrics";
import { setTracingContext } from "deepeval/tracing";
...

await setTracingContext(
  {
    llmSpanContext: {
      metrics: [new AnswerRelevancyMetric(), new FaithfulnessMetric()],
      retrievalContext: ["Paris is the capital of France."],
    },
  },
  () =>
    client.chat.completions.create({
      model: "gpt-4o",
      messages: [{ role: "user", content: "What's the capital of France?" }],
    }),
);
```

</Case>

</Switch>

`LlmSpanContext` accepts `metrics`, <Term py="expected_output" ts="expectedOutput"/>, <Term py="expected_tools" ts="expectedTools"/>, `context`, <Term py="retrieval_context" ts="retrievalContext"/>, and `prompt`. Each one is read by the OpenAI patch when the next LLM span is created.

<Only id="typescript">

A `LlmSpanContext` applies to **every** LLM span in its scope. To configure exactly one call, use `nextLlmSpan(...)` instead — it stages the same fields for the first LLM span opened inside the block and nothing after it.

```typescript title="openai-app.ts" showLineNumbers
import { AnswerRelevancyMetric } from "deepeval/metrics";
import { nextLlmSpan } from "deepeval/tracing";
...

await nextLlmSpan({ metrics: [new AnswerRelevancyMetric()] }, () =>
  client.chat.completions.create({
    model: "gpt-4o",
    messages: [{ role: "user", content: "What's the capital of France?" }],
  }),
);
```

</Only>

## Customizing trace and span data

The patch captures input messages, output text, and <Term py="tools_called" ts="toolsCalled"/> automatically. For anything else, the right API depends on where your code runs.

- Use <Term py="with trace(...)" ts="setTracingContext(...)"/> for trace-level fields (`name`, `tags`, `metadata`, <Term py="thread_id" ts="threadId"/>, <Term py="user_id" ts="userId"/>).
- Use `LlmSpanContext` for LLM-span-level fields the metric needs (<Term py="expected_output" ts="expectedOutput"/>, <Term py="retrieval_context" ts="retrievalContext"/>, etc.).
- Use <Term py="@observe" ts="observe()"/> to wrap retrieval, post-processing, or any other step you want to see as its own span in the trace.

<Switch>

<Case id="python">

```python title="openai_app.py" showLineNumbers
from deepeval.tracing import trace, LlmSpanContext, observe
from deepeval.openai import OpenAI

client = OpenAI()

@observe(type="retriever")
def retrieve_docs(query: str) -> list[str]:
    return ["Paris is the capital of France."]

@observe()
def respond_to_user(prompt: str) -> str:
    docs = retrieve_docs(prompt)
    with trace(
        llm_span_context=LlmSpanContext(retrieval_context=docs),
        user_id="user-123",
        tags=["openai", "rag"],
    ):
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": "\n".join(docs)},
                {"role": "user", "content": prompt},
            ],
        )
    return response.choices[0].message.content
```

</Case>

<Case id="typescript">

```typescript title="openai-app.ts" showLineNumbers
import { observe, setTracingContext } from "deepeval/tracing";
...

const retrieveDocs = observe({
  type: "retriever",
  name: "retrieveDocs",
  fn: async (_query: string) => ["Paris is the capital of France."],
});

const respondToUser = observe({
  name: "respondToUser",
  fn: async (prompt: string) => {
    const docs = await retrieveDocs(prompt);
    const response = await setTracingContext(
      {
        llmSpanContext: { retrievalContext: docs },
        userId: "user-123",
        tags: ["openai", "rag"],
      },
      () =>
        client.chat.completions.create({
          model: "gpt-4o",
          messages: [
            { role: "system", content: docs.join("\n") },
            { role: "user", content: prompt },
          ],
        }),
    );
    return response.choices[0].message.content;
  },
});
```

</Case>

</Switch>

## Advanced patterns

The primitives above compose around one boundary: the patch owns each LLM call's span, and your code chooses what trace to put it inside.

### Wrap an OpenAI call in an observed function

When the OpenAI call is part of a larger operation, observe the outer function. The LLM span nests under your observed span automatically.

<Switch>

<Case id="python">

```python title="openai_app.py" showLineNumbers
from deepeval.tracing import observe, trace, LlmSpanContext
from deepeval.metrics import AnswerRelevancyMetric
...

@observe(name="respond_to_user")
def respond_to_user(prompt: str) -> str:
    with trace(llm_span_context=LlmSpanContext(metrics=[AnswerRelevancyMetric()])):
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
        )
    return response.choices[0].message.content
```

</Case>

<Case id="typescript">

```typescript title="openai-app.ts" showLineNumbers
import { AnswerRelevancyMetric } from "deepeval/metrics";
import { observe, nextLlmSpan } from "deepeval/tracing";
...

const respondToUser = observe({
  name: "respondToUser",
  fn: async (prompt: string) => {
    const response = await nextLlmSpan(
      { metrics: [new AnswerRelevancyMetric()] },
      () =>
        client.chat.completions.create({
          model: "gpt-4o",
          messages: [{ role: "user", content: prompt }],
        }),
    );
    return response.choices[0].message.content;
  },
});
```

</Case>

### Multiple OpenAI calls under one trace

When a single logical unit of work makes several OpenAI calls (e.g. a planner call followed by a respond call), bracket them so the LLM spans share a trace and show up as siblings under one root.

<Switch>

<Case id="python">

```python title="openai_app.py" showLineNumbers
from deepeval.tracing import trace
...

def plan_then_respond(prompt: str):
    with trace(name="plan_then_respond"):
        plan = client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": f"Plan: {prompt}"}],
        )
        return client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": plan.choices[0].message.content}],
        )
```

</Case>

<Case id="typescript">

```typescript title="openai-app.ts" showLineNumbers
import { setTracingContext } from "deepeval/tracing";
...

const planThenRespond = (prompt: string) =>
  setTracingContext({ name: "planThenRespond" }, async () => {
    const plan = await client.chat.completions.create({
      model: "gpt-4o",
      messages: [{ role: "user", content: `Plan: ${prompt}` }],
    });
    return client.chat.completions.create({
      model: "gpt-4o",
      messages: [
        { role: "user", content: plan.choices[0].message.content ?? "" },
      ],
    });
  });
```

</Case>

### Tool-calling models

When the model returns tool calls, the LLM span's <Term py="tools_called" ts="toolsCalled"/> field captures them automatically. Use <Term py="expected_tools" ts="expectedTools"/> on `LlmSpanContext` if you want to evaluate tool selection with a tool-aware metric.

<Switch>

<Case id="python">

```python title="openai_app.py" showLineNumbers
from deepeval.tracing import trace, LlmSpanContext
from deepeval.test_case import ToolCall
...

with trace(
    llm_span_context=LlmSpanContext(
        expected_tools=[ToolCall(name="get_weather", input_parameters={"city": "Paris"})],
    ),
):
    client.chat.completions.create(model="gpt-4o", messages=[...], tools=[...])
```

</Case>

<Case id="typescript">

```typescript title="openai-app.ts" showLineNumbers
import { setTracingContext } from "deepeval/tracing";
import { ToolCall } from "deepeval/test-case";
...

await setTracingContext(
  {
    llmSpanContext: {
      expectedTools: [
        new ToolCall({
          name: "get_weather",
          inputParameters: { city: "Paris" },
        }),
      ],
    },
  },
  () => client.chat.completions.create({ model: "gpt-4o", messages, tools }),
);
```

</Case>

</Switch>

## API reference

`LlmSpanContext` accepts the following fields. Each is read when an OpenAI call's LLM span is created.

| Field | Type | Description |
| --- | --- | --- |
| `metrics` | <Term py="list" ts="array"/> | Metrics applied to the LLM span. |
| `prompt` | `Prompt` | Confident AI prompt object; captured on the LLM span for prompt-version analytics. |
| <Term py="expected_output" ts="expectedOutput"/> | <Term py="str" ts="string"/> | Reference output for metrics that compare against ground truth. |
| <Term py="expected_tools" ts="expectedTools"/> | <Term py="list" ts="array"/> | Reference tool calls for tool-aware metrics. |
| `context` | <Term py="list[str]" ts="string[]"/> | Ideal context the model should use when answering. |
| <Term py="retrieval_context" ts="retrievalContext"/> | <Term py="list[str]" ts="string[]"/> | Retrieved context the model actually used (Faithfulness, Contextual Relevancy, etc.). |

<Term py="with trace(...)" ts="setTracingContext(...)"/> accepts trace-level fields (`name`, `tags`, `metadata`, <Term py="thread_id" ts="threadId"/>, <Term py="user_id" ts="userId"/>, `metrics`, `input`, `output`) — see the [tracing reference](/docs/evaluation-llm-tracing).
