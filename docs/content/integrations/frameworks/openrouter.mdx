[OpenRouter](https://openrouter.ai/) is a gateway that puts 400+ models from every major provider behind one API.

You can reach it two ways — through OpenRouter's own SDK, or by pointing the OpenAI SDK at OpenRouter's base URL — and `deepeval` instruments both. Every call becomes an LLM span you can evaluate, labelled with the provider that actually served it.

`deepeval`'s OpenRouter integration enables you to:

- <Switch><Case id="python">**Instrument either client** — `from deepeval.openrouter import OpenRouter` for the official SDK, or `from deepeval.openai import OpenAI` pointed at OpenRouter's base URL.</Case><Case id="typescript">**Instrument either client** — `instrumentOpenRouter(client)` for the official SDK, or `instrumentOpenAI(client)` pointed at OpenRouter's base URL.</Case></Switch>
- **See the real provider** — spans record `provider="OpenRouter"` rather than the SDK you happened to use.
- **Capture what only OpenRouter knows** — generation id, credit cost, cached and reasoning token counts, and which upstream provider actually served the request.
- <Switch><Case id="python">**Evaluate LLM calls** with any `deepeval` metric through `LlmSpanContext`.</Case><Case id="typescript">**Evaluate LLM calls** with any `deepeval` metric through `llmSpanContext`.</Case></Switch>

## Choosing an entry point

Two span fields answer two different questions: `integration` is the SDK `deepeval` instrumented, and `provider` is who served the request. Pointing the OpenAI SDK at a gateway makes them differ.

<Switch>

<Case id="python">

| You call OpenRouter via              | Import this                                  | `integration` | `provider`   |
| ------------------------------------ | -------------------------------------------- | ------------- | ------------ |
| The official `openrouter` SDK        | `from deepeval.openrouter import OpenRouter` | `OpenRouter`  | `OpenRouter` |
| The OpenAI SDK + OpenRouter base URL | `from deepeval.openai import OpenAI`         | `OpenAI`      | `OpenRouter` |

</Case>

<Case id="typescript">

| You call OpenRouter via              | Instrument with                | `integration` | `provider`   |
| ------------------------------------ | ------------------------------ | ------------- | ------------ |
| The official `@openrouter/sdk`       | `instrumentOpenRouter(client)` | `OpenRouter`  | `OpenRouter` |
| The OpenAI SDK + OpenRouter base URL | `instrumentOpenAI(client)`     | `OpenAI`      | `OpenRouter` |

</Case>

</Switch>

</Switch>

<Step>

### Instrument and evaluate

<Switch>

<Case id="python">

`deepeval.openrouter.OpenRouter` is the SDK's own client class, re-exported — importing it from `deepeval` is what patches the resource classes in place. Your client construction and call sites are unchanged.

```python title="openrouter_app.py" showLineNumbers
from deepeval.openrouter import OpenRouter
from deepeval.tracing import trace, LlmSpanContext
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.metrics import AnswerRelevancyMetric

client = OpenRouter()  # reads OPENROUTER_API_KEY

# Goldens are the inputs you want to evaluate.
dataset = EvaluationDataset(goldens=[Golden(input="What's the capital of France?")])

for golden in dataset.evals_iterator():
    with trace(llm_span_context=LlmSpanContext(metrics=[AnswerRelevancyMetric()])):
        client.chat.send(
            model="anthropic/claude-sonnet-4.5",
            messages=[{"role": "user", "content": golden.input}],
        )
```

</Case>

<Case id="typescript">

`instrumentOpenRouter(client)` patches the client you hand it in place. Note the request envelope: the TypeScript SDK nests the payload under `chatRequest`.

```typescript title="openrouter-app.ts" showLineNumbers
import { OpenRouter } from "@openrouter/sdk";
import { instrumentOpenRouter } from "deepeval/openrouter";
import { setTracingContext } from "deepeval/tracing";
import { AnswerRelevancyMetric } from "deepeval/metrics";

const client = new OpenRouter({ apiKey: process.env.OPENROUTER_API_KEY });
instrumentOpenRouter(client);

export async function respond(input: string) {
  return setTracingContext(
    { llmSpanContext: { metrics: [new AnswerRelevancyMetric()] } },
    () =>
      client.chat.send({
        chatRequest: {
          model: "anthropic/claude-sonnet-4.5",
          messages: [{ role: "user", content: input }],
        },
      }),
  );
}
```

</Case>

</Switch>

Done ✅. You've run your first eval against an OpenRouter call with full traceability via `deepeval`.

## Using the OpenAI SDK instead

OpenRouter is OpenAI-compatible, so many codebases reach it by changing one base URL. `deepeval` recognizes OpenRouter's host and labels the span accordingly — you do not need the OpenRouter SDK for this path.

<Switch>

<Case id="python">

```python title="openrouter_via_openai.py" showLineNumbers
from deepeval.openai import OpenAI
from deepeval.tracing import trace, LlmSpanContext
from deepeval.metrics import AnswerRelevancyMetric

client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key="<your-openrouter-key>",
)

with trace(llm_span_context=LlmSpanContext(metrics=[AnswerRelevancyMetric()])):
    client.chat.completions.create(
        model="anthropic/claude-sonnet-4.5",
        messages=[{"role": "user", "content": "What's the capital of France?"}],
    )
```

</Case>

<Case id="typescript">

```typescript title="openrouter-via-openai.ts" showLineNumbers
import { OpenAI } from "openai";
import { instrumentOpenAI } from "deepeval/openai";
import { setTracingContext } from "deepeval/tracing";

}
```

The resulting span records `provider="OpenRouter"` and `integration="OpenAI"`.

## What gets traced

Each instrumented call produces one **LLM span** under the active trace.

- **LLM spans** — one per call. Captures input messages, output text, token counts, and <Term py="tools_called" ts="toolsCalled"/>.
- **Trace** — auto-created when the call has no parent. If the call runs inside <Term py="with trace(...) or @observe" ts="setTracingContext(...) or observe()"/>, the LLM span nests under that trace instead.

```text
Trace                                    ← auto-created or user-owned
└── LLM: anthropic/claude-sonnet-4.5     ← one OpenRouter call
```

### OpenRouter-specific metadata

Because OpenRouter is a router, its responses carry detail a direct provider call does not. `deepeval` collects that into the span's `metadata` under an `openrouter` key, so it never collides with metadata you set yourself.

<Switch>

<Case id="python">

```python
span.metadata["openrouter"] == {
    "generation_id": "gen-...",        # queryable via /api/v1/generation
    "upstream_provider": "Anthropic",  # who actually served it (OpenAI SDK route)
    "cost": 0.000123,                  # in credits
    "cost_details": {...},
    "is_byok": False,
    "cached_tokens": 4,
    "cache_write_tokens": 9,
    "reasoning_tokens": 2,
    "routing": {                       # native SDK route only
        "strategy": "price",
        "summary": "routed to Anthropic",
    },
}
```

</Case>

<Case id="typescript">


## Running evals

### In CI/CD

<Switch>

<Case id="python">

Each parametrized test invocation becomes one OpenRouter call; a failing metric fails the test, which fails the build.

```python title="test_openrouter_app.py" showLineNumbers
import pytest
from deepeval import assert_test
from deepeval.openrouter import OpenRouter
from deepeval.tracing import trace, LlmSpanContext
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.metrics import AnswerRelevancyMetric

client = OpenRouter()
dataset = EvaluationDataset(goldens=[
    Golden(input="What's the capital of France?"),
    Golden(input="Who wrote Hamlet?"),
])

@pytest.mark.parametrize("golden", dataset.goldens)
def test_openrouter_app(golden: Golden):
    with trace(llm_span_context=LlmSpanContext(metrics=[AnswerRelevancyMetric()])):
        client.chat.send(
            model="anthropic/claude-sonnet-4.5",
            messages=[{"role": "user", "content": golden.input}],
        )
    assert_test(golden=golden)
```

Run it with:

```bash
deepeval test run test_openrouter_app.py
```

</Case>

<Case id="typescript">

Use the `toPass()` matcher. The golden is the subject; `task` produces the trace judged against it. A failing metric fails the test, which fails the build.

```typescript title="openrouter-app.test.ts" showLineNumbers
import { it, expect } from "vitest";
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { respond } from "./openrouter-app";
import "deepeval/vitest";

const dataset = new EvaluationDataset({
  goldens: [
    new Golden({ input: "What's the capital of France?" }),
    new Golden({ input: "Who wrote Hamlet?" }),
  ],
});

it.each(dataset.goldens as Golden[])("answers the question", async (golden) => {
  await expect(golden).toPass([], { task: (g) => respond(g.input) });
});
```

The matcher takes an empty metric array because `AnswerRelevancyMetric` is already staged on the LLM span inside `respond`.

Run it with:

```bash
npx deepeval test run openrouter-app.test.ts
```

</Case>

</Switch>

### In a script

<Switch>

<Case id="python">

```python title="openrouter_app.py" showLineNumbers
import asyncio

from deepeval.openrouter import OpenRouter
from deepeval.tracing import trace, LlmSpanContext
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.evaluate.configs import AsyncConfig
from deepeval.metrics import AnswerRelevancyMetric

client = OpenRouter()
dataset = EvaluationDataset(goldens=[
    Golden(input="What's the capital of France?"),
    Golden(input="Who wrote Hamlet?"),
])

async def call_openrouter(prompt: str):
    with trace(llm_span_context=LlmSpanContext(metrics=[AnswerRelevancyMetric()])):
        return await client.chat.send_async(
            model="anthropic/claude-sonnet-4.5",
            messages=[{"role": "user", "content": prompt}],
        )

for golden in dataset.evals_iterator(async_config=AsyncConfig(run_async=True)):
    task = asyncio.create_task(call_openrouter(golden.input))
    dataset.evaluate(task)
```

Sync (`chat.send`) and async (`chat.send_async`) both work; pick whichever matches your code.

</Case>

<Case id="typescript">

```typescript title="openrouter-app.ts" showLineNumbers
const dataset = new EvaluationDataset({
  goldens: [
    new Golden({ input: "What's the capital of France?" }),
    new Golden({ input: "Who wrote Hamlet?" }),
  ],
});

for await (const golden of dataset.evalsIterator()) {
  await respond((golden as Golden).input);
}
```

The OpenRouter client is promise-based, so there is one code path rather than a sync and an async client.

</Case>

</Switch>

## Applying metrics to LLM spans

Passing `metrics` evaluates the next OpenRouter call's LLM span specifically. The same context carries extra evaluation parameters that some metrics need.

<Switch>

<Case id="python">

```python title="openrouter_app.py" showLineNumbers
from deepeval.openrouter import OpenRouter
from deepeval.tracing import trace, LlmSpanContext
from deepeval.metrics import AnswerRelevancyMetric, FaithfulnessMetric

client = OpenRouter()

with trace(
    llm_span_context=LlmSpanContext(
        metrics=[AnswerRelevancyMetric(), FaithfulnessMetric()],
        retrieval_context=["Paris is the capital of France."],
    ),
):
    client.chat.send(
        model="anthropic/claude-sonnet-4.5",
        messages=[{"role": "user", "content": "What's the capital of France?"}],
    )
```

</Case>

<Case id="typescript">

```typescript title="openrouter-app.ts" showLineNumbers
import { setTracingContext } from "deepeval/tracing";
import { AnswerRelevancyMetric, FaithfulnessMetric } from "deepeval/metrics";

await setTracingContext(
  {
    llmSpanContext: {
      metrics: [new AnswerRelevancyMetric(), new FaithfulnessMetric()],
      retrievalContext: ["Paris is the capital of France."],

  },
  () =>
    client.chat.send({
      chatRequest: {
        model: "anthropic/claude-sonnet-4.5",
```

### Overriding the provider

`provider` is the escape hatch for gateways `deepeval` cannot recognize from a base URL — a self-hosted proxy, a new gateway, or a vanity domain in front of one. It takes precedence over detection, and does not change which response fields are read, so OpenRouter's cost data survives a relabel.

<Switch>

<Case id="python">

```python
from deepeval.openai import OpenAI
from deepeval.tracing import trace, LlmSpanContext

client = OpenAI(base_url="https://llm.internal.example.com/v1", api_key="...")

with trace(llm_span_context=LlmSpanContext(provider="MyGateway")):
    client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": "hello"}],
    )
```

</Case>

<Case id="typescript">

```typescript
import { OpenAI } from "openai";
import { instrumentOpenAI } from "deepeval/openai";
import { setTracingContext } from "deepeval/tracing";

const client = new OpenAI({
  baseURL: "https://llm.internal.example.com/v1",
  apiKey: "...",
});
instrumentOpenAI(client);

await setTracingContext({ llmSpanContext: { provider: "MyGateway" } }, () =>
  client.chat.completions.create({
    model: "gpt-4o",
    messages: [{ role: "user", content: "hello" }],
  }),
);
```

</Case>

</Switch>

## Customizing trace and span data

- Use <Term py="with trace(...)" ts="setTracingContext(...)"/> for trace-level fields (`name`, `tags`, `metadata`, <Term py="thread_id" ts="threadId"/>, <Term py="user_id" ts="userId"/>).
- Use <Term py="LlmSpanContext" ts="llmSpanContext"/> for LLM-span-level fields a metric needs (<Term py="expected_output" ts="expectedOutput"/>, <Term py="retrieval_context" ts="retrievalContext"/>, etc.).
- Use <Term py="@observe" ts="observe()"/> to wrap retrieval, post-processing, or any other step you want as its own span.

<Switch>

<Case id="python">

```python title="openrouter_app.py" showLineNumbers
from deepeval.openrouter import OpenRouter
from deepeval.tracing import trace, LlmSpanContext, observe

client = OpenRouter()

@observe(type="retriever")
def retrieve_docs(query: str) -> list[str]:
    return ["Paris is the capital of France."]

@observe()
def respond_to_user(prompt: str) -> str:
    docs = retrieve_docs(prompt)
    with trace(
        llm_span_context=LlmSpanContext(retrieval_context=docs),
        name="openrouter-app",
        tags=["production"],
    ):
        response = client.chat.send(
            model="anthropic/claude-sonnet-4.5",
            messages=[{"role": "user", "content": prompt}],
        )
    return response.choices[0].message.content
```

</Case>

<Case id="typescript">

```typescript title="openrouter-app.ts" showLineNumbers
import { observe, setTracingContext } from "deepeval/tracing";

const retrieveDocs = observe({
  type: "retriever",
  name: "retrieveDocs",
  fn: async (_query: string) => ["Paris is the capital of France."],
});

export const respondToUser = observe({
  name: "respondToUser",
  fn: async (prompt: string) => {
    const docs = await retrieveDocs(prompt);
    const response: any = await setTracingContext(
      {
        name: "openrouter-app",
        tags: ["production"],
        llmSpanContext: { retrievalContext: docs },
      },
      () =>
        client.chat.send({
          chatRequest: {
            model: "anthropic/claude-sonnet-4.5",
            messages: [{ role: "user", content: prompt }],
          },
        }),
    );
    return response.choices[0].message.content;
  },
});
```

</Case>

</Switch>

## API reference

<Term py="LlmSpanContext" ts="llmSpanContext"/> accepts the following fields. Each is read when an OpenRouter call's LLM span is created.

| Field | Type | Description |
| --- | --- | --- |
| `metrics` | <Term py="list" ts="array"/> | Metrics applied to the LLM span. |
| `prompt` | `Prompt` | Confident AI prompt object; captured on the LLM span for prompt-version analytics. |
| `provider` | <Term py="str" ts="string"/> | Overrides the provider label. Takes precedence over base-URL detection. |
| <Term py="expected_output" ts="expectedOutput"/> | <Term py="str" ts="string"/> | Reference output for metrics that compare against ground truth. |
| <Term py="expected_tools" ts="expectedTools"/> | <Term py="list" ts="array"/> | Reference tool calls for tool-aware metrics. |
| `context` | <Term py="list[str]" ts="string[]"/> | Ideal context the model should use when answering. |
| <Term py="retrieval_context" ts="retrievalContext"/> | <Term py="list[str]" ts="string[]"/> | Retrieved context the model actually used (Faithfulness, Contextual Relevancy, etc.). |

<Term py="with trace(...)" ts="setTracingContext(...)"/> accepts trace-level fields (`name`, `tags`, `metadata`, <Term py="thread_id" ts="threadId"/>, <Term py="user_id" ts="userId"/>, `metrics`, `input`, `output`) — see the [tracing reference](/docs/evaluation-llm-tracing).
