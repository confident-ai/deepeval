[OpenAI Agents](https://openai.github.io/openai-agents-python/) is OpenAI's SDK for building agents that reason, call tools, and hand off to other agents.

The `deepeval` integration plugs into the agents SDK's tracing pipeline as a <Term py="TracingProcessor" ts="DeepEvalTracingProcessor"/>. Every agent run, LLM call, and tool call becomes a span you can inspect — without rewriting your agent code.

`deepeval`'s OpenAI Agents integration enables you to:

- **Trace every agent run** — each <Term py="Runner.run(...)" ts="run(...)"/> produces a trace, and each LLM, tool, and sub-agent call becomes a component span.
- **Evaluate the complete ordered [agent trajectory](/docs/evaluation-trajectory-based-llm-evals)** — score the sequence across all applicable agent, LLM, tool, and handoff spans.
- **Evaluate traces or individual components** with any `deepeval` metric.
- **Run evals from scripts or CI/CD** — same agent, different surfaces.
- **Customize trace and span data** through agent/tool config (Python) or <Term py="next_*_span" ts="next*Span"/> staging (both).

### Instrument and evaluate

Register the processor once at startup, then run your goldens through the agent.

<Switch>

<Case id="python">

```python title="openai_agents_app.py" showLineNumbers
from agents import Runner, add_trace_processor
from deepeval.openai_agents import Agent, DeepEvalTracingProcessor, function_tool
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.metrics import TaskCompletionMetric

add_trace_processor(DeepEvalTracingProcessor())

@function_tool
def get_weather(city: str) -> str:
    """Return the weather in a city."""
    return f"It's always sunny in {city}!"

agent = Agent(
    name="weather_agent",
    instructions="Answer weather questions concisely.",
    tools=[get_weather],
    agent_metrics=[TaskCompletionMetric()],
)

# Goldens are the inputs you want to evaluate.
dataset = EvaluationDataset(goldens=[Golden(input="What's the weather in Paris?")])

for golden in dataset.evals_iterator():
    Runner.run_sync(agent, golden.input)
```

</Case>

<Case id="typescript">

```typescript title="openai-agents-app.ts" showLineNumbers
import { Agent, tool, run, addTraceProcessor } from "@openai/agents";
import { z } from "zod";

import { DeepEvalTracingProcessor } from "deepeval/integrations/openai-agents";
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { TaskCompletionMetric } from "deepeval/metrics";

addTraceProcessor(new DeepEvalTracingProcessor());

const getWeather = tool({
  name: "getWeather",
  description: "Return the weather in a city.",
  parameters: z.object({ city: z.string() }),
  execute: async ({ city }) => `It's always sunny in ${city}!`,
});

const agent = new Agent({
  name: "weatherAgent",
  instructions: "Answer weather questions concisely.",
  model: "gpt-4o-mini",
  tools: [getWeather],
});

const ask = (question: string) => run(agent, question);

// Goldens are the inputs you want to evaluate.
const dataset = new EvaluationDataset({
  goldens: [new Golden({ input: "What's the weather in Paris?" })],
});

// The `TaskCompletionMetric` is passed into the `evalsIterator`.
for await (const golden of dataset.evalsIterator({
  metrics: [new TaskCompletionMetric()],
})) {
  await ask((golden as Golden).input);
}
```

</Case>

</Switch>

Done ✅. You've run your first eval with full traceability into OpenAI Agents via `deepeval`.

## What gets traced

Each <Term py="Runner.run(...)" ts="run(...)"/> call produces a **trace** — the end-to-end unit your user observes. Inside that trace are **component spans** for every step the agent took:

- **Agent spans** — one per `Agent` invocation, including handoffs to other agents.
- **LLM spans** — model calls (Responses API and Chat Completions).
- **Tool spans** — function tools, MCP tools, and other agents-SDK tool calls.

<Switch>
<Case id="python">

```text
Trace                          ← what the user observes
└── Agent: weather_agent       ← one Runner.run(...) call
    ├── LLM: gpt-4o            ← component span: model plans
    ├── Tool: get_weather      ← component span: tool input + output
    └── LLM: gpt-4o            ← component span: final answer
```

</Case>
<Case id="typescript">

```text
Trace                          ← what the user observes
└── Agent: weatherAgent        ← one run(...) call
    ├── LLM: gpt-4o            ← component span: model plans
    ├── Tool: getWeather       ← component span: tool input + output
    └── LLM: gpt-4o            ← component span: final answer
```

</Case>
</Switch>

The trace and its component spans are independently evaluable.

## Running evals

There are two surfaces for running evals against an OpenAI Agents app. Pick by where you want results to surface — your terminal during development, or your CI pipeline as a pass/fail gate.

### In CI/CD

<Switch>

<Case id="python">

Use the `deepeval` pytest integration. Each parametrized test invocation becomes one agent run; failing metrics fail the test, which fails the build.

```python title="test_openai_agents_app.py" showLineNumbers
import pytest
from agents import Runner, add_trace_processor
from deepeval.openai_agents import Agent, DeepEvalTracingProcessor, function_tool
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.metrics import TaskCompletionMetric
from deepeval import assert_test

add_trace_processor(DeepEvalTracingProcessor())

@function_tool
def get_weather(city: str) -> str:
    """Return the weather in a city."""
    return f"It's always sunny in {city}!"

agent = Agent(
    name="weather_agent",
    instructions="Answer weather questions concisely.",
    tools=[get_weather],
)

dataset = EvaluationDataset(goldens=[
    Golden(input="What's the weather in Paris?"),
    Golden(input="What's the weather in London?"),
])

@pytest.mark.parametrize("golden", dataset.goldens)
def test_openai_agents_app(golden: Golden):
    Runner.run_sync(agent, golden.input)
    assert_test(golden=golden, metrics=[TaskCompletionMetric()])
```

Run it with:

```bash
deepeval test run test_openai_agents_app.py
```

</Case>

<Case id="typescript">

Use the `toPass()` matcher. The golden is the subject; `task` produces the trace judged against it. A failing metric fails the test, which fails the build.

```typescript title="openai-agents.test.ts" showLineNumbers
import { it, expect } from "vitest";
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { TaskCompletionMetric } from "deepeval/metrics";
import { ask } from "./openai-agents-app";
import "deepeval/vitest";

const dataset = new EvaluationDataset({
  goldens: [
    new Golden({ input: "What's the weather in Paris?" }),
    new Golden({ input: "What's the weather in London?" }),
  ],
});

it.each(dataset.goldens as Golden[])(
  "completes the weather task",
  async (golden) => {
    await expect(golden).toPass([new TaskCompletionMetric()], {
      task: (g) => ask(g.input),
    });
  },
);
```

Run it with:

```bash
npx deepeval test run openai-agents.test.ts
```

</Case>

</Switch>

### In a script

Use <Term py="EvaluationDataset" ts="EvaluationDataset"/> + <Term py="evals_iterator" ts="evalsIterator"/>. Each `Golden` becomes one agent run; metrics score the resulting trace.

<Switch>

<Case id="python">

```python title="openai_agents_app.py" showLineNumbers
import asyncio

from deepeval.dataset import EvaluationDataset, Golden
from deepeval.evaluate.configs import AsyncConfig
from deepeval.metrics import TaskCompletionMetric
...

dataset = EvaluationDataset(goldens=[
    Golden(input="What's the weather in Paris?"),
    Golden(input="What's the weather in London?"),
])

for golden in dataset.evals_iterator(
    async_config=AsyncConfig(run_async=True),
    metrics=[TaskCompletionMetric()],
):
    task = asyncio.create_task(Runner.run(agent, golden.input))
    dataset.evaluate(task)
```

Sync (`Runner.run_sync`) and async (`Runner.run`) execution both work; pick whichever matches your code.

## Evaluate agent trajectories

Trajectory evaluation scores the complete ordered trace: the agent's decisions, model calls, tool use, handoffs, and other applicable spans in the sequence they occurred. This is distinct from evaluating only the final output or attaching a metric to an individual component span.

Pass trajectory metrics to <Term py="evals_iterator" ts="evalsIterator"/> so each instrumented OpenAI Agents run is evaluated at trace scope:

<Switch>

<Case id="python">

```python title="openai_agents_app.py" showLineNumbers
from deepeval.metrics import TaskCompletionMetric, StepEfficiencyMetric, PlanAdherenceMetric
from deepeval.openai_agents import DeepEvalTracingProcessor
from deepeval.dataset import EvaluationDataset, Golden
from agents import Runner, add_trace_processor
...

add_trace_processor(DeepEvalTracingProcessor())
dataset = EvaluationDataset(goldens=[Golden(input="What's the weather in Paris?")])
metrics = [TaskCompletionMetric(), StepEfficiencyMetric(), PlanAdherenceMetric()]

for golden in dataset.evals_iterator(metrics=metrics):
    Runner.run_sync(agent, golden.input)
```

</Case>

<Case id="typescript">

```typescript title="openai-agents-app.ts" showLineNumbers
import { TaskCompletionMetric, StepEfficiencyMetric, PlanAdherenceMetric } from "deepeval/metrics";
import { DeepEvalTracingProcessor } from "deepeval/integrations/openai-agents";
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { addTraceProcessor, run } from "@openai/agents";
...

addTraceProcessor(new DeepEvalTracingProcessor());
const dataset = new EvaluationDataset({
  goldens: [new Golden({ input: "What's the weather in Paris?" })],
});
const metrics = [
  new TaskCompletionMetric(),
  new StepEfficiencyMetric(),
  new PlanAdherenceMetric(),
];

for await (const golden of dataset.evalsIterator({ metrics })) {
  await run(agent, (golden as Golden).input);
}
```

</Case>

</Switch>

See the [trajectory evaluation guide](/docs/evaluation-trajectory-based-llm-evals) for metric selection and interpretation. To score one step instead of the ordered run, apply metrics to components next.

## Applying metrics to components

Passing metrics to <Term py="evals_iterator" ts="evalsIterator"/> evaluates the **trace**. To evaluate a **component** — a specific agent, LLM call, or tool — attach metrics where that component is created.

### Agent spans

<Switch>

<Case id="python">

Use `agent_metrics=[...]` on `deepeval.openai_agents.Agent`. The metric is applied to that agent's span on every run, including when it's invoked as a sub-agent through a handoff.

```python title="openai_agents_app.py" showLineNumbers
from deepeval.metrics import TaskCompletionMetric
from deepeval.openai_agents import Agent
...

agent = Agent(
    name="weather_agent",
    instructions="Answer weather questions concisely.",
    tools=[get_weather],
    agent_metrics=[TaskCompletionMetric()],
)
```

</Case>

<Case id="typescript">

Wrap the call in `nextAgentSpan(...)`. The processor drains the staged metric onto the **first agent span** it opens inside the callback — useful for scoring the agent (or a handoff target) in isolation.

```typescript title="openai-agents-app.ts" showLineNumbers
import { TaskCompletionMetric } from "deepeval/metrics";
import { nextAgentSpan } from "deepeval/tracing";
...

for await (const golden of dataset.evalsIterator()) {
  await nextAgentSpan({ metrics: [new TaskCompletionMetric()] }, () =>
    ask((golden as Golden).input),
  );
}
```

</Case>

</Switch>

### LLM calls

<Switch>

<Case id="python">

Use `llm_metrics=[...]` on `Agent`. The metric is applied to the LLM span produced for that agent's model calls. Useful when you want to score the model's reasoning step in isolation.

```python title="openai_agents_app.py" showLineNumbers
from deepeval.metrics import AnswerRelevancyMetric
from deepeval.openai_agents import Agent
...

agent = Agent(
    name="weather_agent",
    instructions="Answer weather questions concisely.",
    tools=[get_weather],
    llm_metrics=[AnswerRelevancyMetric()],
)
```

</Case>

<Case id="typescript">

Wrap the call in `nextLlmSpan(...)`. The processor drains the staged metric onto the **first LLM span** it opens inside the callback; later model calls in the same run get nothing.

```typescript title="openai-agents-app.ts" showLineNumbers
import { AnswerRelevancyMetric } from "deepeval/metrics";
import { nextLlmSpan } from "deepeval/tracing";
...

for await (const golden of dataset.evalsIterator()) {
  await nextLlmSpan({ metrics: [new AnswerRelevancyMetric()] }, () =>
    ask((golden as Golden).input),
  );
}
```

:::caution[One-shot per run]
`nextLlmSpan` stages config for the **first** LLM span the processor opens inside the callback. Later model calls in the same `run(...)` — the tool-choice turn followed by the final-answer turn — won't receive it. To score every model call, use `setTracingContext(...)` instead, or score the run end-to-end with trace-level metrics on `evalsIterator({ metrics: [...] })`.
:::

</Case>

</Switch>

### Tool calls

<Switch>

<Case id="python">

Pass `metrics=[...]` to `function_tool` to evaluate a specific tool's behavior. Useful for tools that return non-deterministic content (e.g. retrieval, summarization tools).

```python title="openai_agents_app.py" showLineNumbers
from deepeval.openai_agents import function_tool
from deepeval.test_case import LLMTestCaseParams
from deepeval.metrics import GEval

@function_tool(metrics=[GEval(
    name="Helpful Weather Lookup",
    criteria="The output must be a clear weather summary for the requested city.",
    evaluation_params=[LLMTestCaseParams.INPUT, LLMTestCaseParams.ACTUAL_OUTPUT],
)])
def get_weather(city: str) -> str:
    """Return the weather in a city."""
    return f"It's always sunny in {city}!"
```

For deterministic tool calls, prefer `update_current_span(...)` to add metadata, inputs, and outputs instead of attaching metrics to the tool span.

</Case>

<Case id="typescript">

Inside a tool `execute` body your code **is** the tool span, so reach it with `updateCurrentSpan(...)`:

```typescript title="openai-agents-app.ts" showLineNumbers
import { updateCurrentSpan } from "deepeval/tracing";
import { tool } from "@openai/agents";
import { z } from "zod";
...

const getWeather = tool({
  name: "getWeather",
  description: "Return the weather in a city.",
  parameters: z.object({ city: z.string() }),
  execute: async ({ city }) => {
    updateCurrentSpan({
      metadata: { source: "staticTable" },
    });
    return `It's always sunny in ${city}!`;
  },
});
```

`nextToolSpan(...)` stages the same fields from outside the tool, on the same one-shot semantic as `nextLlmSpan`. Prefer it for deterministic tools where you only want traceability and metadata rather than a metric.

</Case>

</Switch>

## Customizing trace and span data

The integration captures inputs, outputs, model names, and tool calls automatically. For anything dynamic, the right API depends on where your code runs.

<Switch>

<Case id="python">

- Use `with trace(...)` for trace-level fields (`name`, `tags`, `metadata`, `thread_id`, `user_id`).
- Use `Agent`/`function_tool` kwargs (`agent_metrics`, `llm_metrics`, `metrics=`, `confident_prompt`) for component-level defaults.
- Use `update_current_trace(...)` and `update_current_span(...)` from inside a tool body to mutate fields the framework can't see.

```python title="openai_agents_app.py" showLineNumbers
from deepeval.tracing import update_current_trace, update_current_span
from deepeval.openai_agents import function_tool

@function_tool
def get_weather(city: str) -> str:
    """Return the weather in a city."""
    update_current_trace(metadata={"city": city})
    update_current_span(metadata={"source": "static-table"})
    return f"It's always sunny in {city}!"
```

</Case>

<Case id="typescript">

- Use `setTracingContext(...)` for trace-level fields (`name`, `tags`, `metadata`, `threadId`, `userId`) and scope-wide span defaults.
- Use `nextAgentSpan(...)` / `nextLlmSpan(...)` / `nextToolSpan(...)` to stage component-level fields onto the next span the processor opens.
- Use `updateCurrentSpan(...)` / `updateCurrentTrace(...)` from inside a tool body to mutate fields the framework can't see.

```typescript title="openai-agents-app.ts" showLineNumbers
import { setTracingContext, updateCurrentSpan } from "deepeval/tracing";
...

await setTracingContext(
  {
    name: "weather-ask",
    tags: ["openai-agents", "weather"],
    threadId: "thread-123",
    userId: "user-xyz",
  },
  () => ask("What's the weather in Paris?"),
);
```

</Case>

</Switch>

## Advanced patterns

The primitives above compose around one boundary: the agents SDK owns the run lifecycle, and your code attaches metrics where they make sense.

### Evaluate a sub-agent through handoff

When a parent agent hands off to a sub-agent, the sub-agent's span runs as a child of the parent's.

<Switch>

<Case id="python">

Attaching `agent_metrics` to the sub-agent scores that hand-off step in isolation.

```python title="openai_agents_app.py" showLineNumbers
from deepeval.metrics import TaskCompletionMetric, AnswerRelevancyMetric
from deepeval.openai_agents import Agent
...

triage_agent = Agent(
    name="triage",
    instructions="Route the question to the right specialist.",
    handoffs=[
        Agent(
            name="weather_specialist",
            instructions="Answer weather questions.",
            tools=[get_weather],
            agent_metrics=[TaskCompletionMetric()],
        ),
    ],
    agent_metrics=[AnswerRelevancyMetric()],
)
```

#### No trace-level metrics required

Trace-level metrics are end-to-end metrics: they score the whole trace. They are not strictly necessary here because the metrics are already attached to the triage and specialist agents, so CI/CD and scripts only need to run the agent.

This is how you'd run it:

Build handoffs with the SDK's `Agent`, then stage a metric onto the first agent span (or use `setTracingContext` with `agentSpanContext` to score every agent span in the run).

```typescript title="openai-agents-app.ts" showLineNumbers
import { Agent } from "@openai/agents";
import { TaskCompletionMetric } from "deepeval/metrics";
import { nextAgentSpan } from "deepeval/tracing";
...

const weatherSpecialist = new Agent({
  name: "weatherSpecialist",
  instructions: "Answer weather questions.",
  model: "gpt-4o-mini",
  tools: [getWeather],
});

const triageAgent = new Agent({
  name: "triage",
  instructions: "Route the question to the right specialist.",
  model: "gpt-4o-mini",
  handoffs: [weatherSpecialist],
});

for await (const golden of dataset.evalsIterator()) {
  await nextAgentSpan({ metrics: [new TaskCompletionMetric()] }, () =>
    run(triageAgent, (golden as Golden).input),
  );
}
```

To score **every** agent span in the handoff tree (triage + specialist), use scope-wide context:

```typescript title="openai-agents-app.ts" showLineNumbers
import { setTracingContext } from "deepeval/tracing";
...

await setTracingContext(
  {
    agentSpanContext: {
      metricCollection: "agents_v1",
    },
  },
  () => run(triageAgent, "What's the weather in Paris?"),
);
```

</Case>

### Wrap an agent run in observe

When the agent run is part of a larger operation, wrap the outer function with <Term py="@observe" ts="observe()"/>. OpenAI Agents spans nest under your observed span when a current trace already exists.

<Switch>

<Case id="python">

```python title="openai_agents_app.py" showLineNumbers
from agents import Runner
from deepeval.tracing import observe
...

@observe(name="respond_to_user")
async def respond_to_user(prompt: str) -> str:
    result = await Runner.run(agent, prompt)
    return result.final_output.strip()
```

</Case>

<Case id="typescript">

```typescript title="openai-agents-app.ts" showLineNumbers
import { run } from "@openai/agents";
import { observe } from "deepeval/tracing";
...

const respondToUser = observe({
  name: "respondToUser",
  fn: async (prompt: string) => {
    const result = await run(agent, prompt);
    return String(result.finalOutput).trim();

});
```

</Case>

</Switch>

### Bind a Confident AI prompt

<Switch>

<Case id="python">

Pass `confident_prompt=` to attach a Confident AI [`Prompt`](/docs/prompt-management) to every LLM span produced by that agent. Prompt analytics (commit hash, version, label) flow with the trace.

```python title="openai_agents_app.py" showLineNumbers
from deepeval.openai_agents import Agent
from deepeval.prompt import Prompt

prompt = Prompt(alias="weather-system")
prompt.pull(version="latest")

agent = Agent(
    name="weather_agent",
    instructions=prompt.interpolate(),
    tools=[get_weather],
    confident_prompt=prompt,
)
```

</Case>

<Case id="typescript">

Stage a `Prompt` on the LLM context — the processor copies alias, hash, version, and label onto every LLM span opened inside the callback.

```typescript title="openai-agents-app.ts" showLineNumbers
import { Prompt } from "deepeval/prompt";
import { setTracingContext } from "deepeval/tracing";
...

const prompt = new Prompt({ alias: "weather-system" });
await prompt.pull({ version: "latest" });

await setTracingContext(
  {
    llmSpanContext: { prompt },
  },
  () => ask("What's the weather in Paris?"),
);
```

</Case>

</Switch>

## API reference

<Switch>

<Case id="python">

`deepeval.openai_agents.Agent(...)` accepts the SDK's standard `Agent` kwargs plus the following deepeval-specific ones:

| Kwarg              | Type     | Description                                                                         |
| ------------------ | -------- | ----------------------------------------------------------------------------------- |
| `agent_metrics`    | `list`   | Metrics applied to this agent's span on every run.                                   |
| `llm_metrics`      | `list`   | Metrics applied to LLM spans produced by this agent's model calls.                   |
| `confident_prompt` | `Prompt` | Confident AI prompt object; captured on every LLM span produced by this agent.       |

`function_tool(..., metrics=[...])` accepts the SDK's standard kwargs plus `metrics`, applied to that tool's span on every call.

Register with `add_trace_processor(DeepEvalTracingProcessor())`.

</Case>

<Case id="typescript">

`new DeepEvalTracingProcessor()` has no constructor options. Register it once:

```typescript
import { addTraceProcessor } from "@openai/agents";
import { DeepEvalTracingProcessor } from "deepeval/integrations/openai-agents";

addTraceProcessor(new DeepEvalTracingProcessor());
```

Build agents with `@openai/agents` (`Agent`, `tool`, `run`). Attach metrics with:

| Helper | Targets |
| ------ | ------- |
| `evalsIterator({ metrics })` / `toPass([...])` | Trace-level |
| `nextAgentSpan(...)` | First agent span in the callback |
| `nextLlmSpan(...)` | First LLM span in the callback |
| `nextToolSpan(...)` | First tool span in the callback |
| `setTracingContext({ agentSpanContext / llmSpanContext })` | Every matching span in scope |
| `updateCurrentSpan(...)` | Current span (use inside a tool body) |

</Case>

</Switch>

For runtime helpers (<Term py="update_current_trace" ts="updateCurrentTrace"/>, <Term py="update_current_span" ts="updateCurrentSpan"/>) and the test surface (<Term py="@observe" ts="observe()"/>, <Term py="assert_test" ts="toPass"/>, <Term py="trace(...)" ts="setTracingContext(...)"/>), see the [tracing reference](/docs/evaluation-llm-tracing).
