[LangChain](https://www.langchain.com/) is an open-source framework for building LLM applications with models, prompts, tools, retrievers, and agents (via <Term py="create_agent" ts="createAgent"/>).

The `deepeval` integration traces LangChain runs through a <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> that you pass into LangChain's `config`. Every agent run, model call, tool call, and retriever call becomes a span you can inspect, without rewriting your LangChain app.

`deepeval`'s LangChain integration enables you to:

- **Trace any LangChain run** — pass a <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> through LangChain's callbacks config per call.
- **Evaluate the complete ordered [agent trajectory](/docs/evaluation-trajectory-based-llm-evals)** — score the sequence across all applicable agent, LLM, tool, and retriever spans.
- **Evaluate traces or individual components** with `deepeval` metrics.
- **Run evals from scripts or CI/CD** — same callback, different surfaces.
- **Customize trace and span data** through callback kwargs and <Term py="next_*_span" ts="next*Span"/> staging.

### Instrument and evaluate

Create a <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> and pass it to the agent's `invoke` method.

<Switch>

<Case id="python">

```python title="langchain_agent.py" showLineNumbers
from langchain.agents import create_agent
from deepeval.integrations.langchain import CallbackHandler
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.metrics import TaskCompletionMetric

def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

agent = create_agent(
    model="openai:gpt-4o-mini",
    tools=[multiply],
    system_prompt="Be concise.",
)

# Goldens are the inputs you want to evaluate.
dataset = EvaluationDataset(goldens=[Golden(input="What is 8 multiplied by 6?")])

# The `TaskCompletionMetric` is passed into the `evals_iterator`.
for golden in dataset.evals_iterator(metrics=[TaskCompletionMetric()]):
    agent.invoke(
        {"messages": [{"role": "user", "content": golden.input}]},
        config={"callbacks": [CallbackHandler()]},
    )
```

</Case>

<Case id="typescript">

```typescript title="langchain-agent.ts" showLineNumbers
import { createAgent } from "langchain";
import { tool } from "@langchain/core/tools";
import { z } from "zod";

import { DeepEvalCallbackHandler } from "deepeval/integrations/langchain";
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { TaskCompletionMetric } from "deepeval/metrics";

const multiply = tool(
  ({ a, b }) => a * b,
  {
    name: "multiply",
    description: "Multiply two numbers.",
    schema: z.object({ a: z.number(), b: z.number() }),
  },
);

const agent = createAgent({
  model: "openai:gpt-4o-mini",
  tools: [multiply],
  systemPrompt: "Be concise.",
});

const handler = new DeepEvalCallbackHandler({});

const ask = (input: string) =>
  agent.invoke(
    { messages: [{ role: "user", content: input }] },
    { callbacks: [handler] },
  );

// Goldens are the inputs you want to evaluate.
const dataset = new EvaluationDataset({
  goldens: [new Golden({ input: "What is 8 multiplied by 6?" })],
});

// The `TaskCompletionMetric` is passed into the `evalsIterator`.
for await (const golden of dataset.evalsIterator({
  metrics: [new TaskCompletionMetric()],
})) {
  await ask((golden as Golden).input);
}
```

</Case>

</Switch>

Done ✅. You've run your first eval with full traceability into LangChain via `deepeval`.

## What gets traced

Each LangChain call that receives a <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> produces a **trace** — the end-to-end unit your user observes. Inside that trace are **component spans** for each callback LangChain emits:

- **Agent span** — the top-level <Term py="create_agent" ts="createAgent"/> / runnable `invoke(...)` call (the root of the tree).
- **LLM spans** — chat model and completion calls.
- **Tool spans** — tool calls and function executions.
- **Retriever spans** — retriever calls, when your app uses retrieval.

<Switch>
<Case id="python">

```text
Trace                           ← what the user observes
└── Agent: math_agent            ← one create_agent invoke(...) call
    ├── LLM: gpt-4o-mini        ← component span: model chooses a tool
    ├── Tool: multiply          ← component span: tool input + output
    └── LLM: gpt-4o-mini        ← component span: final answer
```

</Case>
<Case id="typescript">

```text
Trace                           ← what the user observes
└── Agent: mathAgent             ← one createAgent invoke(...) call
    ├── LLM: gpt-4o-mini        ← component span: model chooses a tool
    ├── Tool: multiply          ← component span: tool input + output
    └── LLM: gpt-4o-mini        ← component span: final answer
```

</Case>
</Switch>

The trace and its component spans are independently evaluable.

## Running evals

There are two surfaces for running evals against a LangChain app. Pick by where you want results to surface — your terminal during development, or your CI pipeline as a pass/fail gate.

### In CI/CD

<Switch>

<Case id="python">

Use the `deepeval` `pytest` integration. Each parametrized test invocation becomes one LangChain run; failing metrics fail the test, which fails the build.

```python title="test_langchain_agent.py" showLineNumbers
import pytest
from langchain.agents import create_agent
from deepeval.integrations.langchain import CallbackHandler
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.metrics import TaskCompletionMetric
from deepeval import assert_test

def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

agent = create_agent(model="openai:gpt-4o-mini", tools=[multiply], system_prompt="Be concise.")
dataset = EvaluationDataset(goldens=[
    Golden(input="What is 8 multiplied by 6?"),
    Golden(input="What is 7 multiplied by 9?"),
])

@pytest.mark.parametrize("golden", dataset.goldens)
def test_langchain_agent(golden: Golden):
    agent.invoke(
        {"messages": [{"role": "user", "content": golden.input}]},
        config={"callbacks": [CallbackHandler()]},
    )
    assert_test(golden=golden, metrics=[TaskCompletionMetric()])
```

Run it with:

```bash
deepeval test run test_langchain_agent.py
```

</Case>

<Case id="typescript">

Use the `toPass()` matcher. The golden is the subject; `task` produces the trace judged against it. A failing metric fails the test, which fails the build.

```typescript title="langchain-agent.test.ts" showLineNumbers
import { it, expect } from "vitest";
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { TaskCompletionMetric } from "deepeval/metrics";
import { ask } from "./langchain-agent";
import "deepeval/vitest";

const dataset = new EvaluationDataset({
  goldens: [
    new Golden({ input: "What is 8 multiplied by 6?" }),
    new Golden({ input: "What is 7 multiplied by 9?" }),
  ],
});

it.each(dataset.goldens as Golden[])(
  "completes the math task",
  async (golden) => {
    await expect(golden).toPass([new TaskCompletionMetric()], {
      task: (g) => ask(g.input),
    });
  },
);
```

Run it with:

```bash
npx deepeval test run langchain-agent.test.ts
```

</Case>

</Switch>

## Evaluate agent trajectories

Trajectory evaluation scores the complete ordered trace: the agent's decisions, model calls, tool use, and other applicable spans in the sequence they occurred. This is distinct from evaluating only the final output or attaching a metric to an individual component span.

Pass trajectory metrics to <Term py="evals_iterator" ts="evalsIterator"/> so each instrumented LangChain run is evaluated at trace scope:

<Switch>

<Case id="python">

```python title="langchain_agent.py" showLineNumbers
from deepeval.metrics import TaskCompletionMetric, StepEfficiencyMetric, PlanAdherenceMetric
from deepeval.integrations.langchain import CallbackHandler
from deepeval.dataset import EvaluationDataset, Golden
...

dataset = EvaluationDataset(goldens=[Golden(input="What is 8 multiplied by 6?")])
metrics = [TaskCompletionMetric(), StepEfficiencyMetric(), PlanAdherenceMetric()]

for golden in dataset.evals_iterator(metrics=metrics):
    agent.invoke(
        {"messages": [{"role": "user", "content": golden.input}]},
        config={"callbacks": [CallbackHandler()]},
    )
```

</Case>

<Case id="typescript">

```typescript title="langchain-agent.ts" showLineNumbers
import { TaskCompletionMetric, StepEfficiencyMetric, PlanAdherenceMetric } from "deepeval/metrics";
import { DeepEvalCallbackHandler } from "deepeval/integrations/langchain";
import { EvaluationDataset, Golden } from "deepeval/dataset";
...

const dataset = new EvaluationDataset({
  goldens: [new Golden({ input: "What is 8 multiplied by 6?" })],
});
const metrics = [
  new TaskCompletionMetric(),
  new StepEfficiencyMetric(),
  new PlanAdherenceMetric(),
];

for await (const golden of dataset.evalsIterator({ metrics })) {
  await agent.invoke(
    { messages: [{ role: "user", content: (golden as Golden).input }] },
    { callbacks: [new DeepEvalCallbackHandler({})] },
  );
}
```

</Case>

</Switch>

See the [trajectory evaluation guide](/docs/evaluation-trajectory-based-llm-evals) for metric selection and interpretation. To score one step instead of the ordered run, apply metrics to components next.

## Applying metrics to components

Passing metrics to <Term py="evals_iterator" ts="evalsIterator"/> evaluates the overall LangChain run. To evaluate a component instead, stage metrics onto the next span the callback opens.

### Agent spans

Wrap the invocation in <Term py="next_agent_span" ts="nextAgentSpan"/>. The <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> drains the staged metric onto the **root agent span** opened by `invoke(...)` — useful when you want a span-level score on the agent itself rather than the whole trace.

<Switch>

<Case id="python">

```python title="langchain_agent.py" showLineNumbers
from deepeval.integrations.langchain import CallbackHandler
from deepeval.metrics import TaskCompletionMetric
from deepeval.tracing import next_agent_span
...

for golden in dataset.evals_iterator():
    with next_agent_span(metrics=[TaskCompletionMetric()]):
        agent.invoke(
            {"messages": [{"role": "user", "content": golden.input}]},
            config={"callbacks": [CallbackHandler()]},
        )
```

</Case>

<Case id="typescript">

```typescript title="langchain-agent.ts" showLineNumbers
import { TaskCompletionMetric } from "deepeval/metrics";
import { nextAgentSpan } from "deepeval/tracing";
...

for await (const golden of dataset.evalsIterator()) {
  await nextAgentSpan({ metrics: [new TaskCompletionMetric()] }, () =>
    ask((golden as Golden).input),
  );
}
```

</Case>

</Switch>

### LLM calls

Wrap the invocation in <Term py="next_llm_span" ts="nextLlmSpan"/>. The <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> drains the staged metric onto the **first LLM span** it opens inside the block; later LLM calls in the same run get nothing.

<Switch>

<Case id="python">

```python title="langchain_agent.py" showLineNumbers
from langchain.agents import create_agent
from deepeval.integrations.langchain import CallbackHandler
from deepeval.metrics import AnswerRelevancyMetric
from deepeval.tracing import next_llm_span
...

agent = create_agent(model="openai:gpt-4o-mini", tools=[multiply], system_prompt="Be concise.")

for golden in dataset.evals_iterator():
    with next_llm_span(metrics=[AnswerRelevancyMetric()]):
        agent.invoke(
            {"messages": [{"role": "user", "content": golden.input}]},
            config={"callbacks": [CallbackHandler()]},
        )
```

</Case>

<Case id="typescript">

```typescript title="langchain-agent.ts" showLineNumbers
import { AnswerRelevancyMetric } from "deepeval/metrics";
import { nextLlmSpan } from "deepeval/tracing";
...

for await (const golden of dataset.evalsIterator()) {
  await nextLlmSpan({ metrics: [new AnswerRelevancyMetric()] }, () =>
    ask((golden as Golden).input),
  );
}
```

</Case>

</Switch>

:::caution[One-shot per run]
<Term py="next_llm_span" ts="nextLlmSpan"/> stages a metric for the **first** LLM span LangChain opens inside the block. Later LLM calls in the same `agent.invoke(...)` — e.g. the tool-choice turn followed by the final-answer turn — won't receive the staged metric. To score every LLM call, use a scope-wide context (<Term py="trace(...)" ts="setTracingContext(...)"/>) or score the run end-to-end with trace-level metrics on <Term py="evals_iterator" ts="evalsIterator"/>.
:::

</Case>

### Tool calls

For deterministic tool calls, use tool spans for traceability, inputs, outputs, and metadata. Prefer attaching metrics at the LLM or trace level rather than on tools.

<Switch>

<Case id="python">

Use `deepeval`'s patched `tool` decorator when you want to attach a metric collection (or metrics) from the tool definition:

```python title="langchain_agent.py" showLineNumbers
from deepeval.integrations.langchain import tool

@tool(metric_collection="tools_v1")
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b
```

</Case>

<Case id="typescript">

Inside a tool body your code **is** the tool span, so reach it with `updateCurrentSpan(...)`:

```typescript title="langchain-agent.ts" showLineNumbers
import { updateCurrentSpan } from "deepeval/tracing";
import { tool } from "@langchain/core/tools";
import { z } from "zod";
...

const multiply = tool(
  ({ a, b }) => {
    updateCurrentSpan({
      metadata: { operation: "multiply" },
    });
    return a * b;
  },
  {
    name: "multiply",
    description: "Multiply two numbers.",
    schema: z.object({ a: z.number(), b: z.number() }),
  },
);
```

`nextToolSpan(...)` stages the same fields from outside the tool, on the same one-shot semantic as `nextLlmSpan`.

</Case>

</Switch>

## Customizing trace and span data

LangChain is instrumented per-call through callbacks, so customization happens at the callback or span-staging boundary.

- Use <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> kwargs for trace-level defaults like `name`, `tags`, `metadata`, <Term py="thread_id" ts="threadId"/>, and <Term py="user_id" ts="userId"/>.
- Use <Term py="next_agent_span" ts="nextAgentSpan"/> / <Term py="next_llm_span" ts="nextLlmSpan"/> / <Term py="next_retriever_span" ts="nextRetrieverSpan"/> / <Term py="next_tool_span" ts="nextToolSpan"/> to stage component-level fields onto the next span the callback opens.
- Use tool bodies (or Python's patched `tool` decorator) for deterministic traceability, inputs, outputs, and metadata.

<Switch>

<Case id="python">

```python title="langchain_agent.py" showLineNumbers
callback = CallbackHandler(
    name="math-agent",
    tags=["langchain", "math"],
    metadata={"team": "support"},
    user_id="user-123",
)

agent.invoke(
    {"messages": [{"role": "user", "content": "What is 8 multiplied by 6?"}]},
    config={"callbacks": [callback]},
)
```

</Case>

<Case id="typescript">

```typescript title="langchain-agent.ts" showLineNumbers
const handler = new DeepEvalCallbackHandler({
  name: "math-agent",
  tags: ["langchain", "math"],
  metadata: { team: "support" },
  userId: "user-123",
});

await agent.invoke(
  { messages: [{ role: "user", content: "What is 8 multiplied by 6?" }] },
  { callbacks: [handler] },
```

</Case>

</Switch>

## Advanced patterns

The primitives above — <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> and <Term py="next_*_span" ts="next*Span"/> — compose around one boundary: LangChain owns the callback lifecycle, and your code chooses where to stage component config for the next span the callback opens.

### Score every matching span

Where <Term py="next_*_span" ts="next*Span"/> is one-shot, a scope-wide context applies to **every** matching span. Use this when an agent makes several model calls per run and you want all of them scored.

<Switch>

<Case id="python">

```python title="langchain_agent.py" showLineNumbers
from deepeval.tracing import LlmSpanContext, trace
from deepeval.metrics import AnswerRelevancyMetric
...

with trace(llm_span_context=LlmSpanContext(metrics=[AnswerRelevancyMetric()])):
    agent.invoke(
        {"messages": [{"role": "user", "content": prompt}]},
        config={"callbacks": [CallbackHandler()]},
    )
```

</Case>

<Case id="typescript">

```typescript title="langchain-agent.ts" showLineNumbers
import { AnswerRelevancyMetric } from "deepeval/metrics";
import { setTracingContext } from "deepeval/tracing";
...

await setTracingContext(
  {
    llmSpanContext: {
      metrics: [new AnswerRelevancyMetric()],
    },
  },
  () => ask("What is 8 multiplied by 6?"),
);
```

</Case>

</Switch>

### Evaluate components without trace-level metrics

Stage a metric on an LLM (or retriever) span, then run CI/CD or scripts without also passing metrics to the iterator / matcher. Trace-level metrics are end-to-end metrics: they are not strictly necessary when the component already carries the metric.

<Switch>

<Case id="python">

```python title="langchain_agent.py" showLineNumbers
from deepeval.metrics import AnswerRelevancyMetric
from deepeval.tracing import next_llm_span
...

def run_agent(prompt: str):
    with next_llm_span(metrics=[AnswerRelevancyMetric()]):
        return agent.invoke(
            {"messages": [{"role": "user", "content": prompt}]},
            config={"callbacks": [CallbackHandler()]},
        )
```

### Wrap a LangChain run in `@observe`

When the LangChain call is part of a larger operation, decorate the outer function with `@observe`. LangChain spans nest under your observed span when the callback runs inside it.

```python title="langchain_agent.py" showLineNumbers
from deepeval.tracing import observe
...

@observe(name="respond_to_user")
def respond_to_user(prompt: str) -> str:
    result = agent.invoke(
        {"messages": [{"role": "user", "content": prompt}]},
        config={"callbacks": [CallbackHandler()]},
    )
    return result["messages"][-1].content
```

</Only>

## API reference

<Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> accepts the following trace-level kwargs. Each one is a default for runs that use that callback.

| Kwarg | Type | Description |
| --- | --- | --- |
| `name` | <Term py="str" ts="string"/> | Default trace name. |
| `tags` | <Term py="list[str]" ts="string[]"/> | Tags applied to traces produced by this callback. |
| `metadata` | <Term py="dict" ts="object"/> | Trace metadata applied when the callback starts a trace. |
| <Term py="thread_id" ts="threadId"/> | <Term py="str" ts="string"/> | Groups related runs into a single trace thread. |
| <Term py="user_id" ts="userId"/> | <Term py="str" ts="string"/> | Actor identifier for the trace. |
| `metrics` | <Term py="list" ts="array"/> | Trace-level metrics for the run. Prefer <Term py="evals_iterator" ts="evalsIterator"/> in eval scripts. |
| <Term py="metric_collection" ts="metricCollection"/> | <Term py="str" ts="string"/> | Trace-level metric collection, for online evals on live traffic. |
| <Term py="test_case_id" ts="testCaseId"/> | <Term py="str" ts="string"/> | Optional test case identifier. |
| <Term py="turn_id" ts="turnId"/> | <Term py="str" ts="string"/> | Optional turn identifier for conversational traces. |

For native tracing helpers (<Term py="@observe" ts="observe()"/>, <Term py="update_current_trace" ts="updateCurrentTrace"/>, <Term py="update_current_span" ts="updateCurrentSpan"/>) see the [tracing reference](/docs/evaluation-llm-tracing).
