[LangGraph](https://www.langchain.com/langgraph) is a low-level orchestration framework for building stateful, graph-based agent workflows. You compose agents from `StateGraph` nodes and edges, with full control over routing, state, and tool execution.

The `deepeval` integration traces LangGraph runs through LangChain's <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/>, which you pass into your graph's runtime config. Every graph run, node, model call, tool call, and nested step becomes a span you can inspect, without rewriting your LangGraph app.

`deepeval`'s LangGraph integration enables you to:

- **Trace any LangGraph run** — pass a <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> through the graph's callbacks config per call.
- **Evaluate the complete ordered [agent trajectory](/docs/evaluation-trajectory-based-llm-evals)** — score the sequence across all applicable graph, agent, LLM, and tool spans.
- **Evaluate traces or model / agent components** with `deepeval` metrics.
- **Run evals from scripts or CI/CD** — same callback, different surfaces.
- **Customize trace and span data** through callback kwargs and <Term py="next_*_span" ts="next*Span"/> staging.

### Instrument and evaluate

Wire your `StateGraph` (LangGraph's core abstraction), then pass the callback handler to the invocation you want to evaluate.

<Switch>

<Case id="python">

```python title="langgraph_agent.py" showLineNumbers
from langchain.chat_models import init_chat_model
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.prebuilt import ToolNode, tools_condition
from deepeval.integrations.langchain import CallbackHandler
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.metrics import TaskCompletionMetric

def get_weather(city: str) -> str:
    """Return the weather in a city."""
    return f"It's always sunny in {city}!"

llm = init_chat_model("openai:gpt-4o-mini").bind_tools([get_weather])

def chatbot(state: MessagesState):
    return {"messages": [llm.invoke(state["messages"])]}

graph = (
    StateGraph(MessagesState)
    .add_node(chatbot)
    .add_node("tools", ToolNode([get_weather]))
    .add_edge(START, "chatbot")
    .add_conditional_edges("chatbot", tools_condition)
    .add_edge("tools", "chatbot")
    .compile()
)

# Goldens are the inputs you want to evaluate.
dataset = EvaluationDataset(goldens=[Golden(input="What is the weather in Paris?")])

# The `TaskCompletionMetric` is passed into the `evals_iterator`.
for golden in dataset.evals_iterator(metrics=[TaskCompletionMetric()]):
    graph.invoke(
        {"messages": [{"role": "user", "content": golden.input}]},
        config={"callbacks": [CallbackHandler()]},
    )
```

</Case>

<Case id="typescript">

```typescript title="langgraph-agent.ts" showLineNumbers
import { StateGraph, MessagesAnnotation, START } from "@langchain/langgraph";
import { ToolNode, toolsCondition } from "@langchain/langgraph/prebuilt";
import { tool } from "@langchain/core/tools";
import { ChatOpenAI } from "@langchain/openai";
import { z } from "zod";

import { DeepEvalCallbackHandler } from "deepeval/integrations/langchain";
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { TaskCompletionMetric } from "deepeval/metrics";

const getWeather = tool(({ city }) => `It's always sunny in ${city}!`, {
  name: "get_weather",
  description: "Return the weather in a city.",
  schema: z.object({ city: z.string() }),
});

const llm = new ChatOpenAI({ model: "gpt-4o-mini" }).bindTools([getWeather]);

const chatbot = async (state: typeof MessagesAnnotation.State) => ({
  messages: [await llm.invoke(state.messages)],
});

const graph = new StateGraph(MessagesAnnotation)
  .addNode("chatbot", chatbot)
  .addNode("tools", new ToolNode([getWeather]))
  .addEdge(START, "chatbot")
  .addConditionalEdges("chatbot", toolsCondition)
  .addEdge("tools", "chatbot")
  .compile();

const handler = new DeepEvalCallbackHandler({});

export const ask = (input: string) =>
  graph.invoke(
    { messages: [{ role: "user", content: input }] },
    { callbacks: [handler] },
  );

// Goldens are the inputs you want to evaluate.
const dataset = new EvaluationDataset({
  goldens: [new Golden({ input: "What is the weather in Paris?" })],
});

// The `TaskCompletionMetric` is passed into the `evalsIterator`.
for await (const golden of dataset.evalsIterator({
  metrics: [new TaskCompletionMetric()],
})) {
  await ask((golden as Golden).input);
}
```

</Case>

</Switch>

Done ✅. You've run your first eval with full traceability into LangGraph via `deepeval`.

## What gets traced

Each LangGraph run that receives a <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> produces a **trace** — the end-to-end unit your user observes. Inside that trace are **component spans** for each callback LangGraph emits through LangChain:

- **Agent span** — the compiled `StateGraph` `invoke(...)` call (the root of the tree). Nested graph nodes stay custom spans.
- **LLM spans** — chat model and completion calls inside a node.
- **Tool spans** — tool calls executed by `ToolNode` (or your own).
- **Retriever spans** — retriever calls, when your graph uses retrieval.

<Switch>
<Case id="python">

```text
Trace                           ← what the user observes
└── Agent: weather_graph         ← one graph invoke(...) call
    ├── Node: chatbot           ← model picks a tool
    │   └── LLM: gpt-4o-mini
    ├── Node: tools             ← ToolNode runs the tool
    │   └── Tool: get_weather
    └── Node: chatbot           ← model writes the final answer
        └── LLM: gpt-4o-mini
```

</Case>
<Case id="typescript">

```text
Trace                           ← what the user observes
└── Agent: weatherGraph          ← one graph invoke(...) call
    ├── Node: chatbot           ← model picks a tool
    │   └── LLM: gpt-4o-mini
    ├── Node: tools             ← ToolNode runs the tool
    │   └── Tool: get_weather
    └── Node: chatbot           ← model writes the final answer
        └── LLM: gpt-4o-mini
```

The trace and its component spans are independently evaluable.

## Running evals

There are two surfaces for running evals against a LangGraph app. Pick by where you want results to surface — your terminal during development, or your CI pipeline as a pass/fail gate.

### In CI/CD

<Switch>

<Case id="python">

Use the `deepeval` pytest integration. Each parametrized test invocation becomes one LangGraph run; failing metrics fail the test, which fails the build.

```python title="test_langgraph_agent.py" showLineNumbers
import pytest
from langchain.chat_models import init_chat_model
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.prebuilt import ToolNode, tools_condition
from deepeval import assert_test
from deepeval.integrations.langchain import CallbackHandler
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.metrics import TaskCompletionMetric

def get_weather(city: str) -> str:
    """Return the weather in a city."""
    return f"It's always sunny in {city}!"

llm = init_chat_model("openai:gpt-4o-mini").bind_tools([get_weather])

def chatbot(state: MessagesState):
    return {"messages": [llm.invoke(state["messages"])]}

graph = (
    StateGraph(MessagesState)
    .add_node(chatbot)
    .add_node("tools", ToolNode([get_weather]))
    .add_edge(START, "chatbot")
    .add_conditional_edges("chatbot", tools_condition)
    .add_edge("tools", "chatbot")
    .compile()
)

dataset = EvaluationDataset(goldens=[
    Golden(input="What is the weather in Paris?"),
    Golden(input="What is the weather in London?"),
])

@pytest.mark.parametrize("golden", dataset.goldens)
def test_langgraph_agent(golden: Golden):
    graph.invoke(
        {"messages": [{"role": "user", "content": golden.input}]},
        config={"callbacks": [CallbackHandler()]},
    )
    assert_test(golden=golden, metrics=[TaskCompletionMetric()])
```

Run it with:

```bash
deepeval test run test_langgraph_agent.py
```

</Case>

<Case id="typescript">

Use the `toPass()` matcher. The golden is the subject; `task` produces the trace judged against it. A failing metric fails the test, which fails the build.

```typescript title="langgraph-agent.test.ts" showLineNumbers
import { it, expect } from "vitest";
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { TaskCompletionMetric } from "deepeval/metrics";
import { ask } from "./langgraph-agent";

  goldens: [
    new Golden({ input: "What is the weather in Paris?" }),
    new Golden({ input: "What is the weather in London?" }),

it.each(dataset.goldens as Golden[])(
  "answers the weather question",
  async (golden) => {
    await expect(golden).toPass([new TaskCompletionMetric()], {
      task: (g) => ask(g.input),

  },
);
```

Run it with:

```bash
npx deepeval test run langgraph-agent.test.ts
```

## Evaluate agent trajectories

Trajectory evaluation scores the complete ordered trace: the graph's routing decisions, model calls, tool use, and other applicable spans in the sequence they occurred. This is distinct from evaluating only the final output or attaching a metric to an individual component span. Custom graph and node spans remain part of that ordered trajectory, so graph-specific orchestration is preserved in the evaluation scope.

Pass trajectory metrics to <Term py="evals_iterator" ts="evalsIterator"/> so each instrumented LangGraph run is evaluated at trace scope:

<Switch>

<Case id="python">

```python title="langgraph_agent.py" showLineNumbers
from deepeval.metrics import TaskCompletionMetric, StepEfficiencyMetric, PlanAdherenceMetric
from deepeval.integrations.langchain import CallbackHandler
from deepeval.dataset import EvaluationDataset, Golden
...

dataset = EvaluationDataset(goldens=[Golden(input="What is the weather in Paris?")])
metrics = [TaskCompletionMetric(), StepEfficiencyMetric(), PlanAdherenceMetric()]

for golden in dataset.evals_iterator(metrics=metrics):
    graph.invoke(
        {"messages": [{"role": "user", "content": golden.input}]},
        config={"callbacks": [CallbackHandler()]},
    )
```

</Case>

<Case id="typescript">

```typescript title="langgraph-agent.ts" showLineNumbers
import { TaskCompletionMetric, StepEfficiencyMetric, PlanAdherenceMetric } from "deepeval/metrics";
import { DeepEvalCallbackHandler } from "deepeval/integrations/langchain";
import { EvaluationDataset, Golden } from "deepeval/dataset";
...

const dataset = new EvaluationDataset({
  goldens: [new Golden({ input: "What is the weather in Paris?" })],
});
const metrics = [
  new TaskCompletionMetric(),
  new StepEfficiencyMetric(),
  new PlanAdherenceMetric(),
];

for await (const golden of dataset.evalsIterator({ metrics })) {
  await graph.invoke(
    { messages: [{ role: "user", content: (golden as Golden).input }] },
    { callbacks: [new DeepEvalCallbackHandler({})] },
  );
}
```

</Case>

</Switch>

See the [trajectory evaluation guide](/docs/evaluation-trajectory-based-llm-evals) for metric selection and interpretation. To score one step instead of the ordered run, apply metrics to components next.

## Applying metrics to components

Passing metrics to <Term py="evals_iterator" ts="evalsIterator"/> evaluates the overall LangGraph run. To evaluate a component instead, stage metrics onto the next span the callback opens.

### Agent spans

Wrap the graph invocation in <Term py="next_agent_span" ts="nextAgentSpan"/>. The callback drains the staged metric onto the **root agent span** opened by `invoke(...)` — useful when you want a span-level score on the graph run itself rather than the whole trace.

<Switch>

<Case id="python">

```python title="langgraph_agent.py" showLineNumbers
from deepeval.integrations.langchain import CallbackHandler
from deepeval.metrics import TaskCompletionMetric
from deepeval.tracing import next_agent_span
...

for golden in dataset.evals_iterator():
    with next_agent_span(metrics=[TaskCompletionMetric()]):
        graph.invoke(
            {"messages": [{"role": "user", "content": golden.input}]},
            config={"callbacks": [CallbackHandler()]},
        )
```

</Case>

<Case id="typescript">

```typescript title="langgraph-agent.ts" showLineNumbers
import { TaskCompletionMetric } from "deepeval/metrics";
import { nextAgentSpan } from "deepeval/tracing";
...

for await (const golden of dataset.evalsIterator()) {
  await nextAgentSpan({ metrics: [new TaskCompletionMetric()] }, () =>
    ask((golden as Golden).input),
  );
}
```

</Case>

</Switch>

The same one-shot semantic as the LLM helper applies: only the root agent span picks up the staged metric.

### LLM calls

Wrap the graph invocation in <Term py="next_llm_span" ts="nextLlmSpan"/>. The callback drains the staged metric onto the **first LLM span** the graph emits; later LLM calls on subsequent loop turns get nothing.

<Switch>

<Case id="python">

```python title="langgraph_agent.py" showLineNumbers
from deepeval.integrations.langchain import CallbackHandler
from deepeval.metrics import AnswerRelevancyMetric
from deepeval.tracing import next_llm_span
...

for golden in dataset.evals_iterator():
    with next_llm_span(metrics=[AnswerRelevancyMetric()]):
        graph.invoke(
            {"messages": [{"role": "user", "content": golden.input}]},
            config={"callbacks": [CallbackHandler()]},
        )
```

</Case>

<Case id="typescript">

```typescript title="langgraph-agent.ts" showLineNumbers
import { AnswerRelevancyMetric } from "deepeval/metrics";
import { nextLlmSpan } from "deepeval/tracing";
...

for await (const golden of dataset.evalsIterator()) {
  await nextLlmSpan({ metrics: [new AnswerRelevancyMetric()] }, () =>
    ask((golden as Golden).input),
  );
}
```

</Case>

</Switch>

:::caution[One-shot per run]
<Term py="next_llm_span" ts="nextLlmSpan"/> stages a metric for the **first** LLM span the graph emits inside the block. Later loop iterations through the `chatbot` node won't pick it up. To score every LLM call, use a scope-wide context (<Term py="trace(...)" ts="setTracingContext(...)"/>) or score the run end-to-end with trace-level metrics on <Term py="evals_iterator" ts="evalsIterator"/>.
:::

For deterministic tool calls, use tool spans for traceability, inputs, outputs, and metadata. Avoid attaching metrics directly to tool spans.

## Customizing trace and span data

LangGraph is instrumented per-call through LangChain callbacks, so customization happens at the callback or span-staging boundary.

- Use <Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> kwargs for trace-level defaults like `name`, `tags`, `metadata`, <Term py="thread_id" ts="threadId"/>, and <Term py="user_id" ts="userId"/>.
- Use <Term py="next_agent_span" ts="nextAgentSpan"/> / <Term py="next_llm_span" ts="nextLlmSpan"/> / <Term py="next_retriever_span" ts="nextRetrieverSpan"/> / <Term py="next_tool_span" ts="nextToolSpan"/> to stage component-level fields onto the next span the callback opens.
- Use tool spans for deterministic traceability, inputs, outputs, and metadata.

<Switch>

<Case id="python">

```python title="langgraph_agent.py" showLineNumbers
callback = CallbackHandler(
    name="weather-graph",
    tags=["langgraph", "weather"],
    metadata={"team": "support"},
    user_id="user-123",
)

graph.invoke(
    {"messages": [{"role": "user", "content": "What is the weather in Paris?"}]},
    config={"callbacks": [callback]},
)
```

</Case>

<Case id="typescript">

```typescript title="langgraph-agent.ts" showLineNumbers

  name: "weather-graph",
  tags: ["langgraph", "weather"],
```

## Advanced patterns

The primitives above — the callback handler and <Term py="next_*_span" ts="next*Span"/> — compose around one boundary: LangGraph owns the graph execution lifecycle, and your code chooses where to stage component config for the next span the callback opens.

### Evaluate a node instead of the whole graph

Staging a metric applies it to the next matching span the callback opens during the graph run. Use this when you want to evaluate a subagent node or model step instead of the full graph. Pick the helper that matches the span you want to score.

<Switch>

<Case id="python">

```python title="langgraph_agent.py" showLineNumbers
from deepeval.integrations.langchain import CallbackHandler
from deepeval.metrics import TaskCompletionMetric
from deepeval.tracing import next_agent_span
...

def run_graph(prompt: str):
    with next_agent_span(metrics=[TaskCompletionMetric()]):
        return graph.invoke(
            {"messages": [{"role": "user", "content": prompt}]},
            config={"callbacks": [CallbackHandler()]},
        )
```

</Case>

<Case id="typescript">

```typescript title="langgraph-agent.ts" showLineNumbers
import { TaskCompletionMetric } from "deepeval/metrics";
import { nextAgentSpan } from "deepeval/tracing";
...

export const runGraph = (prompt: string) =>
  nextAgentSpan({ metrics: [new TaskCompletionMetric()] }, () => ask(prompt));
```

</Case>

</Switch>

## Tracing a LangGraph server deployment

When you deploy with the [LangGraph server](https://langchain-ai.github.io/langgraph/cloud/), the **server** invokes your graph. So instead you can attach the handler to the compiled graph and export that. The callback then applies to every run the server executes.

<Switch>

<Case id="python">

```python title="langgraph_agent.py" showLineNumbers
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.prebuilt import ToolNode, tools_condition
from deepeval.integrations.langchain import CallbackHandler
...

graph = (
    StateGraph(MessagesState)
    .add_node(chatbot)
    .add_node("tools", ToolNode([get_weather]))
    .add_edge(START, "chatbot")
    .add_conditional_edges("chatbot", tools_condition)
    .add_edge("tools", "chatbot")
    .compile()
    .with_config(callbacks=[CallbackHandler()])  # baked into every server run
)
```

Point `langgraph.json` at the exported `graph`:

```json title="langgraph.json"
{
  "dependencies": ["."],
  "graphs": { "agent": "./langgraph_agent.py:graph" },
  "env": ".env"
}
```

Then start the server — every request it runs against the graph is traced:


:::caution[Baked-in trace attributes are per-handler, not per-request]
Attributes set on a baked-in handler — <Term py="thread_id" ts="threadId"/>, <Term py="user_id" ts="userId"/>, etc. — are the same for every request the server serves, because the handler is constructed once. For per-request values, attach the callback per call instead of baking it into the graph.
:::

## API reference

<Term py="CallbackHandler" ts="DeepEvalCallbackHandler"/> accepts the following trace-level kwargs. Each one is a default for runs that use that callback.

| Kwarg | Type | Description |
| --- | --- | --- |
| `name` | <Term py="str" ts="string"/> | Default trace name. |
| `tags` | <Term py="list[str]" ts="string[]"/> | Tags applied to traces produced by this callback. |
| `metadata` | <Term py="dict" ts="object"/> | Trace metadata applied when the callback starts a trace. |
| <Term py="thread_id" ts="threadId"/> | <Term py="str" ts="string"/> | Groups related runs into a single trace thread. |
| <Term py="user_id" ts="userId"/> | <Term py="str" ts="string"/> | Actor identifier for the trace. |
| `metrics` | <Term py="list" ts="array"/> | Trace-level metrics for the run. Prefer <Term py="evals_iterator" ts="evalsIterator"/> in eval scripts. |
| <Term py="metric_collection" ts="metricCollection"/> | <Term py="str" ts="string"/> | Trace-level metric collection, for online evals on live traffic. |
| <Term py="test_case_id" ts="testCaseId"/> | <Term py="str" ts="string"/> | Optional test case identifier. |
| <Term py="turn_id" ts="turnId"/> | <Term py="str" ts="string"/> | Optional turn identifier for conversational traces. |

For native tracing helpers (<Term py="@observe" ts="observe()"/>, <Term py="update_current_trace" ts="updateCurrentTrace"/>, <Term py="update_current_span" ts="updateCurrentSpan"/>) see the [tracing reference](/docs/evaluation-llm-tracing).
