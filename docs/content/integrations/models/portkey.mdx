`deepeval`'s integration with Portkey AI allows you to use the portkey gateway to connect to any model to power all of `deepeval`'s metrics.

### Command Line

To configure your Portkey model through the CLI, run the following command:

```bash
deepeval set-portkey \
    --model "your-model" \ # Ex: gpt-4.1
    --provider "your-provider" \ # Ex: openai
    --base-url "your-base-url" \
    --temperature=0
```

:::info
The CLI command above sets Portkey as the default provider for all metrics, unless overridden in code. To use a different default model provider, you must first unset Portkey:

```bash
deepeval unset-portkey
```

:::

:::tip[Persisting settings]
You can persist CLI settings with the optional `--save` flag.
See [Flags and Configs -> Persisting CLI settings](/docs/evaluation-flags-and-configs#persisting-cli-settings-with---save).
:::

### In Code

Alternatively, you can define `PortkeyModel` directly in code:

<Switch>

<Case id="python">

<Tabs items={["Python", "ENV"]}>
<Tab value="Python">

```python
from deepeval.metrics import AnswerRelevancyMetric
from deepeval.models import PortkeyModel

model = PortkeyModel(
    model="gpt-4.1",
    provider="openai",
    api_key="your-api-key",
    base_url="your-base-url"
)

answer_relevancy = AnswerRelevancyMetric(model=model)
```

</Tab>
<Tab value="ENV">

To use any Portkey model directly in `deepeval`, set the `USE_PORTKEY_MODEL=1` in your `env` and simply pass the name of your desired model in your metric initialization:

```python
from deepeval.metrics import AnswerRelevancyMetric

answer_relevancy = AnswerRelevancyMetric(
    model="gpt-4.1",
)
```

You should also set the other necessary vars like `PORTKEY_API_KEY` to be able to use the Portkey models as shown above.

</Tab>
</Tabs>

There are **ZERO** mandatory and **SIX** optional parameters when creating a `PortkeyModel`:

- [Optional] `model`: A string specifying the name of the Portkey model to use. Defaults to `PORTKEY_MODEL_NAME` if not passed; raises an error at runtime if unset.
- [Optional] `api_key`: A string specifying your Portkey API key for authentication. Defaults to `PORTKEY_API_KEY` if not passed; raises an error at runtime if unset.
- [Optional] `provider`: A string specifying the Portkey provider of your model. Defaults to `PORTKEY_PROVIDER_NAME` if not passed; raises an error at runtime if unset.
- [Optional] `base_url`: A string specifying the base URL for the model API. Defaults to `PORTKEY_BASE_URL` if not passed; raises an error at runtime if unset.
- [Optional] `temperature`: A float specifying the model temperature. Defaults to `TEMPERATURE` if not passed; falls back to `0.0` if unset.
- [Optional] `generation_kwargs`: A dictionary of additional generation parameters forwarded to Portkey's `chat.completions.create(...)` call.

Any additional `**kwargs` you would like to use for your `Portkey` client can be passed directly to `PortkeyModel(...)`. These are forwarded to the underlying OpenAI client constructor. We recommend double-checking the parameters supported by your chosen model and provider in the [official Portkey docs](https://portkey.ai/docs).

:::tip
Pass generation parameters such as `max_tokens` via `generation_kwargs` (they are forwarded to `chat.completions.create(...)`).
:::

</Case>

<Case id="typescript">

<Tab value="TypeScript">

```typescript
import { AnswerRelevancyMetric } from "deepeval/metrics";
import { PortkeyModel } from "deepeval/models";

const model = new PortkeyModel({
  model: "gpt-4.1",
  provider: "openai",
  apiKey: "your-api-key",
  baseURL: "your-base-url",
});

const answerRelevancy = new AnswerRelevancyMetric({ model });
```

</Tab>
<Tab value="ENV">

To use any Portkey model directly in `deepeval`, set `PORTKEY_MODEL_NAME`, `PORTKEY_PROVIDER_NAME`, and `PORTKEY_API_KEY` in your `env` and create a `PortkeyModel` with no arguments:

```typescript
import { AnswerRelevancyMetric } from "deepeval/metrics";
import { PortkeyModel } from "deepeval/models";

const answerRelevancy = new AnswerRelevancyMetric({
  model: new PortkeyModel(),
});
```

</Tab>
</Tabs>

There are **ZERO** mandatory and **EIGHT** optional parameters when creating a `PortkeyModel`:

- [Optional] `model`: A string specifying the name of the Portkey model to use. Defaults to `PORTKEY_MODEL_NAME` if not passed; raises an error at runtime if unset.
- [Optional] `apiKey`: A string specifying your Portkey API key for authentication. Sent as the `x-portkey-api-key` header. Defaults to `PORTKEY_API_KEY` if not passed; raises an error at runtime if unset.
- [Optional] `provider`: A string specifying the Portkey provider of your model. Sent as the `x-portkey-provider` header. Defaults to `PORTKEY_PROVIDER_NAME` if not passed.
- [Optional] `baseURL`: A string specifying the base URL for the model API. Defaults to `PORTKEY_BASE_URL` if not passed; falls back to `https://api.portkey.ai/v1` if unset.
- [Optional] `temperature`: A number specifying the model temperature. Defaults to `0`. Pass `null` to omit it from the request entirely, which is required by reasoning models that reject it.
- [Optional] `defaultHeaders`: An object of extra HTTP headers sent with every request.
- [Optional] `costPerInputToken`: A number specifying the cost for each input token for the provided model. Defaults to the price in `deepeval`'s model cost registry, else `null`.
- [Optional] `costPerOutputToken`: A number specifying the cost for each output token for the provided model. Defaults to the price in `deepeval`'s model cost registry, else `null`.

Any other key you pass is forwarded as-is to Portkey's `chat.completions.create(...)` call, so generation parameters `deepeval` does not name go inline alongside the rest:

```typescript
const model = new PortkeyModel({
  model: "gpt-4.1",
  top_p: 0.9,
  max_tokens: 512,
});
```

We recommend double-checking the parameters supported by your chosen model and provider in the [official Portkey docs](https://portkey.ai/docs).

</Case>
